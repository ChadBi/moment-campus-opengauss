# 此刻校园 - 完整项目开发规划 Spec

## Why

此刻校园项目已完成全部产品与技术文档（阶段一），需要进入实际开发阶段。本规划将指导从项目初始化到最终交付的完整开发流程，确保所有 P0 功能实现，核心用户闭环可走通，最终交付可演示的完整项目。

## What Changes

- **项目初始化**：创建前端（React + TypeScript + Vite + Tailwind CSS）和后端（Python + FastAPI + SQLAlchemy）项目结构
- **数据库实现**：创建 21 个核心实体的数据库表结构，实现数据迁移
- **后端 API 开发**：实现认证、信息、评论、互动、搜索、地图、管理等全部 API 接口
- **前端页面开发**：实现登录注册、首页、地图、搜索、详情、发布、个人中心、管理后台等所有页面
- **前后端联调**：替换 Mock 数据为真实 API，完成所有业务流程闭环
- **测试与修复**：执行功能测试、API 测试、响应式测试，修复发现的问题
- **部署与交付**：配置生产环境，部署前后端服务，准备演示环境

## Impact

- **受影响的能力**：用户认证、信息浏览、地图发现、搜索、信息发布、互动功能、社区治理、管理后台
- **受影响的代码**：
  - 前端：`frontend/` 目录（新建）
  - 后端：`backend/` 目录（新建）
  - 数据库：SQLite 开发数据库、PostgreSQL 生产数据库
  - 配置：环境变量、Docker 配置、CI/CD 配置

#### Scenario: 后端项目初始化成功
- **WHEN** 执行后端项目初始化命令
- **THEN** 创建 FastAPI + SQLAlchemy 项目结构
- **AND** 配置数据库连接、环境变量、日志
- **AND** 项目可以正常启动（`uvicorn main:app --reload`）

### Requirement: 数据库设计与迁移

系统必须实现 21 个核心实体的数据库表结构，支持数据迁移和演示数据填充。

#### Scenario: 数据库表创建成功

#### Scenario: 演示数据填充成功

### Requirement: 用户认证系统

系统必须提供完整的用户注册、登录、登出、Token 刷新功能，使用 JWT 进行身份认证。

#### Scenario: 用户注册成功
- **WHEN** 用户提交注册表单（用户名、邮箱、密码、昵称）
- **THEN** 创建用户账户，密码使用 bcrypt 加密存储
- **AND** 返回 access_token 和 refresh_token
- **AND** 用户名和邮箱唯一性校验通过

#### Scenario: 用户登录成功
- **WHEN** 用户提交登录表单（用户名/邮箱、密码）
- **THEN** 验证密码正确
- **AND** 返回 access_token（30 分钟有效期）和 refresh_token（7 天有效期）
- **AND** 记录登录时间和 IP

#### Scenario: Token 刷新成功
- **WHEN** access_token 过期，前端使用 refresh_token 请求刷新
- **THEN** 验证 refresh_token 有效
- **AND** 返回新的 access_token 和 refresh_token
- **AND** 旧 refresh_token 失效

### Requirement: 信息浏览与发现

系统必须提供首页信息流、分类浏览、地图发现、信息详情等功能，支持游客浏览。

#### Scenario: 首页信息流加载成功
- **WHEN** 用户访问首页
- **THEN** 显示推荐和最新的校园信息列表
- **AND** 支持分页加载（每页 20 条）
- **AND** 支持综合排序（有效性×0.3 + 时间×0.25 + 距离×0.2 + 互动×0.15 + 质量×0.1）
- **AND** 显示信息卡片（标题、分类、地点、时间、有效性状态、点赞数）

#### Scenario: 地图发现功能正常
- **WHEN** 用户访问地图页
- **THEN** 显示校园地图（使用 MapLibre GL JS 或 Leaflet）
- **AND** 在地图上标记有信息的地点（最多 100 个）
- **AND** 点击标记显示地点信息摘要
- **AND** 支持缩放和拖动

#### Scenario: 信息详情查看成功
- **WHEN** 用户点击信息卡片或地图标记
- **THEN** 显示信息完整内容（标题、分类、地点、描述、图片、标签、发布时间、有效期）
- **AND** 显示发布者信息（昵称、头像）
- **AND** 显示有效性状态和确认人数
- **AND** 显示点赞、收藏、评论数
- **AND** 显示评论区（最新 10 条，可展开查看全部）

### Requirement: 搜索功能

系统必须提供关键词搜索功能，支持多维度搜索和筛选。

#### Scenario: 关键词搜索成功
- **WHEN** 用户输入关键词并搜索
- **THEN** 搜索范围包括标题、正文、地点名称、分类名称、标签、发布者昵称
- **AND** 支持模糊匹配
- **AND** 支持筛选条件（分类、距离、发布时间、有效性状态、是否有图片）
- **AND** 支持排序方式（综合、距离最近、发布时间最新、热度最高）
- **AND** 分页加载搜索结果（每页 20 条）

### Requirement: 信息发布功能

系统必须提供完整的信息发布流程，支持分类选择、地点选择、图片上传、标签添加、有效期设置。

#### Scenario: 信息发布成功
- **WHEN** 用户填写发布信息表单并提交
- **THEN** 验证必填项（标题、描述、分类、地点）
- **AND** 验证标题长度（5-100 字符）、描述长度（10-5000 字符）
- **AND** 支持上传图片（最多 9 张，每张不超过 5MB）
- **AND** 支持添加标签（最多 5 个）
- **AND** 支持设置有效期（永久、短期、自定义日期）
- **AND** 支持匿名发布选项
- **AND** 发布前检查敏感信息（手机号、身份证号等）
- **AND** 发布后状态为"待审核"或"已发布"
- **AND** 跳转至信息详情页

### Requirement: 互动功能

系统必须提供点赞、收藏、评论、有效性确认、举报等互动功能。

#### Scenario: 点赞功能正常
- **WHEN** 用户点击点赞按钮
- **THEN** 创建点赞记录（每个用户对每条信息只能点赞一次）
- **AND** 更新信息点赞数
- **AND** 可以取消点赞

#### Scenario: 收藏功能正常
- **WHEN** 用户点击收藏按钮
- **THEN** 创建收藏记录（每个用户对每条信息只能收藏一次）
- **AND** 可以取消收藏
- **AND** 收藏列表按时间倒序排列

#### Scenario: 评论功能正常
- **WHEN** 用户发表评论
- **THEN** 创建评论记录（内容长度 1-1000 字符）
- **AND** 支持回复其他评论（最多 2 级）
- **AND** 评论按时间倒序排列
- **AND** 可以删除自己的评论
- **AND** 更新信息评论数

#### Scenario: 有效性确认功能正常
- **WHEN** 用户确认信息有效性
- **THEN** 创建有效性确认记录（仍然有效、已经失效、暂时无法确认）
- **AND** 每个用户可以多次确认，保留历史记录
- **AND** 根据确认结果更新信息的有效性状态
- **AND** 显示确认统计（有效人数、失效人数）

#### Scenario: 举报功能正常
- **WHEN** 用户举报违规内容
- **THEN** 创建举报记录（举报类型、举报说明）
- **AND** 每个用户对每条内容只能举报一次
- **AND** 举报后进入管理员审核队列
