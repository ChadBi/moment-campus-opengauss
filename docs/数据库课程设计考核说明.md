# 数据库课程设计考核说明

## 一、课程设计目的

- 掌握openGauss数据库设计的基本方法
- 了解C/S与B/S结构应用系统的特点与应用场合
- 了解C/S与B/S结构应用系统的不同开发设计环境与开发设计方法
- 综合运用《数据库系统原理》实验掌握的数据库知识与技术，开发设计小型数据库应用系统

---

## 二、课程设计内容要求

### 1. 开发语言

- Java集成开发工具
- VC++集成开发工具
- C语言集成开发环境
- SQL集成开发环境
- 其他支持的开发语言

### 2. 操作系统及数据库DBMS

- 支持系统：Win2K / Win XP / Win Vista / Win10
- 数据库：openGauss 数据库

> openGauss是关系型数据库，采用客户端/服务器、单进程多线程架构，支持单机和一主多备部署方式，备机可读，支持双机高可用和读扩展。

### 3. 开发要求

- 结合具体应用场景开展用户需求调查分析，绘制组织机构图、数据流图、判定表或判定树，编制数据字典。
- 设计数据库概念模型（ER图），规划应用系统的功能模块（必做）。
- 设计数据库逻辑模型（数据库模式），并针对系统各类用户设计对应视图。
- 设计数据库物理模型。
- 采用前台C语言/C++/Java等语言搭配后台SQL，基于对应开发平台与工具完成应用系统的开发实现。

> 说明：可参考华为实验指导书中08 openGauss场景化综合应用实验、09 openGauss场景化实验作业设计、11 openGauss数据库应用系统开发(学生选课管理系统)等内容。

## 三、课程设计报告要求

### 1. 书面报告要求

报告文本不少于16页，内容包含以下模块：

1. 课程设计封面（参见附录1）
2. 目录（可通过Word标题及域功能自动生成）
3. 系统概述（参考实验示例的书写规范）
4. 数据库设计各阶段书面文档，说明各阶段设计理由（参考实验示例的过程书写）
5. 开发环境与开发工具介绍
6. 系统需求分析
7. 功能需求分析，绘制对应系统的E-R图（覆盖需求分析、概念设计）
8. 系统设计（概念设计、模块设计、逻辑结构设计、物理结构设计），绘制所有涉及的表格、流程图等，并配套详细介绍文字
9. 系统实现（包含程序核心代码、界面展示等）：所有系统界面按逻辑顺序排布，每个界面配图后附详细介绍与10行左右的核心代码，剩余完整代码放在报告末尾的附录代码中
10. 系统运行情况说明与维护计划
11. 小结：总结开发收获、开发过程中遇到的问题及对应解决方法
12. 参考文献
13. 致谢

> 说明：报告内容框架需完整，排版要求参见附录2。

### 2. 光盘提交要求

光盘需包含以下内容：

- 书面报告电子文档
- 软件代码（程序源代码、数据库逻辑模式创建的SQL文件）
- 安装说明

### 3. 作业递交要求

1. 学生独立完成课题，程序代码单独建立文件夹存放源代码与数据库设计SQL文件，连同课程设计报告等所有课设内容，以「学号+姓名」命名后提交给班长。
2. 班级所有学生的内容统一存放在一张光盘中，每位学生对应一个文件夹，文件夹按学号从小到大命名，格式为「学号+姓名」；跨班级组队的学生，按各自班级学号+姓名分别存档。
3. 所有内容需在课程设计最后一次统一集中上机课之前完成，经老师检查通过后，由班长统一收集U盘并刻录光盘提交学院。
4. 每位学生必须完成全部要求，系统与书面报告需亲自面交老师，经老师认可后方可获得成绩，否则本门课程无成绩。

## 四、课程设计参考题目

可单人或最多4人组队任选一题完成，同组同学需分工协作。报告第一章末尾需写明每位同学的负责内容；若组队工作量不足，全员均按不及格处理，同组分数可因分工、考勤存在差异。可根据设计增减系统功能，也可自拟题目；系统美观度、功能完整度、报告完善度越高，成绩越高。

### 题目1：08 openGauss场景化综合应用实验

以金融行业为场景设计数据库模型，基于华为openGauss构建金融场景数据库。通过创建数据库中的表、约束、视图、索引等对象，掌握基础SQL语法；通过对表中数据进行增删改查操作，模拟金融场景的业务实现。

### 题目2：09 openGauss场景化实验作业设计

围绕金融产品（理财产品、保险、基金）经营场景，通过程序实现基础管理功能，包括：客户信息查询、理财产品查询、符合人群类型的保险产品查询、指定基金产品的上线下线、金融理财产品购买等。

**金融管理系统关系模型参考**：

- 客户信息：客户姓名、身份证号、联系方式、登录密码、电子邮箱
- 银行卡信息：客户可办理多张储蓄卡/信用卡，记录卡号信息
- 理财产品：产品编号、产品名称、产品描述；支持多客户购买，记录购买金额、理财年限
- 保险产品：保险编号、保险名称、适用人群、保险项目；支持多客户购买，记录保险金额、保险年限
- 基金产品：基金编号、基金名称、基金类型、风险等级、基金管理者；支持多客户购买，记录基金金额
- 客户资产：记录客户购买的理财产品、保险、基金的资产状态（可用/冻结）、购买数量、收益、购买时间

### 题目3：11 openGauss数据库应用系统开发(学生选课管理系统)

以学校学生选课为场景进行应用系统开发，采用VSCode作为集成开发环境，Java作为开发语言，layui作为前端框架，SpringBoot、Mybatis作为后端框架，openGauss作为后端数据库，开发学生选课管理系统；openGauss数据库部署于华为弹性云ECS服务器。

**实验环境推荐配置**：

| 软件名称 | 软件版本 |
| --- | --- |
| Linux操作系统 | openEuler 20.3 LTS |
| ECS | 4vCPUs \| 8GiB弹性云服务器 |

**系统用户角色**：

- 管理员：管理系统相关数据
- 教师：查询教授课程，对学生选课成绩进行评定
- 学生：选择课程、查询课程信息与选课成绩/学分

## 附录2：报告书写标准

字体、格式等整体规范参照发放的「课程设计模板」，具体要求如下：

### 1. 目录

按三级标题编写（格式：1……、1.1……、1.1.1……），标题层次清晰，目录标题与正文标题一致，附录需列入目录。
可通过设置大纲级别，利用Word域功能自动生成目录。

### 2. 章节

采用分级阿拉伯数字编号，符合国家标准：

- 第一级：1、2、3……，标题居中书写
- 第二级：2.1、2.2、2.3……，序数顶格书写，后空一格接标题
- 第三级：2.2.1、2.2.2、2.2.3……，空两格书写序数，后空一格接标题
- 分级编号一般不超过四级，两级间用下角圆点分隔，每级末尾不加标点
- 第四级以下采用A.B.C.…和a.b.c.两层编号，空两格书写序数，后空一格接标题
- 正文分项序号采用⑴、⑵、⑶…，子项采用①、②、③…，括号后不加其他标点

### 3. 表格

每个表格配有表序和表题，居中放置在表格上方；表序后空一格书写表题，例如第三章第一个表标注为：**表3-1 XXX**，字体为五号字体。

### 4. 插图

插图需保证线条清晰、画面整洁；每幅插图配有图序和图题，居中放置在图片下方，例如第三章第一个图标注为：**图3-1 XXX**，字体为五号字体。

### 5. 打印与排版要求

- 论文题目：2号黑体加粗
- 一级标题（章）：3号黑体加粗
- 二级标题（节）：4号黑体加粗
- 三级标题（小节）：小4号黑体加粗
- 正文：小4号宋体
- 参考文献：5号宋体
- 页码：5号宋体，居中放置
- 数字和字母：Times New Roman字体
- 版面：A4幅面，1.2倍行距
- 边距：上空2.5cm，下、左、右各空2cm，装订线一侧增加5mm空白
- 页眉：奇数页书写课程设计题目，偶数页书写「江南大学课程设计」，宋体小五号
- 编辑要求：Microsoft Word 2003以上版本，以.doc格式保存，单页起始为第一章

### 6. 参考文献格式

- 书籍：`[序号] 作者1, 作者2. 书名[M]. 出版社名, 出版年: 页码范围`
- 期刊论文：`[序号] 作者1, 作者2. 论文名[J]. 出版社名, 出版年, 卷号(期号): 页码范围`

## 附录3：评分标准

总评成绩 = 平时成绩（50%） + 期末成绩（50%）

- 平时成绩：出勤率 + 课堂表现 + 报告成绩
- 期末成绩：设计的系统成绩

### 成绩等级说明

**1. 优秀（90-100分）**

全勤，平时表现良好；文档撰写正确完整，系统设计优异；分析报告准确规范合理，符合软件工程要求，图表准确且为原创；系统设计合理、界面友好，工作量超出要求或达到企业应用级水平；演示讲解效果好。

**2. 良好（80-89分）**

全勤，平时表现良好；文档撰写基本正确完整，系统设计良好；分析报告准确规范合理，图表准确且为原创；系统设计较合理、界面较友好，工作量符合要求；演示讲解效果较好。

**3. 中等（70-79分）**

基本满勤，平时表现良好；文档撰写一般，系统设计中等；分析报告基本正确，图表基本准确且为原创；系统设计基本合理，工作量基本符合要求，无明显错误；演示讲解效果一般。

**4. 及格（60-69分）**

基本满勤，平时表现一般；文档撰写有偏差，系统设计一般；分析报告基本正确，图表基本准确；系统设计基本合理，工作量勉强符合要求或报告存在明显错误不足；可完成演示讲解。

**5. 不及格（60分以下）**

缺勤较多，平时表现差；文档撰写较差，系统设计较差；系统设计不合理，工作量不足，报告存在明显严重错误；项目中基本未参与发挥作用，或无法完成演示讲解。

### 不及格/零分情形

出现以下任意情形，按不及格或零分处理，后果自负：

1. 报告及软件系统二者缺一者
2. 代码相互拷贝，拷贝方与被拷贝方均按此处理
3. 报告相互抄袭，抄袭方与被抄袭方均按此处理
4. 报告由网页、书籍内容拼凑而成，成段复制或无实际内容者
5. 提交的软件为网上下载，非自主开发
6. 软件或报告为其他课程作业/成果，或由他人代做
