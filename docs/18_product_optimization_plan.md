# 产品优化规划：地图优先设计

> 版本：2.0  
> 更新日期：2026-06-18  
> 状态：待评审
>
> **历史规划说明（2026-08-01）**：本文是 2026-06-18 的地图优先改造草案，不代表当前功能基线。文中的收藏动作属于历史设想，现行产品已删除收藏能力。

## 一、当前方案问题分析

### 1.1 核心问题

**问题 1：产品定位模糊**
- 当前文档将产品定位为"校园信息共享与沉淀平台"，但未突出"地图"这一核心交互方式
- 页面规格中，首页是"信息流 + 推荐"，地图只是"发现页"的一个子功能
- 用户进入后的第一视觉焦点不是地图，而是信息列表

**问题 2：信息架构不合理**
- 底部导航：首页 → 发现 → 发布 → 消息 → 我的
- 地图被放在"发现页"下，需要二次点击才能进入
- 地图作为核心功能，却沦为二级页面

**问题 3：视觉风格与 demo 不一致**
- 现有 UI 规范采用标准化组件风格（纯白卡片、标准圆角、常规阴影）
- 两个 demo HTML 采用手绘风格（不规则边框、纸张质感、校园插画）
- 文档规范与实际 demo 存在明显割裂

**问题 4：页面设计缺乏重点**
- 首页同时承载信息流、推荐、分类入口、搜索入口
- 信息卡片抢占视觉空间，地图入口不够突出
- 用户进入后不知道第一步应该做什么

### 1.2 Demo 分析

#### Demo 1：创意文档.html

**设计特点：**
- 配色：主色 #287a55（深绿），背景 #f4f7f4（浅灰绿），强调色 #f4b85f（暖黄）
- 风格：清新、温暖、校园感，使用 emoji 作为图标
- 布局：卡片式布局，圆角 24px，柔和阴影
- 特色：mini-map 示意区域，展示地图概念

**可复用元素：**
- 配色方案（绿色系 + 暖黄强调）
- 卡片样式（大圆角、柔和阴影）
- emoji 图标风格
- 温暖亲切的文案语气

#### Demo 2：此刻校园_可演示Demo.html

**设计特点：**
- 配色：主色 #174d5e（深蓝绿），背景 #f8fbfa（米白），强调色 #ff8a4c（橙色）
- 风格：手绘地图风格，使用 SVG 绘制校园地图，带有纸张质感
- 布局：左侧分类面板 + 中间地图区域 + 右侧信息流
- 特色：
  - 地图作为主视觉区域（占据 60% 以上空间）
  - 手绘风格的地图标记（pin-bubble 带旋转角度）
  - 地图/列表视图切换
  - 右侧"校园正在发生"信息流

**可复用元素：**
- 地图优先的布局结构
- 手绘风格地图（SVG 实现）
- 地图标记样式（带旋转、阴影、hover 效果）
- 分类筛选面板
- 地图/列表切换交互
- 信息卡片样式（左侧彩色边条）

**关键发现：**
Demo 2 已经实现了"地图优先"的设计理念，地图占据主视觉区域，分类筛选在左侧，信息流在右侧作为补充。这正是产品应该采用的核心交互方式。

## 二、地图优先的产品定位说明

### 2.1 产品定位重新定义

**原定位：**
> "此刻校园"是一个校园信息共享与沉淀平台。

**新定位：**
> "此刻校园"是一个**基于校园地图的信息发现与共享平台**。用户通过地图发现校园中的各类信息点位，也可以发布新的地点信息，形成一张由校园成员共同维护的"校园生活地图"。

**核心差异：**
- 原定位：信息为中心，地图为辅助
- 新定位：**地图为中心**，信息为地图上的点位

### 2.2 核心交互方式

**主页面 = 校园地图**

用户进入产品后，首先看到的是：
1. **全屏地图**（占 70% 以上空间）
2. **地图上的信息点位标记**（不同分类用不同颜色/图标）
3. **左侧分类筛选面板**（快速过滤特定类型信息）
4. **右侧信息流面板**（展示"校园正在发生"的动态）
5. **顶部搜索栏**（关键词搜索）
6. **发布按钮**（发布新的地点信息）

**核心操作流程：**
```
查看地图 → 点击标记 → 查看详情 → 确认有效/收藏/评论
    ↓
筛选分类 → 查看特定点位 → 查看详情
    ↓
搜索关键词 → 定位到相关点位 → 查看详情
    ↓
点击发布 → 选择地点 → 填写信息 → 发布新点位
```

### 2.3 地图的核心价值

**为什么地图应该是核心？**

1. **空间维度是校园信息的关键属性**
   - "哪里有好吃的" → 需要知道位置
   - "哪里可以打印" → 需要知道距离
   - "哪里有校园猫" → 需要知道出没地点
   - 地图天然承载空间信息

2. **地图提供直觉式发现**
   - 用户可以看到"附近有什么"
   - 用户可以发现"原来这里有个好地方"
   - 地图支持探索式浏览，而不仅仅是搜索

3. **地图是差异化竞争力**
   - 普通论坛/社区：信息列表
   - 此刻校园：**地图 + 信息点位**
   - 这是产品的核心创新点

4. **地图支持多场景使用**
   - 新生：查看校园全貌，了解设施分布
   - 在校生：发现附近的新地点
   - 访客：快速定位目标地点

- 地图占据全屏

- 底部信息卡片可上拉展开（显示更多信息）
- 底部导航简化为：地图 | 发现 | 发布 | 我的

### 3.3 页面层级调整

**原层级：**
```
首页（信息流） → 发现页（地图入口） → 地图页
```

**新层级：**
```
地图页（主页） → 信息详情页（点击标记）
    ↓
发现页（列表视图） → 信息详情页
    ↓
发布页 → 发布成功
```

**底部导航调整：**

| 原导航 | 新导航 | 说明 |
|--------|--------|------|
| 首页 | **地图** | 地图作为主页 |
| 发现 | **发现** | 列表视图 + 分类浏览 |
| 发布 | **发布** | 保持不变 |
| 消息 | **我的** | 合并消息到"我的" |
| 我的 | - | 合并到"我的" |

## 五、地图交互流程

### 5.1 核心交互流程

**流程 1：浏览地图 → 查看详情**
```
1. 用户进入主页（地图页）
2. 查看地图上的标记点位
3. 点击某个标记
4. 弹出详情卡片（底部卡片或半屏弹窗）
5. 查看详情：标题、分类、地点、图片、描述、有效性状态
6. 操作：确认有效、收藏、评论、导航
```

**流程 2：筛选分类 → 查看特定点位**
```
1. 用户点击左侧分类（如"美食"）
2. 地图只显示该分类的标记
3. 点击某个标记
4. 查看详情
```

**流程 3：搜索 → 定位点位**
```
1. 用户在搜索栏输入关键词（如"打印"）
2. 地图高亮匹配的标记
3. 其他标记变灰
4. 点击高亮标记查看详情
```

**流程 4：发布新点位**
```
1. 用户点击"发布"按钮
2. 在地图上点击选择地点（或搜索地点）
3. 填写信息：标题、分类、描述、图片、标签
4. 预览并发布
5. 新点位出现在地图上
```

### 5.2 地图控件

**缩放控件：**
- 位置：地图右下角
- 功能：放大、缩小
- 快捷键：Ctrl + 滚轮

**定位控件：**
- 位置：地图右下角（缩放控件上方）
- 功能：定位到用户当前位置
- 权限：需要用户授权地理位置

**图层切换：**
- 位置：地图左下角
- 功能：切换地图样式（标准/卫星/手绘）
- 第一版：仅支持手绘风格

**地图/列表切换：**
- 位置：地图右上角
- 功能：切换地图视图和列表视图
- 默认：地图视图

### 5.3 地图标记交互

**标记点击：**
- 点击标记 → 弹出详情卡片
- 详情卡片内容：
  - 标题
  - 分类图标
  - 地点名称
  - 距离（如果授权位置）
  - 有效性状态
  - 点赞数、评论数
  - 操作按钮：确认有效、收藏、评论、导航

**标记 Hover：**
- 显示标签（地点名称）
- 标记放大 + 上浮

**标记筛选：**
- 选择分类 → 只显示该分类标记
- 搜索关键词 → 高亮匹配标记

## 六、页面视觉风格规范

### 6.1 整体风格定义

**关键词：**
- 清新
- 温暖
- 轻松
- 校园感
- 手绘感
- 年轻化
- 社区氛围

**避免：**
- ❌ 过度科技感
- ❌ 传统后台管理系统风格
- ❌ 大量冰冷的纯白卡片
- ❌ 标准化组件堆叠
- ❌ 过度花哨

### 6.2 配色方案

**主色调：**

**圆角系统：**


**阴影系统：**
```css

```

### 6.5 手绘风格元素

**地图背景：**
- 使用 SVG 绘制手绘风格校园地图
- 包含：道路、建筑、绿地、水体
- 建筑使用不规则矩形（轻微旋转）
- 道路使用曲线（非直线）
- 添加纸张质感（noise 纹理）

**地图标记：**
- 气泡形状（圆角矩形 + 小尾巴）
- 轻微旋转（-6deg）
- 白色粗边框（3px）
- 柔和阴影

**卡片设计：**
- 左侧彩色边条（4px）
- 大圆角（20px）
- 柔和阴影
- Hover 时上浮（-2px）

**装饰元素：**
- 可使用少量手绘插画（小猫、树木、云朵等）
- 插画风格：线条简单、色彩柔和

## 九、技术风险与解决方案

### 9.1 技术风险

**风险 1：SVG 地图性能**
- 问题：SVG 地图包含大量元素，可能影响渲染性能
- 影响：地图缩放、拖动时卡顿
- 概率：中

**解决方案：**
- 使用 SVG 简化路径（减少节点数）
- 使用 CSS transform 实现缩放（GPU 加速）
- 使用 requestAnimationFrame 优化动画
- 如果性能问题严重，考虑使用 Canvas 或 WebGL

**风险 2：地图标记数量**
- 问题：标记数量过多时，地图性能下降
- 影响：标记渲染慢、点击响应慢
- 概率：中

**解决方案：**
- 使用标记聚合（zoom 级别低时，聚合相近标记）
- 使用虚拟列表（只渲染可见区域的标记）
- 限制单次渲染数量（最多 100 个标记）

**风险 3：手绘风格地图维护**
- 问题：SVG 地图需要手动维护，更新成本高
- 影响：校园建筑变化时，地图更新困难
- 概率：高

**解决方案：**
- 第一版使用 SVG 手绘地图（快速实现）
- 后续接入真实地图服务（MapLibre GL JS）
- 提供地图编辑工具（管理员可更新地图）

**风险 4：移动端地图交互**
- 问题：移动端屏幕小，地图操作不便
- 影响：用户体验差
- 概率：高

**解决方案：**
- 移动端使用全屏地图
- 简化地图控件（只保留缩放、定位）
- 使用手势操作（双指缩放、单指拖动）
- 底部信息卡片可上拉展开

**风险 5：地图服务依赖**
- 问题：如果使用真实地图服务，依赖第三方服务
- 影响：服务不稳定、费用问题
- 概率：低

**解决方案：**
- 第一版使用 SVG 手绘地图（无依赖）
- 后续接入 MapLibre GL JS（开源、免费）
- 使用离线地图瓦片（减少网络依赖）

### 9.2 技术选型建议

**地图实现方案：**

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| SVG 手绘地图 | 快速实现、无依赖、风格统一 | 维护成本高、不支持真实地理坐标 | 第一版、演示版 |
| MapLibre GL JS | 功能强大、支持真实地图、性能优秀 | 需要地图瓦片服务、学习成本高 | 正式版、生产环境 |
| Leaflet | 轻量、易用、插件丰富 | 性能不如 MapLibre、样式定制困难 | 中型项目 |

**建议：**
- 第一版：使用 SVG 手绘地图（快速实现、风格统一）
- 正式版：接入 MapLibre GL JS（功能强大、性能优秀）
