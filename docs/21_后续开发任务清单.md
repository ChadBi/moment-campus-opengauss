## 0. 使用说明

### 0.1 文档定位

本清单将后续开发工作拆分为**可执行任务**，每项任务包含：
- 任务编号（用于跨文档引用，如 `T-A-02`）
- 任务名称
- 任务目标
- 涉及文件（精确到路径）
- 前置条件（依赖的其他任务编号或外部条件）
- 验收标准（可客观判断是否完成）
- 优先级（P0/P1/P2）
- 风险或注意事项

### 0.2 任务编号规则

```
T-<阶段>-<序号>
```

| 阶段代号 | 阶段名称 | 对应 doc 19 阶段 | 对应 doc 20 阶段 |
| -------- | -------- | ---------------- | ---------------- |
| A | openGauss 适配 | 阶段 A | 阶段 0–6 |
| B | 核心业务升级 | 阶段 B | — |
| C | 创新点实现 | 阶段 C | — |
| D | 扩展能力 | 阶段 D | — |
| E | 测试与交付 | 阶段 E | 阶段 7 |
| X | 横切关注点 | 跨阶段 | — |

### 0.3 优先级定义

| 优先级 | 含义 | 完成门槛 |
| ------ | ---- | -------- |
| **P0** | 必须完成，否则无法交付课程设计 | 全部完成且通过验收 |
| **P1** | 核心创新点，体现课设深度 | 至少完成 80% |
| **P2** | 锦上添花 | 视时间情况 |
