# 安全与隐私

> 此刻校园 · Moment Campus

## 1. 身份认证安全

### 1.1 密码安全

**加密存储**

- 使用 bcrypt 算法对用户密码进行加密存储
- bcrypt 成本因子（cost factor）设置为 12 或更高
- 每个用户使用独立的盐值（salt）
- 禁止明文存储或可逆加密存储密码

**密码强度要求**

- 最小长度：8 个字符
- 必须包含：字母和数字
- 建议包含：大小写字母、数字、特殊字符
- 禁止使用常见弱密码（如 123456、password 等）
- 密码强度检测与提示

**密码重置**

- 通过邮箱验证码进行密码重置
- 验证码有效期：5 分钟
- 验证码使用后立即失效
- 限制密码重置频率（每小时最多 3 次）

### 1.2 JWT Token 安全

**Token 配置**

- Access Token 有效期：2 小时
- Refresh Token 有效期：7 天
- 使用 RS256 算法（非对称加密）签名
- Token 中包含用户 ID、角色、过期时间等必要信息
- 禁止在 Token 中存储敏感信息

**Token 刷新机制**

- Access Token 过期前 30 分钟可刷新
- 刷新时颁发新的 Access Token
- Refresh Token 使用后自动失效（一次性使用）
- 支持 Refresh Token 轮换（rotation）

**Token 存储方式**

- Access Token：存储在内存中（前端）
- Refresh Token：存储在 HttpOnly Cookie 中
- 禁止将 Token 存储在 localStorage 中（防止 XSS 攻击）
- Cookie 设置 Secure 标志（仅 HTTPS 传输）
- Cookie 设置 SameSite=Strict 标志（防止 CSRF）

### 1.3 登录失败锁定机制

**失败次数限制**

- 连续登录失败 5 次后，账户锁定 15 分钟
- 锁定期间禁止该账户登录
- 锁定期间显示友好提示，不透露账户是否存在

**锁定解除**

- 锁定时间到期后自动解除
- 支持通过邮箱验证码提前解除锁定
- 管理员可手动解除锁定

**失败记录**

- 记录登录失败的 IP 地址
- 记录登录失败的时间
- 记录登录失败的用户名（如果存在）
- 用于安全审计和异常检测

## 2. 权限验证

### 2.1 基于角色的权限控制

**角色定义**

| 角色 | 说明 | 权限范围 |
|------|------|----------|
| 游客 | 未登录用户 | 浏览公开信息、查看地点、搜索 |
| 普通用户 | 已登录用户 | 游客权限 + 发布信息、评论、点赞、举报 |
| 管理员 | 系统管理员 | 普通用户权限 + 内容审核、用户管理、系统配置 |

**权限矩阵**

| 操作 | 游客 | 普通用户 | 管理员 |
|------|------|----------|--------|
| 浏览信息 | ✅ | ✅ | ✅ |
| 搜索信息 | ✅ | ✅ | ✅ |
| 查看地点 | ✅ | ✅ | ✅ |
| 发布信息 | ❌ | ✅ | ✅ |
| 编辑自己的信息 | ❌ | ✅ | ✅ |
| 删除自己的信息 | ❌ | ✅ | ✅ |
| 评论、点赞 | ❌ | ✅ | ✅ |
| 举报内容 | ❌ | ✅ | ✅ |
| 审核内容 | ❌ | ❌ | ✅ |
| 管理用户 | ❌ | ❌ | ✅ |
| 系统配置 | ❌ | ❌ | ✅ |

### 2.2 API 接口权限中间件

**中间件实现**

- 每个 API 接口明确指定所需角色
- 中间件在请求处理前验证用户权限
- 权限验证失败返回 403 Forbidden
- 未登录访问受保护接口返回 401 Unauthorized

**权限装饰器示例**

```python
# 后端权限装饰器示例
def require_role(*roles):
    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            user = get_current_user()
            if not user or user.role not in roles:
                abort(403)
            return func(*args, **kwargs)
        return wrapper
    return decorator

@app.route('/api/posts', methods=['POST'])
@require_role('user', 'admin')
def create_post():
    # 只有登录用户和管理员可以发布信息
    pass
```

### 2.3 防止越权访问

**资源所有权验证**

- 用户只能编辑和删除自己创建的内容
- API 接口验证资源所有权
- 尝试访问他人资源返回 403 Forbidden

**IDOR 防护**

- 禁止通过简单递增 ID 访问资源
- 使用 UUID 或不可预测的标识符
- 验证请求用户是否有权访问目标资源

**批量操作防护**

- 限制批量操作的数量
- 验证批量操作中每个资源的所有权
- 记录批量操作日志

## 3. 接口安全

### 3.1 接口限流（Rate Limiting）策略

**限流维度**

- 基于 IP 地址限流
- 基于用户 ID 限流
- 基于接口路径限流

**限流策略**

| 接口类型 | 限流策略 | 说明 |
|----------|----------|------|
| 登录接口 | 10 次/分钟/IP | 防止暴力破解 |
| 注册接口 | 5 次/小时/IP | 防止批量注册 |
| 密码重置 | 3 次/小时/IP | 防止恶意重置 |
| 信息发布 | 30 次/小时/用户 | 防止刷屏 |
| 评论接口 | 60 次/小时/用户 | 防止恶意评论 |
| 搜索接口 | 100 次/分钟/用户 | 防止滥用搜索 |
| 文件上传 | 20 次/小时/用户 | 防止滥用存储 |
| 普通接口 | 300 次/分钟/用户 | 默认限流 |

**限流响应**

- 超限时返回 429 Too Many Requests
- 响应头包含限流信息：
  - `X-RateLimit-Limit`: 限制次数
  - `X-RateLimit-Remaining`: 剩余次数
  - `X-RateLimit-Reset`: 重置时间

### 3.2 SQL 注入防护

**ORM 参数化查询**

- 使用 SQLAlchemy ORM 进行数据库操作
- 禁止拼接 SQL 字符串
- 所有用户输入通过参数化查询传递

**示例**

```python
# 正确：使用 ORM 查询
posts = session.query(Post).filter(Post.title == user_input).all()

# 错误：拼接 SQL（禁止）
query = f"SELECT * FROM posts WHERE title = '{user_input}'"
```

**输入验证**

- 验证输入数据类型
- 验证输入长度
- 过滤特殊字符
- 使用白名单验证枚举值

### 3.3 XSS 防护

**输入过滤**

- 过滤用户输入中的 HTML 标签
- 过滤 JavaScript 事件（onerror、onclick 等）
- 过滤 javascript: 协议
- 允许安全的 Markdown 格式

**输出转义**

- 前端渲染时转义 HTML 实体
- 使用 React 的 JSX 自动转义
- 禁止使用 `dangerouslySetInnerHTML`
- 必须使用时进行严格的消毒处理

**Content Security Policy**

- 配置 CSP 头限制资源加载
- 禁止内联脚本执行
- 限制外部资源域名

### 3.4 CSRF 风险及应对

**风险评估**

- 使用 JWT Token 认证，CSRF 风险较低
- Refresh Token 存储在 HttpOnly Cookie 中，存在 CSRF 风险

**防护措施**

- Cookie 设置 SameSite=Strict
- 关键操作验证 Origin 或 Referer 头
- 敏感操作要求二次验证（如密码确认）

## 4. 文件上传安全

### 4.1 文件类型白名单

**允许的文件类型**

| 类型 | 扩展名 | MIME 类型 |
|------|--------|-----------|
| 图片 | .jpg, .jpeg | image/jpeg |
| 图片 | .png | image/png |
| 图片 | .gif | image/gif |
| 图片 | .webp | image/webp |

**禁止的文件类型**

- 可执行文件：.exe, .bat, .cmd, .sh
- 脚本文件：.php, .asp, .jsp, .py
- 文档文件：.pdf, .doc, .docx（第一版不支持）
- 压缩文件：.zip, .rar, .7z
- 其他所有未明确允许的类型

**文件类型验证**

- 验证文件扩展名
- 验证文件 MIME 类型
- 验证文件魔数（magic number）
- 三重验证确保文件类型正确

### 4.2 文件大小限制

**大小限制**

- 单张图片最大：5 MB
- 单次上传最多：9 张图片
- 总上传大小最大：45 MB

**压缩处理**

- 上传后自动压缩图片
- 压缩后质量：80%
- 最大尺寸：1920x1080
- 生成缩略图：400x300

### 4.3 文件名安全处理

**文件重命名**

- 使用 UUID 重命名上传文件
- 禁止使用原始文件名
- 禁止包含特殊字符

**存储路径**

- 按日期组织存储目录：/uploads/2024/01/15/
- 禁止目录遍历（..）
- 禁止访问系统目录

### 4.4 病毒扫描（后续）

**扫描方案**

- 集成 ClamAV 进行病毒扫描
- 上传后异步扫描
- 扫描完成前标记为"待审核"
- 发现病毒立即删除并通知用户

## 5. 敏感信息保护

### 5.1 联系方式保护策略

**默认不公开**

- 联系方式默认不显示
- 用户可选择是否公开联系方式
- 公开时显示为"点击查看"

**查看限制**

- 需要登录才能查看联系方式
- 记录查看联系方式的用户
- 限制查看频率（防止爬取）

**联系方式类型**

- 手机号：部分隐藏（138****1234）
- 微信号：完整显示
- QQ 号：完整显示
- 邮箱：部分隐藏（a****b@example.com）

### 5.2 发布前敏感信息检测

**检测内容**

- 手机号（11 位数字）
- 身份证号（18 位）
- 银行卡号（16-19 位）
- 邮箱地址
- 微信号、QQ 号
- 家庭住址

**检测处理**

- 检测到敏感信息时提示用户
- 建议用户隐藏或模糊处理
- 用户确认后可继续发布
- 记录检测结果用于审计

### 5.3 数据加密存储

**加密字段**

- 密码：bcrypt 加密
- 联系方式：AES-256 加密
- 邮箱：AES-256 加密

**密钥管理**

- 使用环境变量存储密钥
- 定期轮换密钥
- 禁止硬编码密钥
- 禁止将密钥提交到代码库

## 6. 位置隐私

### 6.1 用户位置授权机制

**授权流程**

- 首次使用地图功能时请求授权
- 明确说明位置用途
- 用户可选择拒绝授权
- 拒绝后仍可使用其他功能

**授权类型**

- 精确定位：用于定位当前位置
- 地点选择：仅在用户主动为帖子选择地点时使用学校地图坐标，不采集用户实时位置
- 手动选择：在地图上选择地点

**授权管理**

- 用户可随时关闭位置授权
- 在设置中管理位置权限
- 关闭后不记录位置信息

### 6.2 地点模糊化方案

**模糊化策略**

- 发布地点时不记录精确坐标
- 地点坐标模糊化到 100 米范围
- 显示大致位置而非精确位置
- 用户可选择是否显示位置

**模糊化实现**

```python
# 坐标模糊化示例
def fuzz_location(lat, lng, precision=100):
    # 将坐标模糊化到 precision 米范围
    offset_lat = random.uniform(-precision, precision) / 111000
    offset_lng = random.uniform(-precision, precision) / (111000 * math.cos(lat))
    return lat + offset_lat, lng + offset_lng
```

### 6.3 不收集行动轨迹

**隐私承诺**

- 不记录用户的行动轨迹
- 不分析用户的位置历史
- 不基于位置进行用户画像
- 不向第三方分享位置数据

**数据收集**

- 只收集用户主动选择的地点
- 只收集发布内容时选择的位置
- 不后台收集位置信息
- 不记录浏览位置历史

## 7. 用户数据控制

### 7.1 账号注销流程

**注销条件**

- 账户无未处理的违规记录
- 账户无未完成的交易
- 确认注销意愿

**注销流程**

1. 用户提交注销申请
2. 验证身份（输入密码或邮箱验证码）
3. 确认注销后果
4. 进入 7 天冷静期
5. 冷静期内可取消注销
6. 冷静期后自动注销

**注销处理**

- 删除用户个人信息
- 删除用户发布的内容
- 删除用户的评论、点赞
- 保留统计数据（匿名化）

### 7.2 用户数据删除

**删除范围**

- 个人基本信息
- 发布的内容
- 上传的图片
- 评论、点赞记录
- 登录记录

**删除方式**

- 软删除：标记为已删除，30 天后物理删除
- 物理删除：从数据库中彻底删除
- 备份删除：从备份中删除（如有）

**删除验证**

- 删除后验证数据不可访问
- 删除后验证关联数据已处理
- 记录删除日志

### 7.3 数据导出（后续）

**导出内容**

- 个人信息
- 发布的内容
- 评论记录

**导出格式**

- JSON 格式
- 包含所有用户数据
- 包含数据关联关系

**导出流程**

- 用户提交导出申请
- 系统生成导出文件
- 提供下载链接（24 小时有效）
- 记录导出日志

## 8. 最小化数据收集

### 8.1 只收集必要数据

**必要数据**

- 用户名：用于显示和登录
- 邮箱：用于登录和找回密码
- 密码：用于登录验证
- 发布内容：核心功能数据
- 位置信息：地点相关功能

**非必要数据**

- 不收集手机号（可选）
- 不收集真实姓名（可选）
- 不收集学号（不收集）
- 不收集身份证号（不收集）

### 8.2 数据保留策略

**保留期限**

| 数据类型 | 保留期限 | 说明 |
|----------|----------|------|
| 活跃账户数据 | 账户存续期间 | 正常使用期间保留 |
| 已注销账户数据 | 30 天 | 冷静期后删除 |
| 登录日志 | 90 天 | 安全审计需要 |
| 操作日志 | 180 天 | 安全审计需要 |
| 举报记录 | 1 年 | 社区治理需要 |
| 备份数据 | 30 天 | 灾难恢复需要 |

**过期处理**

- 定期清理过期数据
- 自动化清理脚本
- 记录清理日志

### 8.3 日志脱敏

**脱敏字段**

- 密码：不记录
- 联系方式：部分隐藏
- 邮箱：部分隐藏
- IP 地址：部分隐藏

**脱敏示例**

```
# 原始日志
User login: user@example.com, password: 123456, phone: 13812341234

# 脱敏后日志
User login: u***@example.com, password: ***, phone: 138****1234
```

**日志级别**

- DEBUG：开发环境，包含详细信息
- INFO：生产环境，记录关键操作
- WARNING：记录异常和警告
- ERROR：记录错误和失败
