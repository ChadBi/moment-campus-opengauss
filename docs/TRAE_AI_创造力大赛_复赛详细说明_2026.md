# 二、初赛 Demo 与复赛完整作品的区别

很多选手会问:「初赛已经交过 Demo 了，复赛还要再交什么?」答案是——交一个**真正能用起来的产品**。

初赛的 Demo 只需要「证明你的想法能成立」，跑通一条核心链路、让评审看到创意亮点即可；而复赛要交的是一个**功能完整、流程顺畅、体验稳定、供评审随时打开体验**的正式作品。换句话说,你要把初赛那个「能演示的雏形」，继续打磨成一个「他人可真实上手使用」的成品。

**1. 核心目标：从「打动评审」到「可被使用」。**初赛 Demo 的使命是让评审相信你的创意可行、有亮点；复赛作品则要交付一个有完整使用流程、能被真实体验的产品，评审会像真实用户一样把它从头用到尾。

**2. 功能与页面：从「跑通一条链路」到「核心功能齐全」。**初赛跑通 1 条核心链路即可；复赛要求核心功能齐全、必要页面完备，具备一个产品应有的**完整用户路径，**而不是只能走通「主流程那一条路」。

**3. 稳定性：从「能演示」到「可稳定使用」。**初赛允许有小瑕疵，只要能演示、可交互即可；复赛要求结构稳定可靠，核心流程能顺畅走通、无**严重 bug，**经得起评审反复操作。

**4. 体验形式：从「链接 / 视频」到「真实可访问的产品」。**初赛可以用体验链接、可交互 HTML 甚至演示视频来展示；复赛必须提供**真实可访问、可独立运行**的体验环境(在线链接、Web 应用、小程序、可安装的 App 等)，具体按第三部分「按作品形式，你该交什么」准备；硬件赛道则需提交真实硬件的完整演示视频(见第三部分)。

**5. 必备材料：在 Demo 基础上做加法。**复赛不是把初赛材料原样再交一遍，而是在原有简介、创作思路、体验入口、TRAE 实践过程之上，**新增产品说明书、完整产品演示视频，以及更完整、可核验的 TRAE 实践证明**(关键任务 Session ID 不少于 3 个)，让技术方案与 AI 开发过程均可被核验。

> ✅
> **复赛合格作品的最低标准(对照自查):**
> 1. 是延续初赛 Demo、与初赛创意方向一致的**完整作品，**不是另起炉灶的新项目；
> 2. 必须完全由 [TRAE IDE](https://www.trae.cn/ide/download) 或 [TRAE Work](https://www.trae.cn/ide/download) 开发，并能提供可核验的开发过程材料；
> 3. 具备完整的用户使用路径、齐全的核心功能与必要页面，产品结构稳定可靠、核心流程可顺畅走通；
> 4. 软件类作品已**部署上线 / 可被评审直接访问体验；**硬件类作品已做出**可真实运行的实物**(详见第三部分)；
> 5. 技术架构清晰，AI 链路可验证，任务 Session ID 不少于 3个。

> 🌐
> **关于「是否需要部署上线」——请务必看清：**
> - **软件类作品(Web / 小程序 / App / 抖音小程序等)：需要让评审「能直接体验」，因此必须部署上线或提供可独立运行的体验入口。仅提交一段录屏尚不满足要求——评审需要亲自打开你的产品、走一遍真实流程来打分**。Web 作品请部署到可公开访问的线上环境(HTTP/HTTPS 链接)；小程序提供可扫码的体验版二维码；App 提供可安装的安装包(APK / TestFlight 等)。**源代码并非必须提交项:**能提供上述可运行的体验入口即可，是否附源码由你自行决定;仅当主办方核验原创性时，可要求补交源码。
> - **硬件类作品：无需「部署到服务器」，但必须做出可真实运行的硬件实物，**并通过完整演示视频 + 硬件方案文档证明其真实可用(详见第三部分)；决赛为线下路演，届时需现场演示实物。
> - **无论哪种形式，「产品演示视频」都是必交项，**作为评审无法实际安装 / 运行时的兜底验证，但它**不能替代**软件作品的可体验入口或硬件作品的实物。

# 三、按作品形式，你该交什么

不同形式的作品，「可体验」的方式不一样。请先对号入座，找到你的作品类型，按对应要求准备「体验入口」。核心原则只有一句：**软件类作品要「能被评审直接打开、上手体验」，硬件类作品要「做出可真实运行的实物」**。所有作品**除体验入口外，都需额外提交一段产品演示视频（录屏即可，1–5 分钟，清晰展示核心流程）**，作为评审无法实际安装 / 运行时的兜底验证——但请注意，演示视频**不能替代**软件作品的可体验入口或硬件作品的实物。

| **作品形式** | **体验入口该怎么交（择一即可，越易体验越好）** | **额外要求** |
|-|-|-|
| **Web 网站 / Web 应用** | 提供一个随时可公开访问的部署链接（HTTP/HTTPS），评审点开即可体验 | 如有登录，请提供测试账号密码 |
| **纯前端 / HTML 作品** | 可公开访问的部署链接；或将可交互的 HTML 文件用 **Zip 打包**，作为附件上传到飞书问卷 | Zip 内附 1 份「如何打开」的简短说明 |
| **微信小程序** | ① 体验版二维码（推荐）；  <br/>② 或提供小程序名称 + 测试账号，并在演示视频中完整走查核心流程 | 体验版二维码请确保在评审期内有效；注明扫码后的进入路径 |
| **抖音小程序 / 抖音小游戏** | ① 抖音小程序/小游戏的体验二维码或测试链接；  <br/>② 或提供作品名称 + 进入路径，并配完整录屏 | 注明是否需要特定客户端版本 |
| **移动 App（Android / iOS）** | Android：提供 **APK 安装包**（上传问卷或第三方网盘公开链接）；  <br/>iOS：提供 TestFlight 链接或可安装的描述文件，如不便分发可用完整录屏 + 安装包替代 | 注明系统版本要求、安装步骤；如有登录请提供测试账号 |
| **桌面客户端（Win / Mac）** | 提供可下载的安装包（上传问卷或第三方网盘公开链接），附安装与运行说明 | 注明操作系统与运行环境要求；**若为需配置 API 的智能体类应用,请在说明中写明「需在设置页填入模型 API Key 后使用」,并以完整录屏展示从启动 → 配置 API → 运行 → 出结果的真实过程**(本地应用无在线体验链接，以演示视频为主)。 |
| **硬件作品** | 硬件赛道**必须做出可真实运行的硬件实物**(不能只用效果图、渲染图或概念视频代替)，并提交**真实硬件的完整演示视频**（展示实物从开机到完成核心功能的全过程，能看出是真机而非模型）  <br/>如作品含硬件设计细节，可选交简要方案说明（硬件清单、原理框图等），非强制。 | **决赛为线下路演，如晋级后须携带硬件实物到现场演示；**因此复赛阶段请确保硬件确实做出来、能稳定运行。视频请上传至 抖音等第三方平台后附公开链接。  <br/>**如评审在打分过程中需进一步核验，主办方有权要求选手邮寄硬件实物作为评审补充；届时请按官方通知配合寄送。** |
| **硬件内嵌软件 / 固件** | ① 提交运行在硬件上的**软件源码包 / 固件包**（Zip）；  <br/>② **演示视频**展示软件在设备上的真实运行效果；  <br/>③ 软件与硬件的**交互链路说明文档。** | 说明软件运行的目标设备 / 芯片平台、烧录或部署方式；**该软件须已真实运行在硬件设备上，**决赛线下路演时需现场演示真机运行效果。 |
| **其他形式** | 若你的作品不属于上表所列形式(例如浏览器插件 / 扩展、API 或后端服务、CLI 命令行工具、AI Agent 或自动化工作流、开发者库 / SDK、脚本工具等)，请提供任意一种可供评审独立验证的体验方式（如可访问的服务地址、可运行的调用示例、可安装的插件包等），并在演示视频中完整走查核心流程。 | 不确定如何提交可在交流群咨询官方 |



> 📌
> **统一提醒：**
> - **源代码非必交项：**复赛以「评审能否真实体验到你的作品」为准，并不强制提交完整源代码。软件类作品只需按第三部分提供可体验入口（在线链接 / 体验二维码 / 可安装的安装包等），**无需上交源码；**仅当作品没有可在线体验的形式（如需本地运行的桌面客户端、硬件内嵌软件 / 固件），才需以安装包、源码包或固件包作为评审运行的替代。是否额外附上源码由你自愿决定，不作加减分依据。如主办方需核验原创性，可要求你补交源码，届时按官方通知提供即可。
> - 凡涉及登录、付费、权限的作品，**务必提供可用的测试账号 / 体验权限**，否则评审无法体验将影响评分。
> - 凡通过链接分发的安装包 / Zip / 视频，请确保链接在**整个复赛评审期（截止至公示前）持续有效、可公开访问、无需额外申请权限**。
> - 体验入口失效、文件无法打开、无法正常运行，主办方有权要求补充材料、暂缓评审或降低晋级优先级。
> - **API Key 安全：**凡需配置模型 API 的作品，**任何阶段都不得将真实 API Key 明文写入文档、演示视频或提交包；**录屏中涉及密钥的画面请打码。如需评审实测,，请提供**测试专用 Key 或测试账号，**或在说明中写清评审如何自行配置。
> - **无需备案 / 上架：**复赛只考察评审能否实际体验到你的作品，**不要求任何 ICP 备案、小程序类目审核或应用商店上架**。小程序用**开发版 / 体验版二维码**提交即可(无需发布上线)；App 用 **APK 安装包(Android)或 TestFlight / 内测包(iOS)**提交即可(无需上架商店)；Web 作品如受国内域名备案限制，可使用免备案的海外托管(如 Vercel、Netlify、GitHub Pages、Cloudflare Pages 等)或临时公网链接，评审能打开即可。
> - **硬件作品复赛无需主动邮寄实物：**复赛阶段硬件只需提交真机实物的完整演示视频（能看出是真机运行、非渲染或概念演示）即可，无需主动邮实物；实物到现场演示是决赛(线下路演)环节的要求，晋级决赛后携带即可。但若评审在打分过程中需进一步核验，主办方有权要求选手邮寄硬件实物作为评审补充，届时请按官方通知配合寄送。

# 四、提交方式：社区发帖 + 飞书问卷提交（防止作品被盗用）

复赛阶段你交付的是接近成品的完整作品。我们既希望你的作品能在社区充分展示、获得关注，又要**保护你的作品不被他人抄袭、盗用或抢先公开**。因此复赛采用「**社区发帖 + 飞书问卷提交**」的双轨机制:**「让别人看得懂、感兴趣」的内容(产品说明书、演示视频、TRAE 实践过程)发到社区公开展示；「能被下载、复刻」的作品本体(体验入口、源码包、安装包等)只走飞书问卷提交。**请严格按下表区分什么交到哪里。

| **提交内容** | **提交到哪里** | **是否公开** |
|-|-|-|
| 作品名称、赛道、团队介绍(如有)、**产品简介**、**产品演示视频**、产品创作历程、**TRAE 实践过程**(开发流程说明、过程截图、对话记录、阶段成果) | 社区【复赛专区】 | **公开展示**(让社区看得到你做了什么、怎么用 TRAE 做出来的) |
| **作品体验入口**(体验链接 / 二维码 / 安装包 / 固件包，源码包为选交项)、测试账号与打开说明、硬件方案文档；以及说明书 / 演示视频的**同步存档** | **官方飞书问卷**(私密通道，评审打分以此为准) | **不公开，**仅评审在飞书查看;可下载的作品本体不进社区 |

> 🔒
> **为什么这样分?**  
> 若将可下载的源码包、安装包、体验文件整体公开发布到社区，作品存在被他人下载、复刻乃至抢先注册的风险；但若社区帖不允许展示任何内容，又会缺乏应有的展示价值。因此复赛将**「作品展示」与「作品本体交付」分开处理：**
> - 社区说明帖**用于充分展示：**产品说明书、产品演示视频、TRAE 实践过程、产品截图与核心亮点，清晰呈现你的作品成果与使用 TRAE 的开发过程;
> - 而**可下载、可复刻的作品本体（体验入口、源码包、安装包、固件包、测试账号）仅通过飞书问卷私密提交，**由评审在后台调阅评分，不在社区及任何公开页面展示，从机制上降低作品被抄袭、盗用的风险。

> 💡
> **复赛提交 = 两步，缺一不可:**
> 1. **第一步 ： 社区发帖(公开展示)，**在社区【复赛专区】发布「作品说明帖」，展示产品简介、演示视频、创作历程与 TRAE 实践过程，**不含可下载的源码 / 安装包 / 体验链接 / 二维码；**
> 2. **第二步： 填飞书问卷(私密提交)，**填写官方飞书问卷，提交作品交付物(体验入口、源码包、安装包等)与组队信息，仅评审可见。
> **只做第一步、未填问卷 = 未完成复赛提交，不进入评审；**问卷中需回填你的社区帖链接；因此请**先发帖、再填问卷**。

# 五、复赛组队规则

复赛起（7月21日）开放组队，便于选手在产品打磨、技术实现、设计、演示等环节分工协作。请仔细阅读以下规则，组队一经确认即生效，后续变更受时间窗口约束。

## 5.1 谁可以组队、队伍人数

- **组队人数：**每支队伍 **2–3 人**（含队长），不允许超过 3 人。单人也可继续以个人身份参赛，无需强制组队。
- **队长：**每队须指定 **1 名队长**，队长必须是该作品**初赛晋级作品的所属选手**。队长是队伍唯一的官方对接人，负责提交作品、接收通知、领取与分配奖励。
- **队员资格：**队员**无需在初赛阶段报名或参赛**——即使此前没有参加过报名/初赛，也可以作为队员加入复赛队伍。
- **作品归属：**每支队伍只能围绕 **1 个初赛晋级作品**组队参赛；一个晋级作品只能成立一支队伍。
- **不可重复参赛：**同一选手**不得同时加入多支队伍**，也不得既以个人身份、又以队员身份重复参赛同一作品；一经发现，主办方有权取消相关参赛资格。

## 5.2 组队确认时间（关键节点）

- 组队信息须在**复赛作品提交截止时间（2026 年 8 月 9 日 23:59）前**，通过飞书问卷一次性提交并确认；
- **组队信息以队长在飞书问卷中最终提交的版本为准**。截止时间后，队伍成员名单即**锁定**，不再接受新增、删除或替换成员；
- 若到截止时间仍未提交组队信息，则**视为该作品以队长个人身份参赛**，其他口头/私下约定的成员不予承认。

## 5.3 组队需提交哪些信息

组队信息在**复赛飞书问卷**中随作品一并提交（见 4.2），需包含：

1. **队伍名称**（队名）；
2. **队长信息：**社区昵称、TRAE UID、对应初赛晋级作品链接、联系方式（手机号 ）；
3. **全部队员名单：**每位成员的真实姓名、社区昵称、TRAE UID；
4. **成员分工：**简述每位成员在作品中的实际职责（如产品、开发、设计、测试、演示等）；
5. **全员同意确认：**队长须确认「全部成员均已知悉并同意以本队伍身份参赛，并同意本赛事规则」。

> 📌
> 为保证公平，**成员分工与实际贡献将作为决赛资格与奖励发放的核验依据之一**。
> - 复赛允许组队协作，也允许具备专业能力的新成员加入，但禁止任何形式的枪手代做、外包代做、买断作品、虚假挂名或由非登记成员完成核心作品。
> - 队长作为初赛晋级作品所属选手，须持续、实质性参与复赛迭代，并能够说明作品核心创意、主要技术方案、关键实现与 TRAE 使用过程。
> - 队伍需在提交时说明每位成员的具体分工与实际贡献，并提供可核验材料，包括但不限于 TRAE Session ID、关键开发截图、提交记录、设计文档、部署记录等。
> - 主办方有权在评审或决赛阶段对队长及成员进行答辩、随机提问或过程材料核验；若发现成员贡献不实、队长无法解释作品核心内容、作品主要由非登记人员完成，主办方有权降低评分、取消相关成员资格，情节严重的取消作品参赛或获奖资格。

## 5.4 组队后退赛怎么办

| **退赛情形** | **处理方式** |
|-|-|
| **个别队员退出（队长仍在、队伍仍≥2人）** | 在组队锁定前，队长可在飞书问卷中更新名单（见 5.5）；锁定后，队员退出不影响队伍继续参赛，但**该退出成员不再享有该作品的任何获奖与奖励权益**。 |
| **队长退赛** | 因队长须为初赛晋级作品所属选手、且为唯一官方对接人，**队长退赛原则上视为该队伍（该作品）整体退出复赛**。 |
| **全队退赛** | 由队长通过官方渠道提交退赛说明，该作品**放弃复赛资格，名额不顺延、不递补**。 |
| **奖励已部分发放后退赛** | 已发放的阶段性奖励（如复赛晋级奖）原则上不予追回，但**退赛后不再享有后续阶段（如决赛）的任何资格与奖励**。 |

## 5.5 组队后想变更成员怎么办

- **锁定前（截止时间 8 月 9 日 23:59 之前）：**队长可在飞书问卷中**自由更新**队伍成员（新增、删除、替换均可），以队长最终提交的版本为准，无需单独审批，但须保证人数始终在 1–3人范围内，且新增成员同意参赛。
- **锁定后（截止时间之后）：**原则上**不接受任何成员变更**（包括新增、删除、替换、调整分工）。仅在以下特殊情形下，由队长通过官方渠道申请、主办方个案核验后酌情处理：成员因不可抗力（如重大疾病、意外等）无法继续参与。即便如此，**也只做减员处理，不允许在锁定后新增任何此前未登记的成员**，以防止「临时拉人分奖」「借名替赛」等行为。
- **变更不得损害他人权益：**任何成员变更都不得违背已登记成员的意愿；如发生成员间纠纷，主办方不介入私下约定，仅以飞书问卷登记的最终名单为准。

> 💡
> **反作弊与边界说明：**
> - 一人一队、一作品一队，**严禁一人横跨多队**；
> - 锁定后**只减不增**，杜绝临时拉人分奖；
> - 成员须有**真实贡献**，挂名成员不予承认资格与奖励；
> - 队伍内部的奖励分配由队长与成员自行约定，**主办方仅向队长统一发放**，不介入队内分配纠纷；
> - 同一自然人通过多账号、多身份重复出现在不同队伍的，按同一用户处理并取消相关资格。

# 六、复赛评审标准

复赛全程采用专家**人工评审**。专业评审团基于飞书问卷提交的作品本体，按以下维度对每个作品综合打分，择优选出 **20 个作品**晋级决赛。复赛相比初赛，更侧重**产品的完整性与技术实现**。

## 6.1 通用赛道评分维度

| **维度** | **权重** | **说明** |
|-|-|-|
| 产品完成度 | 30% | 非硬件赛道评估作品的完整性  <br/>1. 功能完整：具备完整的用户使用路径，核心功能齐全，必要页面完备  <br/>2. 体验稳定：产品结构稳定可靠，无严重bug，核心流程可顺畅走通  <br/>**硬件赛道**评估硬件产品的完整性  <br/>1. 原型完成度：硬件原型已完成开发，功能完整，可稳定运行  <br/>2. 量产可行性：硬件设计考虑了量产需求  <br/>3. 可靠性：硬件产品经过基本的可靠性测试，满足日常使用要求 |
| 技术实现 | 30% | 非硬件赛道评估作品的技术方案质量  <br/>1. 交互友好：交互流程符合用户习惯，操作反馈及时明确  <br/>2. 运行稳定：系统运行稳定，能应对正常使用场景的并发需求  <br/>3. 技术方案：完整，架构设计合理  <br/>硬件赛道评估硬件赛道作品的工程实现质量与系统成熟度  <br/>1. **软硬件协同**：传感、控制、计算、反馈等关键环节是否联动顺畅，TRAE 能力是否真正嵌入设备使用链路  <br/>2. **稳定性与可靠性**：设备运行是否稳定，关键功能在连续运行、重复操作或典型场景下是否表现一致  <br/>3. **可验证性**：是否能通过演示视频、文档或测试结果清楚证明关键链路已经实现。 |
| 实用性 | 20% | 评估作品的实际使用价值  <br/>1. 场景成熟：作品所解决的问题是否真实存在且高频，目标用户是否明确具体  <br/>2. 解决效果：产品能否有效解决目标用户的问题，提升工作效率/生活便捷度/社会服务能力  <br/>3. 持续使用价值：产品是否具备用户粘性和持续使用价值，而非一次性工具 |
| 创新性 | 20% | 评估作品的创新程度  <br/>1. 需求创新：是否精准识别了工作/学习/生活/社会服务等真实场景中，长期存在但尚未被有效解决的用户需求  <br/>2. 解决思路：解决方案是否具有突破性，是否以不同于现有产品的方式回应了该需求  <br/>3. 技术创新：是否在 TRAE 能力运用上展现出独特思路 |

## 6.2 社会服务赛道评分维度（增加「社会价值」）

## 6.3 评审通用说明

- 复赛评审以**飞书问卷提交的作品（包括社区说明帖）**为准，评审通过后台调阅；

# 十、复赛常见问题（FAQ）

## Q：复赛要交的东西和初赛 Demo 有什么不一样？

A：初赛交的是「能跑、能展示核心想法」的 Demo；复赛交的是「功能完整、流程可跑通、体验稳定」的完整作品，并新增了产品说明书、完整演示视频和更完整的 TRAE 实践证明。详见第二部分对照表。请不要把初赛 Demo 原样再交一次。

## Q：我的作品是微信小程序 / App / 抖音小游戏 / 硬件，体验入口怎么交？

A：请对照第三部分「按作品形式，你该交什么」找到对应行。简单说：Web 交可访问链接；小程序交体验二维码；App 交安装包（APK / TestFlight）；抖音小程序/小游戏交体验二维码或测试链接；硬件交完整演示视频 ；硬件内嵌软件交源码/固件包 + 演示视频 + 交互链路说明。所有形式都**额外需要一段产品演示视频**作为兜底。

## Q：完整作品交到社区，会不会被别人抄走？

A：不会。复赛**不要求把完整作品公开发布到社区**。你只在社区发一篇「作品说明帖」展示截图、简介和亮点；**作品本体、体验入口、源码包、安装包等通过官方飞书问卷私密提交**，仅评审在飞书查看，不公开展示。这正是为保护你的作品不被抄袭、盗用而设计的双轨提交机制（详见第四部分）。

## Q：那评审到底看哪一份？社区帖还是飞书问卷？

A：**评审以飞书问卷提交的作品本体为准。**社区说明帖只用于公示与交流，不单独评分。只发社区帖、没提交飞书问卷的，视为未完成复赛提交，不进入评审。

## Q：复赛可以组队吗？最多几个人？

A：可以。复赛起支持组队，每队 **2–3 人**（含队长）。单人也可以继续以个人身份参赛。详见第五部分。

## Q：我朋友没参加报名 / 初赛，能加入我的复赛队伍吗？

A：可以。**队员无需在此前参加过报名或初赛**，只要使用 TRAE 即可加入。但**队长必须是该初赛晋级作品的所属选手**。

## Q：组队要在什么时候确认？之后还能改吗？

A：组队信息须在**复赛提交截止（8 月 9 日 23:59）前**通过飞书问卷提交并确认，以队长最终提交版本为准。**截止时间后名单锁定：**锁定前可自由增减/替换成员（保持 2–3 人）；锁定后原则上不接受任何成员变更，仅在不可抗力情形下经官方核验做**减员处理，不允许新增**。

## Q：组队后有人退赛 / 队长退赛怎么办？

A：个别队员退出不影响队伍继续参赛，但退出成员不再享有该作品的获奖权益；队长退赛原则上视为该作品整体退出复赛；全队退赛则该作品放弃复赛资格，名额不递补。详见 5.4。

## Q：组队后奖励发给谁？

A：组队作品的奖励**统一发放至队长**，队内分配由队伍自行约定，主办方不介入队内分配纠纷。

## Q：作品涉及登录 / 付费，评审打不开怎么办？

A：请务必在飞书问卷中**提供可用的测试账号 / 体验权限**，并保证所有链接、安装包、二维码在整个评审期内有效、可公开访问。体验入口失效、无法运行的，主办方有权要求补充材料、暂缓评审或降低晋级优先级。

## Q：复赛作品必须完全由 TRAE 开发吗？

A：是。复赛作品必须完全由 [TRAE IDE](https://www.trae.cn/ide/download) 或 [TRAE Work](https://www.trae.cn/ide/download) 开发，并需提供可证明开发过程真实性的材料(关键任务 Session ID 不少于 3 个、AI 对话记录、阶段成果截图等)。评审期内主办方将要求候选作品提供 Session ID 等信息核验原创性。

## Q：对复赛评审结果有异议怎么办？

A:可在结果公布后 **72 小时内，**通过官方邮箱 [feedback@mail.trae.cn](mailto:feedback@mail.trae.cn) 向总评审组提交申诉，并附社区账号、作品链接及具体问题说明，官方将在 **5 个工作日内**回复。申诉不受理范围:对评分标准的个人理解差异、超过时限的提交、缺乏具体证据的质疑。
