## 1. 逻辑模型设计方法

### 1.1 设计方法

将 [doc 25 概念模型](file:///d:/Project/database-class/moment-campus/docs/25_数据库概念模型设计.md) 中的 E-R 图转换为**关系模型**（数据库模式），步骤如下：

1. 实体 → 关系（表）
2. 1:N 联系 → 在 N 端添加外键
3. M:N 联系 → 新建关联表
4. 自引用 → 在自身表中添加外键
5. 规范化至 3NF

### 1.2 设计原则

- 所有关系满足 **第三范式（3NF）**：消除传递依赖
- 主键统一为 `id`（BigInteger，自增）
- 外键命名规范：`<被引用实体>_id`
- 软删除：`is_deleted` + `deleted_at`
- 时间戳：`created_at` + `updated_at`
- 状态字段：`status`（String）

### 2.3 关系模式统计

| 统计项 | 数量 |
| ------ | ---- |
| 关系模式（表）总数 | 21 |
| 主键总数 | 21（全部为 id） |
| 外键总数 | 35 |
| 唯一约束 | 8（email, school.code, category.code, tag.name, tag.slug, post_tags(post_id,tag_id), likes(post_id,user_id), favorites(post_id,user_id) 等） |
| 软删除字段表数 | 12 |

### 2.4 规范化分析

| 关系模式 | 1NF | 2NF | 3NF | 说明 |
| -------- | --- | --- | --- | ---- |
| schools | ✓ | ✓ | ✓ | 无传递依赖 |
| users | ✓ | ✓ | ✓ | school_id 为外键，无传递依赖 |
| posts | ✓ | ✓ | ✓ | 所有非主属性只依赖于主键 |
| comments | ✓ | ✓ | ✓ | parent_id 自引用，无传递依赖 |
| ... | ✓ | ✓ | ✓ | 全部满足 3NF |

**结论**：所有关系模式均满足第三范式（3NF），无冗余、无传递依赖。

## 3. 视图设计

### 3.1 视图设计原则

- 视图面向**不同用户角色**，提供不同数据视角
- 视图隐藏底层表结构复杂性，简化查询
- 视图实现**数据安全**：限制用户只能看到其权限范围内的数据
- 视图实现**数据聚合**：预计算统计数据

### 3.3 视图 SQL 定义（openGauss 语法）

#### 3.3.1 V01 v_published_posts（已发布信息视图）

```sql
CREATE OR REPLACE VIEW v_published_posts AS
SELECT
    p.id,
    p.title,
    p.content,
    p.is_anonymous,
    p.status,
    p.credibility_score,
    p.view_count,
    p.like_count,
    p.comment_count,
    p.favorite_count,
    p.valid_count,
    p.invalid_count,
    p.expire_at,
    p.is_top,
    p.is_recommend,
    p.created_at,
    p.updated_at,
    u.nickname AS author_nickname,
    u.avatar_url AS author_avatar,
    CASE WHEN p.is_anonymous = TRUE THEN NULL ELSE u.id END AS author_id,
    c.name AS category_name,
    c.icon AS category_icon,
    pt.name AS post_type_name,
    l.name AS location_name,
    l.latitude AS location_lat,
    l.longitude AS location_lng,
    s.name AS school_name
FROM posts p
    INNER JOIN users u ON p.user_id = u.id
```

## 4. 完整性约束

### 4.1 实体完整性

- 所有表的主键 `id` 非空且唯一（PRIMARY KEY 约束）
- 自增字段使用 `AUTOINCREMENT`

### 4.2 参照完整性

- 所有外键必须有对应的主键记录（FOREIGN KEY 约束）
- 删除策略：`ON DELETE RESTRICT`（默认，禁止删除被引用的记录）
- 建议在应用层实现软删除，而非物理删除

### 4.3 用户定义完整性

| 表 | 字段 | 约束 | 说明 |
| -- | ---- | ---- | ---- |
| users | email | UNIQUE, NOT NULL | 邮箱唯一 |
| users | role | IN ('user', 'admin', 'super_admin') | 角色枚举 |
| schools | code | UNIQUE, NOT NULL | 学校代码唯一 |
| categories | code | UNIQUE, NOT NULL | 分类代码唯一 |
| tags | name, slug | UNIQUE | 标签名与slug唯一 |
| posts | status | IN ('draft', 'pending_review', 'published', 'expired', 'conflict', 'archived') | 状态枚举 |
| posts | credibility_score | BETWEEN 0 AND 100 | 可信度范围 |
| likes | (post_id, user_id) | UNIQUE | 每人每条只能赞一次 |
| favorites | (post_id, user_id) | UNIQUE | 每人每条只能收藏一次 |
| post_tags | (post_id, tag_id) | UNIQUE | 标签不重复 |
| locations | latitude | BETWEEN -90 AND 90 | 纬度范围 |

| validation_records | validation_type | IN ('confirmation', 'refutation', 'update', 'expiration_report', 'conflict_report') | 验证类型枚举 |
| reports | report_type | IN ('spam', 'illegal', 'inaccurate', 'infringement', 'other') | 举报类型枚举 |
