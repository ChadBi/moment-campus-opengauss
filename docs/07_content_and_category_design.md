# 内容与分类设计

> 此刻校园 · Moment Campus  
> 版本：1.0  
> 最后更新：2026-06-18

## 1. 概述

本文档描述"此刻校园"平台的内容分类体系、字段设计、标签体系和有效期规则。平台通过 5 个核心分类组织校园信息，每个分类具有通用字段和特有字段，支持灵活的标签系统和有效期管理。

---

## 2. 核心分类详细设计

### 2.1 分类概览

| 编号 | 分类名称 | Code | 图标 | 描述 | 默认有效期 |
|------|----------|------|------|------|------------|
| C01 | 分享吐槽 | share | 💬 | 校园生活分享、吐槽、心得 | 30天 |
| C02 | 组队交友 | teamup | 🤝 | 组队、交友、活动搭子 | 30天 |
| C03 | 二手交易 | trade | 💰 | 二手物品买卖、赠予 | 30天 |
| C04 | 失物招领 | lost_found | 🔍 | 丢失与拾到物品信息 | 30天 |
| C05 | 其他 | other | 📝 | 其他校园信息 | 30天 |

---

### 2.2 分类详细设计

#### C01：分享吐槽（share）

**分类描述：** 分享校园生活点滴、学习心得、美食推荐、生活吐槽、心情感悟等。覆盖原美食推荐、校园动物、拍照地点、学习空间等细分场景。

**特有字段：**

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| share_type | 枚举 | 是 | 分享类型：生活分享、美食推荐、学习心得、吐槽、心情、其他 |
| mood_tags | 多选枚举 | 否 | 心情标签：开心、感慨、求助、推荐、吐槽、搞笑 |
| related_location | 文本 | 否 | 相关地点描述 |
| has_images | 布尔 | 否 | 是否包含图片 |

**有效期特点：** 默认 30 天。

**交互差异：** 
- 支持"同感"快捷反馈
- 图片内容优先展示
- 心情标签用颜色区分

**展示重点：** 
- 图文并茂展示
- 心情标签醒目展示
- 相关地点在地图上标记

---

#### C02：组队交友（teamup）

**分类描述：** 发布组队邀请、交友信息、活动搭子寻找等。覆盖原校园活动、学习组队等场景。

**特有字段：**

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| teamup_type | 枚举 | 是 | 类型：学习组队、运动搭子、活动参加、社团招新、技能交换、其他 |
| member_count | 数字 | 否 | 需要人数（含自己） |
| target_time | 文本 | 否 | 目标时间段 |
| location_desc | 文本 | 否 | 活动/见面地点 |
| contact_preference | 枚举 | 否 | 联系方式偏好：私信、微信、QQ |

**有效期特点：** 默认 30 天。组队信息有明确目标，到期自动降低展示权重。

**交互差异：** 
- 支持"加入"快捷按钮
- 剩余名额动态显示
- 组队成功后可标记

**展示重点：** 
- 类型标签醒目展示
- 剩余名额突出显示
- 地点信息在地图上标记

---

#### C03：二手交易（trade）

**分类描述：** 发布二手物品买卖、闲置物品赠予、物品求购等信息。

**特有字段：**

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| trade_type | 枚举 | 是 | 交易类型：出售、求购、免费赠送、交换 |
| item_category | 枚举 | 是 | 物品类别：书籍教材、电子数码、生活用品、服饰、运动器材、其他 |
| price | 数字 | 否 | 价格（元），免费赠送时为 0 |
| condition | 枚举 | 否 | 成色：全新、几乎全新、轻微使用痕迹、明显使用痕迹 |
| trade_method | 多选枚举 | 是 | 交易方式：面交、邮寄、自取 |
| meeting_location | 文本 | 否 | 面交地点 |

**有效期特点：** 默认 30 天。交易信息时效性强，成交后应标记为已售出。

**交互差异：** 
- 价格用大字体突出显示
- 支持"想要"快捷按钮
- 成交后可标记为"已售出"

**展示重点：** 
- 价格信息醒目展示
- 成色用标签清晰展示
- 物品照片优先展示

---

#### C04：失物招领（lost_found）

**分类描述：** 发布丢失物品或拾到物品的信息，帮助校园成员找回失物。

**特有字段：**

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| lost_type | 枚举 | 是 | 类型：失物（我丢了）、招领（我捡到了） |
| item_category | 枚举 | 是 | 物品类别：证件、电子产品、书籍、衣物、钥匙、其他 |
| item_description | 文本 | 是 | 物品详细描述 |
| event_time | 日期时间 | 否 | 丢失/拾到时间 |
| contact_method | 枚举 | 是 | 联系方式类型：私信、电话、微信 |
| contact_info | 文本 | 是 | 联系方式（根据类型填写） |

**有效期特点：** 默认 30 天。失物招领信息时效性强，过期后自动降低展示权重。

**交互差异：** 
- 类型（失物/招领）用不同颜色标签区分
- 支持"我见到了"快捷反馈
- 联系方式默认隐藏，点击显示
- 物品找到后可标记为"已找回"

**展示重点：** 
- 类型标签醒目（红色=失物，绿色=招领）
- 物品照片优先展示
- 联系方式在安全提示后显示

---

#### C05：其他（other）

**分类描述：** 不属于以上 4 个分类的其他校园信息。包括临时提醒、便民服务、通知公告等。

**特有字段：** 无特有字段，仅使用通用字段。

**有效期特点：** 默认 30 天。

**交互差异：** 无特殊交互。

**展示重点：** 标准卡片展示。

---

## 3. 通用字段设计

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| id | UUID | 自动 | 信息唯一标识 |

| images | 图片数组 | 否 | 图片列表，最多9张 |
| validity_type | 枚举 | 否 | 有效期类型：永久、短期、自定义 |

| validity_status | 枚举 | 自动 | 有效性状态：有效、可能过期、已过期、不确定 |
| author_id | UUID | 自动 | 发布者ID |

| created_at | 日期时间 | 自动 | 创建时间 |

| like_count | 数字 | 自动 | 点赞数 |

## 4. 标签体系

### 4.1 系统预设标签

每个分类提供一组系统预设标签，用户发布时可快速选择：

| 分类 | 预设标签 |
|------|----------|
| 分享吐槽 | 分享、吐槽、心得、推荐、搞笑、日常、美食、学习、生活 |
| 组队交友 | 组队、搭子、交友、学习、运动、活动、社团、招募 |
| 二手交易 | 全新、便宜、急售、免费赠送、包邮、可议价、出售、求购 |
| 失物招领 | 紧急、重要证件、电子产品、已找到、求助 |
| 其他 | 推荐、重要、紧急、临时、通知、公告 |

### 4.2 用户自定义标签

用户可以创建自定义标签，规则如下：

- 标签长度：2-20字符
- 每条信息最多5个标签（系统+自定义总计）
- 标签不能包含特殊字符（如#、@、&等）
- 标签不能重复
- 自定义标签会被系统记录，高频使用的标签可被推荐

### 4.3 标签使用规则

1. **发布时添加标签：**
   - 优先展示系统预设标签
   - 支持搜索预设标签
   - 支持输入自定义标签
   - 已选标签可删除

2. **浏览时筛选标签：**
   - 支持按标签筛选信息
   - 支持多标签组合筛选
   - 热门标签优先展示

3. **标签管理：**
   - 管理员可添加/修改/删除系统预设标签
   - 高频自定义标签可被提升为系统标签
   - 标签使用次数统计

## 5. 有效期规则

### 5.1 有效期类型

| 类型 | 说明 | 适用场景 |
|------|------|----------|
| 短期-7天 | 7天后过期 | 临时提醒、紧急信息 |
| 短期-30天 | 30天后过期 | 分享吐槽、组队交友、二手交易、失物招领、其他 |
| 自定义日期 | 用户指定具体过期日期 | 有时限的活动信息等 |

### 5.2 各分类默认有效期建议

| 分类 | 默认有效期 | 说明 |
|------|------------|------|
| 分享吐槽 | 30天 | 生活分享类信息有效期30天 |
| 组队交友 | 30天 | 组队交友信息时效性强 |
| 二手交易 | 30天 | 交易信息时效性强 |
| 失物招领 | 30天 | 时效性强，过期后降低权重 |
| 其他 | 30天 | 一般信息默认30天 |

### 5.3 过期处理规则

**过期前提醒：**

- 过期前7天：通知发布者"您的信息即将过期，是否延长有效期？"
- 过期前1天：再次提醒发布者

**过期后处理：**

1. **状态变更：** 信息状态从"有效"变为"可能过期"
2. **展示调整：** 
   - 信息仍可在详情页查看
   - 在列表中的展示权重降低
   - 显示"可能过期"黄色标识
3. **用户确认：** 
   - 其他用户可确认"仍然有效"或"已经失效"
   - 如3人以上确认"仍然有效"，状态恢复为"有效"
   - 如3人以上确认"已经失效"，状态变为"已过期"
4. **管理员处理：** 
   - 管理员可查看可能过期的信息列表
   - 管理员可手动延长有效期、标记过期或隐藏信息

**已过期信息处理：**

- 显示"已过期"红色标识
- 在搜索结果中排名靠后
- 不在首页信息流中展示
- 保留90天后自动隐藏（可配置）

## 6. 分类体系说明

### 6.1 分类（Category）概念

**分类（Category）** 是平台唯一的信息分类维度，用于组织信息的内容主题：

| 维度 | 说明 |
|------|------|
| **定义** | 信息的内容主题划分 |
| **作用** | 组织信息内容，便于用户按主题浏览和筛选 |
| **数量** | 5 个固定分类 |
| **变更频率** | 相对稳定，每所学校可独立配置 |
| **用户感知** | 用户可见，用于筛选和浏览 |

### 6.2 分类的使用场景

- 用户按主题浏览信息
- 发布时选择信息主题
- 搜索时按分类筛选
- 统计各分类信息数量
- 管理员配置分类和预设标签
