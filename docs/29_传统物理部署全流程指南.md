## 1. 架构说明

传统物理部署架构（所有组件直接安装在服务器上）：

```
                    用户浏览器
                        │
                        ▼
                ┌───────────────┐
                │     Nginx     │ ← 80/443端口，SSL终结，静态文件服务
                └───────┬───────┘
                        │
            ┌───────────┴───────────┐
            │  /api/ 反代           │  静态文件
            ▼                       ▼
    ┌───────────────┐       ┌───────────────┐
    │  FastAPI      │       │  前端dist/    │
    │  (uvicorn)    │       │  (静态文件)   │
    │  :8000        │       └───────────────┘
    └───────┬───────┘
            │ 数据库连接
            ▼
    ┌───────────────┐
    │  openGauss    │ ← :5432
    └───────────────┘
```

**进程管理**：使用 systemd 管理后端服务，开机自启，崩溃自动重启。

## 2. 准备工作

### 2.1 服务器要求

| 配置 | 最低要求 | 推荐配置 |
|---|---|---|
| CPU | 2核 | 2核+ |
| 内存 | 4GB | 4GB+ |
| 系统盘 | 40GB | 40GB+ |
| 操作系统 | Ubuntu 22.04 LTS | Ubuntu 22.04 LTS |
| 网络 | 公网IP | 固定公网IP |

### 2.2 域名准备（可选但推荐）

1. 购买域名（阿里云/腾讯云/Namesilo等）
2. **域名备案**（国内服务器必须，否则80/443端口无法访问）
3. 添加A记录解析到服务器公网IP

**临时方案**：如果只是课程演示，也可以直接用服务器IP访问，不需要域名和HTTPS。

### 2.3 云服务器安全组/防火墙

在云服务商控制台放行以下端口：
- **22**：SSH（必须）
- **80**：HTTP（必须）
- **443**：HTTPS（有域名时）

Ubuntu UFW防火墙配置（登录服务器后执行）：
```bash
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw --force enable
```

## 3. 安装 openGauss 数据库

openGauss 物理安装比Docker稍微复杂一点，按以下步骤操作：

### 3.1 下载 openGauss

在**本地电脑**下载 openGauss 7.0.0-RC3 轻量版：
- 官网：https://opengauss.org/zh/download/
- 选择：**轻量版**，架构选 **x86_64**（大多数云服务器）或 **ARM**（如鲲鹏/ARM服务器）
- 文件类似：`openGauss-Lite-7.0.0-RC3-x86_64.tar.gz`

### 3.2 上传到服务器

使用 FinalShell/WinSCP/scp 将下载的压缩包上传到服务器的 `/opt/` 目录。

使用 scp 示例（本地终端执行）：
```bash
scp openGauss-Lite-7.0.0-RC3-x86_64.tar.gz root@你的服务器IP:/opt/
```

### 3.3 安装 openGauss

SSH 连接到服务器后执行：

```bash
# 切换到/opt目录
cd /opt

# 解压
tar -zxvf openGauss-Lite-7.0.0-RC3-x86_64.tar.gz
cd openGauss-Lite-7.0.0-RC3  # 目录名根据实际解压结果调整

# 安装依赖
apt update
apt install -y libreadline-dev zlib1g-dev libssl-dev libnsl2

# 以root执行安装（轻量版简易安装）
# 注意：设置密码为 Gaussdb@123（与项目默认配置一致）
./install.sh -w Gaussdb@123
```

安装脚本会自动完成：
- 创建 `omm` 用户（数据库管理员）
- 初始化数据库
- 启动数据库服务
- 创建默认用户 `gaussdb`

### 3.4 创建项目数据库

切换到 omm 用户，创建数据库和用户：

```bash
# 切换到omm用户
su - omm

# 连接数据库
gsql -d postgres -p 5432
```

在 gsql 命令行中执行（注意密码是 Gaussdb@123）：

```sql
-- 创建用户（如果不存在）
CREATE USER gaussdb WITH PASSWORD 'Gaussdb@123';

-- 创建数据库
CREATE DATABASE moment_campus OWNER gaussdb;

-- 授权
GRANT ALL PRIVILEGES ON DATABASE moment_campus TO gaussdb;

-- 退出
\q
```

退出 omm 用户回到 root：
```bash
exit
```

### 3.5 配置数据库允许本地连接

```bash
# 找到pg_hba.conf文件（路径可能因安装方式不同略有差异）
find /opt -name "pg_hba.conf" 2>/dev/null
```

通常在类似 `/opt/openGauss-Lite-xxx/data/pg_hba.conf` 路径，编辑它：

```bash
vim /opt/openGauss-Lite-7.0.0-RC3/data/pg_hba.conf   # 替换为实际路径
```

确保有以下两行（允许本地MD5密码认证）：
```
host    all             all             127.0.0.1/32            md5
host    all             all             ::1/128                 md5
```

重启数据库：
```bash
su - omm -c "gs_ctl restart -D /opt/openGauss-Lite-7.0.0-RC3/data"
```

### 3.6 设置 openGauss 开机自启

创建 systemd 服务文件：

```bash
cat > /etc/systemd/system/opengauss.service << 'EOF'
[Unit]
Description=openGauss Database
After=network.target

[Service]
Type=forking
User=omm
Group=omm
Environment="GAUSSHOME=/opt/openGauss-Lite-7.0.0-RC3"
Environment="PGDATA=/opt/openGauss-Lite-7.0.0-RC3/data"
ExecStart=/opt/openGauss-Lite-7.0.0-RC3/bin/gs_ctl start -D /opt/openGauss-Lite-7.0.0-RC3/data
ExecStop=/opt/openGauss-Lite-7.0.0-RC3/bin/gs_ctl stop -D /opt/openGauss-Lite-7.0.0-RC3/data
ExecReload=/opt/openGauss-Lite-7.0.0-RC3/bin/gs_ctl reload -D /opt/openGauss-Lite-7.0.0-RC3/data
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF

# 注意：路径要根据你实际解压的openGauss目录调整！

systemctl daemon-reload
systemctl enable opengauss
systemctl start opengauss
```

**验证数据库连接**：
```bash
# 测试能否用gaussdb用户连接
PGPASSWORD=Gaussdb@123 psql -h 127.0.0.1 -U gaussdb -d moment_campus -c "SELECT version();"
```

> ⚠️ **重要提示**：如果你觉得安装openGauss太麻烦，只是为了课程演示，可以参考第9节使用PostgreSQL替代，安装更简单。

## 6. 验证部署

### 6.1 检查服务状态

```bash
# 检查后端服务
systemctl status moment-backend

# 检查Nginx
systemctl status nginx

# 检查openGauss（如果配置了systemd）
systemctl status opengauss
```

所有服务都应该显示 `active (running)`。

### 6.2 检查后端日志

```bash
journalctl -u moment-backend -f
```

看到 `Application startup complete` 表示后端启动成功。按 `Ctrl+C` 退出日志查看。

### 6.3 测试API健康检查

```bash
# 本地测试
curl http://127.0.0.1:8000/health

# 通过Nginx测试（HTTP）
curl http://你的域名/health

# 通过Nginx测试（HTTPS，如果配置了）
curl https://你的域名/health
```

应该返回 `{"status":"ok"}`。

打开浏览器访问：
- HTTP：`http://你的域名` 或 `http://服务器IP`

## 7. 日常运维

### 7.1 常用命令

**查看后端日志：**
```bash
journalctl -u moment-backend -f                    # 实时查看
journalctl -u moment-backend --since "1 hour ago"  # 最近1小时
journalctl -u moment-backend -n 100                # 最近100行
```

**重启服务：**
```bash
systemctl restart moment-backend    # 重启后端
systemctl restart nginx             # 重启Nginx
systemctl restart opengauss         # 重启数据库
```

**停止/启动服务：**
```bash
systemctl stop moment-backend
systemctl start moment-backend
```

**查看配置是否有误：**
```bash
nginx -t                            # 检查Nginx配置
```

### 7.2 更新代码部署

当代码有更新时：

```bash
cd /opt/moment-campus/deploy/bare-metal
sudo bash update.sh
```

脚本会自动：
1. git pull拉取最新代码
2. 更新Python依赖
3. 执行数据库迁移
4. 重新构建前端
5. 重启服务

### 7.3 备份数据库

**手动备份：**
```bash
su - omm -c "gs_dump -U gaussdb -W'Gaussdb@123' moment_campus -F c -f /tmp/moment_backup.dump"
# 将备份文件复制到安全位置
cp /tmp/moment_backup.dump /opt/backup_$(date +%Y%m%d).dump
```

**设置定时备份（每天凌晨2点）：**
```bash
crontab -e
```

添加一行：
```
0 2 * * * su - omm -c "gs_dump -U gaussdb -W'Gaussdb@123' moment_campus -F c -f /opt/moment_backup_$(date +\%Y\%m\%d).dump"
```

### 7.4 更新SSL证书

Let's Encrypt证书有效期90天，certbot会自动续期（通过systemd timer）。

手动检查续期：
```bash
certbot renew --dry-run
```

## 8. 常见问题

### Q1: 后端启动失败，日志提示数据库连接错误

**原因：** openGauss没启动、密码不对、或pg_hba.conf没配置好。

**排查：**
```bash
# 检查openGauss状态
systemctl status opengauss
# 或
su - omm -c "gs_ctl query -D /opt/openGauss-Lite-7.0.0-RC3/data"

# 手动测试连接
PGPASSWORD=Gaussdb@123 psql -h 127.0.0.1 -U gaussdb -d moment_campus
```

**检查 `/opt/moment-campus/backend/.env.prod` 中的DATABASE_URL密码是否正确。**

### Q2: Nginx 502 Bad Gateway

**原因：** 后端服务没启动或启动失败。

**排查：**
```bash
systemctl status moment-backend
journalctl -u moment-backend -n 50  # 看最后50行日志
```

### Q3: 前端页面能打开但API请求失败

**原因：** Nginx配置问题或后端没起来。

**排查：**
1. 先访问 `http://服务器IP:8000/docs` 看后端是否直接响应
2. 检查Nginx配置中 `proxy_pass http://127.0.0.1:8000;` 是否正确
3. 检查后端是否监听在 `127.0.0.1:8000`（不是0.0.0.0也没关系，因为Nginx在同一台机器）

### Q4: 静态文件404或刷新页面404

**原因：** Nginx没有配置SPA路由回退。

**检查** `/etc/nginx/sites-available/moment` 中有这行：
```nginx
location / {
    try_files $uri $uri/ /index.html;
}
```

修改后重启Nginx：
```bash
nginx -t && systemctl restart nginx
```

### Q5: npm install 很慢或失败

**解决：** 使用淘宝npm镜像：
```bash
cd /opt/moment-campus/frontend
npm config set registry https://registry.npmmirror.com
rm -rf node_modules package-lock.json
npm install
```

### Q6: pip install 很慢或失败

**解决：** 使用清华PyPI镜像：
```bash
cd /opt/moment-campus/backend
source .venv/bin/activate
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
pip install -r requirements.txt
```

### Q7: 上传的图片无法访问

**检查：**
1. `/opt/moment-campus/backend/uploads/` 目录权限正确（moment用户可写）
2. Nginx配置中有 `/uploads/` 的location反代配置

```bash
chown -R moment:moment /opt/moment-campus/backend/uploads
```

### Q8: 忘记管理员密码

重置为 `pass123`：

```bash
cd /opt/moment-campus/backend
source .venv/bin/activate
python3 -c "
import asyncio
from app.database import AsyncSessionLocal
from app.models import User
from app.core.security import get_password_hash

async def reset():
    async with AsyncSessionLocal() as db:
        user = await db.get(User, 1)
        if user:
            user.hashed_password = get_password_hash('pass123')
            await db.commit()
            print('密码已重置为: pass123')
asyncio.run(reset())
"
systemctl restart moment-backend
```

### Q9: 修改域名/重新配置HTTPS

```bash
# 编辑Nginx配置
vim /etc/nginx/sites-available/moment

# 替换域名后，重新申请证书
certbot --nginx -d 新域名

# 重启Nginx
systemctl restart nginx
```

## 9. 备选：使用 PostgreSQL 替代 openGauss

> ⚠️ **注意**：课程设计要求使用openGauss时请不要用这个方案！
> 但如果只是演示功能，PostgreSQL 14+ 兼容 openGauss 协议（asyncpg可以直接连接），且安装更简单。

### 9.1 安装 PostgreSQL

```bash
apt install -y postgresql postgresql-contrib
systemctl enable postgresql
systemctl start postgresql
```

### 9.2 创建数据库和用户

```bash
su - postgres
psql
```

在psql中执行：
```sql
CREATE USER gaussdb WITH PASSWORD 'Gaussdb@123';
CREATE DATABASE moment_campus OWNER gaussdb;
GRANT ALL PRIVILEGES ON DATABASE moment_campus TO gaussdb;
\q
exit
```

### 9.3 修改后端配置

编辑 `/opt/moment-campus/backend/.env.prod`：

```ini
# 注意：PostgreSQL默认端口也是5432，连接串基本一样
DATABASE_URL=postgresql+asyncpg://gaussdb:Gaussdb%40123@127.0.0.1:5432/moment_campus
```

然后重启后端：
```bash
systemctl restart moment-backend
```

> **注意**：openGauss的一些物理模型特性（表空间、分区表、存储过程等）在PostgreSQL上可能不兼容，但基础功能（用户、帖子、评论、点赞、搜索等）都能正常运行，足够课程演示使用。
