# 专题与用量说明长期维护规范

> 本规范建立「专题内容（TopicCollection）」与「用量说明（UsagePage）」的长期维护机制，
> 确保演示数据新鲜、说明文案准确、维护责任清晰、更新周期可预期。

## 1. 维护目标

| 维护对象 | 位置 | 目标 |
| --- | --- | --- |
| 专题内容（TopicCollection） | `backend/scripts/seed_data.py` 中 `*_TOPICS` + 前端 `TopicListPage` / `TopicDetailPage` | 保证三校每校≥3 个专题、每个专题 3-5 篇精选帖子、封面/描述与季节/学期节奏匹配 |
| 用量说明（UsagePage） | `frontend/src/pages/admin/UsagePage.tsx` + `backend/app/api/admin.py` 用量接口 | 套餐档位说明、额度字段、stat_basis 文案与后端 `ProductPlan` / `PlanEntitlement` 表保持一致 |
| 专题封面图 | `topic_collections.cover_url` | 演示场景可为 null；上线前需补齐封面图 URL，统一走 `/uploads/` 路径 |

## 2. 维护角色与责任

| 角色 | 专题责任 | 用量说明责任 |
| --- | --- | --- |
| 内容运营（admin） | 通过 `/admin/topics` 创建/排序/归档专题；每周巡检过期帖子 | 通过 `/admin/usage` 查看本校用量；月度对账 |
| 平台运营（super_admin） | 跨校专题模板下发；季度评估专题活跃度 | 套餐档位调整、`ProductPlan` 表维护、stat_basis 文案更新 |
| 开发 | `seed_data.py` 专题数据结构维护；`TopicListPage` UI 适配 | `UsagePage.tsx` 文案维护；`PlanEntitlement` key 与前端字段映射维护 |

## 3. 更新周期

### 3.1 专题内容更新（按学期节奏）

| 时间点 | 更新动作 | 责任人 |
| --- | --- | --- |
| 每学期开学前 1 周 | 上线「新生入学指南」专题；归档上学期过期专题 | admin |
| 每月 1 日 | 巡检专题内帖子状态，移除 `expired/archived` 帖子，补充新 `published` 帖子 | admin |
| 每学期末 | 上线「期末复习资源合集」专题；评估专题 `view_count` 调整 `sort_order` | admin |
| 节假日（国庆/寒假/暑假） | 上线节日主题专题（如「寒假留校指南」） | admin |
| 每季度末 | 平台运营评估三校专题覆盖率，必要时下发专题模板 | super_admin |

### 3.2 用量说明更新（按版本节奏）

| 触发条件 | 更新动作 | 责任人 |
| --- | --- | --- |
| `ProductPlan` 表新增/调整套餐档位 | 同步更新 `UsagePage.tsx` 套餐卡片展示 + `seed_data.py` 中 `PLANS_DATA` | 开发 |
| `PlanEntitlement` key 新增 | 同步更新 `UsagePage.tsx` 额度项渲染 + `analytics_service.py` 用量统计 | 开发 |
| stat_basis 文案调整 | 同步更新 `UsagePage.tsx` 副标题文案 + 后端 `admin.py` 用量接口返回值 | 开发 |
| 每次发版前 | 验证三校 `operations` 档订阅状态为 `active`，用量数据可正常加载 | 开发 |

## 4. 维护流程

### 4.1 专题内容维护流程

```
1. admin 登录 → /admin/topics → 查看专题列表
2. 对过期专题点击「归档」（status: published → archived）
3. 点击「新建专题」→ 填写标题/描述/封面 → 选择 3-5 篇 published 帖子 → 发布
4. 调整 sort_order（重要专题置顶）
5. 在 seed_data.py 中同步新增对应专题数据（保证重跑种子脚本后演示数据一致）
6. 提交 git，commit message: "chore(topics): 更新 XX 学校专题内容"
```

### 4.2 用量说明维护流程

```
1. 修改 backend/app/models/product_plan.py 或 plan_entitlement.py（如需新增字段）
2. 创建 alembic 迁移：alembic revision --autogenerate -m "update plan entitlements"
3. 同步修改 seed_data.py 中 PLANS_DATA
4. 同步修改 frontend/src/pages/admin/UsagePage.tsx 渲染逻辑
5. 同步修改 backend/app/services/analytics_service.py 用量统计（如涉及）
6. 运行 alembic upgrade head + python scripts/seed_data.py 验证
7. 前端 npm run build 验证 TS 编译通过
8. 提交 git，commit message: "feat(usage): 新增 XX 套餐档位/额度项"
```

## 5. 质量检查清单

### 5.1 专题质量检查（每月执行）

- [ ] 三校每校至少 3 个 `published` 状态专题
- [ ] 每个专题至少 3 篇 `published` 状态帖子
- [ ] 专题 `sort_order` 无重复
- [ ] 专题标题与学期节奏匹配（开学/期末/节日）
- [ ] `post_count` 字段与实际 `topic_collection_posts` 记录数一致
- [ ] 前端 `TopicListPage` 列表渲染正常，无空封面占位

### 5.2 用量说明质量检查（每次发版执行）

- [ ] `UsagePage.tsx` 展示的套餐档位与 `ProductPlan` 表一致
- [ ] `UsagePage.tsx` 展示的额度项与 `PlanEntitlement.key` 一致
- [ ] `stat_basis` 文案与后端返回值一致
- [ ] 三校订阅状态均为 `active`，套餐为 `operations`
- [ ] 用量数据接口 `/admin/usage` 返回 200，无 500 错误
- [ ] 用量进度条渲染正常（未超限时绿色，超限时红色）

## 6. 演示数据维护约定

为保证竞赛演示效果，`seed_data.py` 中的专题与套餐数据需遵循：

| 约定 | 说明 |
| --- | --- |
| 江南大学专题数 ≥ 6 | 主展示校，覆盖新生/美食/期末/生态/社团/生活 6 个主题 |
| 复旦/浙大专题数 ≥ 3 | 复赛演示校，覆盖新生/美食/学习 3 个主题 |
| 三校套餐统一 `operations` | 演示档为运营档，避免额度限制影响演示 |
| 专题帖子覆盖 5 类分类 | share/teamup/trade/lost_found/other 均有专题覆盖 |
| 跨校专题命名差异化 | 避免三校专题标题完全相同，体现多租户差异化 |

## 7. 文档与代码同步要求

修改专题或用量说明时，需同步更新以下文件：

| 修改场景 | 需同步文件 |
| --- | --- |
| 新增专题 | `seed_data.py` + 前端 `TopicListPage.tsx`（如需新 UI） |
| 调整套餐档位 | `seed_data.py` PLANS_DATA + `UsagePage.tsx` + `product_plan.py` + alembic 迁移 |
| 调整额度 key | `plan_entitlement.py` + `UsagePage.tsx` + `analytics_service.py` + alembic 迁移 |
| 调整 stat_basis 文案 | `UsagePage.tsx` 副标题 + `admin.py` 用量接口 + `analytics_service.py` |

## 8. 回滚机制

- 专题误删：通过 `seed_data.py` 重跑恢复（前提：未提交 git 的专题数据丢失前已记录在 seed_data.py）
- 套餐误改：通过 `alembic downgrade -1` 回滚迁移
- 用量说明误改：通过 `git revert` 回滚 `UsagePage.tsx` 改动

## 9. 维护记录

每次维护后，在 `AIwork/` 目录新增维护报告，记录：
- 维护时间、维护人、维护对象
- 变更内容（新增/修改/删除）
- 影响范围
- 验证结果
