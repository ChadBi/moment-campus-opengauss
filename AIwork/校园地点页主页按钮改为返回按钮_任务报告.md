# 任务报告：校园地点页主页按钮改为返回按钮

## 1. 任务概述

用户反馈："这个页面加个返回按钮而不是主页按钮"，附截图显示小程序校园地点页（`subpackages/pages/locations/locations`）左上角是**🏠主页图标**（圆形灰底、房子形状），而不是习惯的"← 返回"箭头。

目标：无论用户从首页/地图页 navigateTo 进入，还是从分享卡片、扫码、系统菜单等**栈空入口**进入，左上角始终显示语义统一的"← 返回"按钮，不再显示🏠主页图标。

## 2. 已完成内容

### 2.1 根因定位：系统原生🏠不可配置

经 `locations.json` 检查 + 经验库 ID 310587 经验确认：

- 原页面 `navigationStyle: "default"`（系统原生导航栏）；
- 当 `getCurrentPages().length > 1`（navigateTo 进入有上一页）时，微信显示"< 返回"；
- 当栈空（从分享卡片/扫码/系统菜单/快捷入口等直接进入）时，**微信强制用🏠替换返回**，提示"返回首页"。**这是微信系统行为，绝不能通过 JSON 或 CSS 改图标**（经验 ID 310587 Failure 1 明确指出：`navigationBarBackButtonText` 仅影响文字，不影响按钮是否出现或图标形状）。

两种入口视觉不一致，且用户的偏好是"返回语义而不是主页语义"。因此按经验 ID 310587 策略B——**自定义 navigationStyle:custom + 自绘返回按钮**，完全接管导航栏绘制权。

### 2.2 切换到自定义 navigationStyle

在 `locations.json` 中：
- 删除静态标题 `navigationBarTitleText: "校园地点"`（由自绘标题承载）
- 新增 `"navigationStyle": "custom"`：让微信的系统🏠/返回/标题全部不渲染，顶部留出纯透明区域由我们自绘

### 2.3 精确计算的自定义导航栏（经验 ID 1055592 对齐）

按经验库「自定义导航栏必须用 getSystemInfoSync + getMenuButtonBoundingClientRect 精确计算高度」的标准做法：

**onLoad 注入**：`locations.ts` 顶部 data 新增 `statusBarHeight / navBarHeight / navBarTotalHeight` 三字段，onLoad 时计算：
```
statusBarHeight = getSystemInfoSync().statusBarHeight || 20
navBarHeight = max(44, gap*2 + 胶囊.height)    // gap = 胶囊.top - statusBar
navBarTotalHeight = statusBarHeight + navBarHeight
```
失败安全回退值 20+44=64px（老设备兜底）。

**WXML 结构三层**（严格按经验库：状态栏占位 + 内容区 + 底部分割阴影）：
```
.custom-nav                          // sticky top:0, z999, --paper 白背景
├─ .custom-nav-status                // 状态栏纯占位，高度 style 注入
├─ .custom-nav-content               // 内容区，高度 style 注入
│   ├─ .custom-nav-back (bindtap=onBackTap)  // ← 圆形返回按钮 64rpx
│   ├─ .custom-nav-title             // position:absolute 居中"校园地点" 32rpx/600
│   └─ .custom-nav-placeholder       // 与返回按钮同尺寸对称占位，保证标题不偏
└─ .custom-nav-shadow                // 1rpx 分割线 + 6rpx * 16rpx 底部淡阴影
```

**WXSS 细节**：
- `.custom-nav-back`：圆形 64rpx，`rgba(21,38,41,0.04)` 浅灰背景，hover 变湖蓝 `rgba(23,77,94,0.12)` + scale(0.92)，与全局按钮交互风格统一；
- `.custom-nav-title`：使用 `position:absolute left:50% top:50% translate(-50%,-50%)` 居中，最大宽度 55% 做省略，避免与左右按钮重叠；
- 整体 sticky 固定，列表滚动时导航栏保持在顶部。

### 2.4 返回按钮的双分支安全逻辑

`onBackTap()` 需要处理两种入口（经验库 ID 636812 提醒 tabBar 与栈逻辑要区分）：

```ts
onBackTap() {
  const pages = getCurrentPages()
  if (pages && pages.length > 1) {
    wx.navigateBack({ delta: 1 })        // 常规 navigateTo 入口 → 真正返回上一页（< 语义）
  } else {
    wx.switchTab({ url: '/pages/home/home' })  // 栈空（分享/扫码）→ 回首页，功能与原🏠等价，但视觉统一是←
  }
}
```

### 2.5 配套修复：icon 组件补齐 chevron-left

在代码检查时发现 `ICON_PATHS` 映射里有 `chevron-right / chevron-down / arrow-left`，**唯独缺 `chevron-left`**（尖角左箭头，适合做导航栏返回）。直接在 icon.ts 里加一行标准 lucide 路径：

```
'chevron-left': '<path d="m15 18-6-6 6-6"/>'
```

（如果用 `arrow-left` 是带横线的粗箭头，视觉偏笨重，不如 chevron-left 的尖角轻巧，更符合微信原生"< 返回"的视觉习惯。）

## 4. 实现思路

**决策依据：经验库先行**——一开始我以为只要在 locations.json 里加某个 navigation 配置项就能换图标，查完经验 ID 310587 的 Failure 1 后直接放弃"改系统配置"这条路，选用策略B自绘，避免走弯路、反复试错。

**高度计算按标准流程走**：经验 ID 1055592 明确指出 custom 导航栏必须同时读 statusBarHeight + getMenuButtonBoundingClientRect（不能写死 88rpx 或 44px），否则刘海、灵动岛、胶囊按钮等都会错位。代码里严格按 gap×2 + 胶囊高度公式计算，保证各种机型一致。

**栈分支行为保持可预期**：用户要的是"返回语义"，但不能让栈空时按钮变成死循环。双分支保证了：用户从普通入口进来，点击返回就真的回到上一页（符合返回语义）；从分享入口进来时视觉仍是返回，但行为悄悄切换到回首页（和原来🏠等价），用户不会察觉不一致。

**样式保持与系统风格近似**：自绘返回按钮特意做成圆形浅灰背景 + 深灰 chevron 箭头，与微信原生"< 返回"的视觉重量相近、又稍带项目自家湖蓝 hover 反馈，既保持与两端一致又不偏离品牌色。

## 6. 影响范围

- **唯一受影响页面**：`subpackages/pages/locations/locations`（校园地点页）——顶部导航栏从系统原生（系统🏠/<）切换为自绘 custom（始终 ← + 居中标题 + 白底阴影）；其余逻辑（搜索、卡片、详情、评分）完全不受影响。
- **附带影响**：
  - `components/icon/icon.ts` 新增 chevron-left，其他页面未来也可直接用（如发布页返回、编辑页返回等），属于正向能力扩展。
  - `locations.wxss` .locations-page padding 重置不会影响子元素，因为 24rpx 的内容 padding 被挪到了 locations-content 层，整体外边距视觉不变。
- **完全不影响**：首页、地图页、发布页、搜索页、个人中心、Web 端、后端、数据库。
- **一致性收益**：navigateTo 入口和分享/扫码入口现在视觉完全统一（都是 ← 返回），不会出现"有时🏠有时<"的割裂感。

## 8. 后续建议

1. **全站 custom 导航栏统一**：edit-post（修改帖子）、school-select（学校选择）、forgot-password（找回密码）等子包页面仍是系统原生导航，分享入口也会显示🏠主页图标，建议按相同 `getSystemInfoSync + getMenuButtonBoundingClientRect + chevron-left` 模式批量改造，形成整站一致的"← 返回"视觉与行为。
2. **全局抽取 custom-nav 组件**：将 `.custom-nav` WXML/WXSS + 高度计算逻辑 + `onBackTap` 抽成通用组件 `/components/custom-nav/custom-nav`，支持 `title`、`showBack`、`rightSlot` 等属性，后续页面不再重复写 20+ 行计算代码和样式，避免每次重复踩高度和安全区的坑。
3. **深色模式适配**：目前导航栏硬依赖 `--paper` 白背景 + 黑字，如后续启用深色模式需新增 `prefers-color-scheme:dark` 分支，反色为深色底+浅色文字，避免品牌色和深色背景对比度不足。
4. **返回手势支持**：微信 iOS 原生返回支持屏幕左侧边缘右滑手势。`navigationStyle:custom` 一般不影响该手势，但建议在真机关闭滑动确认手势仍可用，保证体验与原生导航栏一致。
5. **chevron-left 在其他返回入口复用**：目前 `icon.ts` 已补齐路径，edit-post、publish、profile 等页面若需要新的返回按钮可直接使用，不必再新增 icon SVG。
