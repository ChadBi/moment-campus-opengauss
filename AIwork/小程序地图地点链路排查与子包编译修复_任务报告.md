# 任务报告：小程序地图地点链路排查与子包编译修复

## 1. 任务概述

排查微信小程序地图页从学校坐标、地点标记、地点详情、评价、相关帖子到完整地点详情页的完整链路，定位“地点详情打不开”和“相关帖子数量不一致”等问题，并完成可验证的修复。

## 2. 已完成内容

- 核对 `GET /schools/current` 返回江南大学中心坐标 `31.483652, 120.271160`、缩放级别 `16`，与地图状态一致。
- 核对 `GET /locations` 返回 15 个当前学校静态地点，地图标记均来自地点接口，没有调用设备定位。
- 点击体育馆、蠡湖畔时，地点详情、评价、相关帖子三个请求均并行返回 200，且请求携带 `X-School-Code: jiangnan`。
- 修复地图面板把地点缓存字段 `post_count` 当作实时帖子数的问题，改为使用相关帖子接口的 `total`；体育馆面板由错误的 `0 条` 修正为实际的 `1 条`。
- 验证地点面板半屏打开、连续滚动、上滑全屏、下滑收起/关闭，以及快速连续点击地点时旧响应不会覆盖新地点。
- 定位到开发者工具在 Skyline 开启时加载 `subpackages/pages/*` 会统一报“编译 .wxss 文件错误”，导致从地图跳转地点详情超时；本地开发配置关闭 Skyline 后，地图跳转 `/subpackages/pages/locations/locations?id=6` 正常，详情数据和 AI 摘要空状态均正常渲染。

## 3. 未完成内容

- 尚未在真机和线上体验/正式 API 地址重复执行地图全链路。
- 后端 `locations.post_count` 仍是历史缓存字段，接口列表/详情中可能继续返回 0；小程序地图面板已不再依赖它，Web/管理端如需展示该字段应另行补充服务端重算。
- `project.private.config.json` 属于本机忽略配置，本次关闭 Skyline 的变更不会进入 Git；受版本控制的 `project.config.json` 本身已为关闭 Skyline。

## 4. 实现思路

先用网络日志确认租户、坐标和地点接口，再通过运行时页面数据确认面板请求结果。针对数量不一致，使用同一次相关帖子查询的分页总数作为展示来源，避免依赖异步维护的地点冗余计数。针对详情页打不开，分别打开多个子包页面复现 WXSS 错误，确认是 Skyline 子包编译配置而非地点 API 404，并用本地 WebView 渲染配置验证跳转和详情加载。
