# 任务报告：小程序地图页点击修复与评分界面补齐

## 1. 任务概述

解决小程序地图页（`pages/map/map`）的两个关键问题：
1. **点击无反应**：地点详情弹层内「帖子卡片」「查看完整详情」按钮、星级评分等可交互元素全部无法点击，用户反馈「卡住了」。
2. **评分界面缺失**：小程序地图页地点详情没有与 Web 端一致的评分汇总卡片和我的评价表单，「查看完整详情」按钮位置也与 Web 端布局不统一。

目标：让小程序地图页与 Web 端 LocationPage 保持功能与布局一致，同时保证帖子卡片点击跳转、详情按钮跳转、评分提交/撤回全链路可用。

## 2. 已完成内容

### 2.1 Bug 修复：点击事件拦截问题

- **根因定位**：`map.wxml` 外层 `scroll-view` 组件使用了 `catchtouchstart` / `catchtouchmove` / `catchtouchend` 绑定事件。`catch` 前缀属于「捕获型事件绑定」，会阻止事件进一步向上冒泡，导致 `scroll-view` 内部所有子元素的 `bindtap`（帖子卡片 `bind:tap`、`.goto-detail-btn` 的 `bindtap`、星级选项的 `bindtap` 等）全部无法触发。
- **修复方案**：
  1. 将 `catchtouch*` 全部改为 `bindtouch*`（冒泡型绑定），不再无条件吞掉事件。
  2. 触摸处理逻辑中引入 `_sheetGestureBlocked` 状态变量：只有当手势明确满足面板拖拽条件时才处理（expanded 态下拉或 half 态上滑），其余点击/轻触被标记为 `blocked` 直接 return，让事件自然冒泡给子元素的 `bindtap`。
  3. expanded 态新增 `_sheetPullFromExpanded` 状态：`scrollTop > 1` 时判定为正在滚动而非拖拽，避免滚动过程误触发面板收起；`movingDown`（从顶部向下拉）时重置起始 Y 坐标、开启下拉模式，其余方向直接放行。

### 2.2 新增：评分汇总卡片（与 Web 端对齐）

在 `map.wxml` 地点详情内容流最顶部（原本旧 sheet-meta 之前）新增 `.rating-summary-card`：

- **顶行**：左侧大星级 `{{averageStarsText}}` + 大号分数 `{{selectedLocation.scoreText}}`；右侧放置「查看完整详情」主按钮 `.goto-detail-btn`（湖蓝背景、白色文字 + 右箭头图标，与 Web 端按钮位置一致）。
- **次行**：`rating_count` 人评分 · `review_count` 条评价统计。
- **描述行**：地点描述（如有）。
- **位置行**：小地图 pin 图标 + building/floor 位置说明。
- 原底部孤立的「查看完整详情」按钮及其样式全部删除，避免重复入口。

### 2.3 新增：我的评价表单卡片

在评分汇总卡片下方新增 `.my-review-card`，完全对齐 Web 端的统一评分表单布局约束：

- **顶行标题 + 主按钮同排**：
  - 标题：`myReview ? '我的评价' : '给这个地点打个分'`
  - 主按钮（顶行右上角，紧凑尺寸 `h-52rpx px-22rpx rounded-10rpx`，湖蓝背景 + 白字）：
    - 有评价且非编辑态：显示「更新评价」（带 edit-3 图标）
    - 无评价或编辑态：显示「提交评价」或「更新评价」，带 submitting 禁用态
- **三态分支**：
  1. **未登录态**：显示「登录后即可为校园设施评分评价」+「去登录」按钮，直接跳转登录页。
  2. **有评价且未编辑（常态只读）**：显示紧凑摘要卡片——作者「我」+ 星级 + 分数 + 文字评价（空时显示"（仅评分，未填写文字评价）"），不展开表单。
  3. **无评价 或 编辑态**：
     - 未校园认证：显示「完成校园身份认证后即可评分评价」提示文案并禁用提交。
     - 已认证：展开星级选择器（5 个 ★/☆，点击切换，右对齐显示「X.0 分」预览）+ 500 字文本框 + 底部次要操作区（右对齐）——「取消编辑」（仅编辑态显示）+「撤回评价」（仅已有评价显示，红色文字）。

### 2.4 逻辑层补齐：评分表单相关方法

`map.ts` 新增/完善以下 Page 方法：

| 方法 | 作用 | 关键校验 |
|---|---|---|
| `onScoreTap` | 通过 `data-score` 读取点击星级，setData 更新 `score` | — |
| `onContentInput` | 文本框输入同步到 `content` | — |
| `onStartEditReview` | 用已有评价初始化 score/content，进入编辑态 | — |
| `onCancelEditReview` | 退出编辑态，保留原评价不做变更 | — |
| `submitReview` | 提交/更新评价 | requireLogin → 校园认证 → 分数非空 → 调用 `submitReview(id, {score, content?})` → 成功后并行重新 `getDetail + getReviews` → 就地刷新 location/scoreText/stars/myReview |
| `withdrawReview` | 撤回评价 | wx.showModal 二次确认 → 调用 `withdrawReview(id)` → 成功后并行重新拉取 + 重置表单 |

额外修复：`submitReview` 与 `withdrawReview` 中原本用了错误的 setData 键 `selectedLocation_scoreText`（下划线非嵌套路径），修正为点号路径 `'selectedLocation.scoreText'`，保证评分提交后顶部评分卡片的分数和星级能同步刷新。

## 4. 实现思路

**事件冒泡修复**：沿用原有的「sheet 拖拽 + 滚动」交互思路，不做结构性重写，只把捕获型事件改为冒泡型，并用 `_sheetGestureBlocked` 区分「用户确实在拖拽面板」与「用户只是点了面板里的按钮」两种场景——这样既保留拖拽手感，又不拦截子元素点击。

**UI 对齐**：以 Web 端 LocationPage 的评分汇总卡片 + 我的评价卡片为参考蓝本（近期已在 Web 端定稿：顶行主按钮右上角、常态只读紧凑卡片、编辑态才展开表单），小程序端直接复用同构的信息层级和配色（湖蓝 lake、琥珀 lamp、mist 背景、湖蓝主按钮），保证两端演示时视觉一致。

**接口复用**：直接调用小程序 `services/locations` 中已存在的 `submitReview` / `withdrawReview` / `getDetail` / `getReviews`（Web 与小程序共用后端 REST 契约），不新增后端路由，不破坏现有权限体系。

## 6. 影响范围

- **小程序地图页**（唯一受影响的页面）：
  - 面板拖拽手感保持不变（仍支持 half → expanded → 关闭三级状态）；
  - 面板内所有子元素的 `bindtap` 事件现在都能正常触发；
  - 地点详情的内容流顺序调整：原本「旧紧凑评分 meta」前置，现在改为「评分汇总卡片 → 我的评价卡片 → 旧 meta → 资料 → 摘要 → 帖子」，与 Web 端 LocationPage 顺序一致。
- **服务接口层**：评分提交/撤回、详情/评价查询全部复用现有 `services/locations` 接口契约，无后端路由改动。
- **不影响**：小程序其他页面、Web 端、后端、数据库、AI 搜索、订阅/通知、举报/治理等模块。
