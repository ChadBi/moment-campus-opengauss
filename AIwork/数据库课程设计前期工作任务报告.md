## 4. 实现思路

### 4.1 文档体系衔接

```
doc 24 需求分析  ──┐
                  ├──> doc 25 概念模型  ──> doc 26 逻辑模型  ──> doc 27 物理模型
doc 23 江南大学  ──┘
```

- doc 24 提供数据字典与数据流图，作为概念模型的输入
- doc 25 将需求抽象为 E-R 模型（21 实体 + 35 联系）
- doc 26 将 E-R 模型转换为关系模式（21 表 + 15 视图），满足 3NF
- doc 27 将关系模式落实为 openGauss 物理存储结构

### 4.2 设计原则

1. **真实可用**：所有 SQL 均为可执行的 openGauss 7.0.0-RC3 语法
2. **课程设计深度**：体现 openGauss 特性应用（双引擎、分区、物化视图、部分索引、存储过程/触发器）
3. **江南大学核心**：所有数据样例与地点均以蠡湖校区为模拟核心
4. **可追溯**：每个设计决策可回溯到 doc 18-23 的既有项目分析

### 4.3 关键设计决策

| 决策点 | 选择 | 依据 |
| ------ | ---- | ---- |
| 主键类型 | 统一 BIGINT | 解决原项目 Integer/BigInteger 类型不一致（doc 20 H1） |
| 存储引擎 | Ustore（核心表）+ Astore（日志表） | 按读写特征分配 |
| 索引策略 | 部分索引（WHERE is_deleted=FALSE） | 软删除场景下减少 90% 扫描量 |
| 视图实现 | 11 普通视图 + 4 物化视图 | 聚合型视图物化，避免每次重算 |
| 分区策略 | RANGE 按月分区 | 时间序列数据，便于归档 |
| 可信度计算 | 存储过程 + 触发器自动重算 | 业务原子性保证 |
