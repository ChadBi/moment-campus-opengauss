# 任务报告：微信小程序真机调试切换局域网模式

## 1. 任务概述

用户在问"启动的是局域网模式吗？"之后立即澄清：**要做微信小程序的真机调试，所以前后端和小程序的网络配置必须切到电脑的局域网 IP（不能再用 localhost/127.0.0.1）**。

核心矛盾：
1. 真机（手机）上的 localhost 指向手机自身，根本不会走到电脑上的后端；
2. 微信小程序真机调试对非 HTTPS、非合法域名有限制，开发期需要"不校验合法域名"开关；
3. 代码中之前只改了 `miniprogram/config/env.ts` 的 dev 地址到 `192.168.3.10`，但 AI Skills 分包里两个独立 util 文件（`skills/moment-campus/utils/util.js` 与 `request.js`）**仍然硬编码 `http://localhost:8000`**——意味着真机里业务代码能联网，但图片渲染、技能内网络请求都会失败（经典 80% 正常 + 20% 诡异 bug 类问题）。

交付目标：一次改齐后端监听、小程序 3 处地址、project.config 显式开关、防火墙命令、文档齐全，真机扫码打开小程序后无需手动改一行配置，链路全通。

## 2. 已完成内容

### 2.1 本机局域网 IPv4 探测（选网卡优先）

用 `Get-NetIPAddress` 过滤掉回环、169.254 APIPA、虚拟机 Hyper-V WSL 的 172.24 段之后，得到真实 Wi-Fi 网卡的地址：

- WLAN：**192.168.3.10 / 24** ✅（家庭 Wi-Fi，江南大学环境为 `192.168.3.x` 段，优先选择）
- 忽略：172.24.128.1（WSL Hyper-V 虚拟网卡，手机真机永远连不到）、198.18.0.1（Fxy 其他虚拟适配器）

### 2.2 后端启动命令切到 0.0.0.0（真机才能 TCP 握手）

[AGENTS.md](file:///e:/Project/moment-campus/AGENTS.md#L14-L19) 原来的启动命令是：

```
uvicorn app.main:app --reload
```

uvicorn 默认只监听 `127.0.0.1:8000`（也就是本机回环）。真机即便跟电脑连同一个 Wi-Fi，发 SYN 包到 `192.168.3.10:8000` 也会被 Windows 网络栈直接 RST 掉，表现为"请求超时"。

改为：

```
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

并且在同一段补充配套的 2 条操作指引：
- 微信开发者工具 UI 必须勾选「详情 → 本地设置 → 不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」（否则真机阶段对 HTTP + 裸 IP 直接拦截）
- Windows 防火墙 8000/TCP 入站一次性放行的管理员 PowerShell 命令（后文 §6 实测因非管理员权限需要手动执行）

### 2.4 project.config.json 「不校验合法域名」语义化

[miniprogram/project.config.json](file:///e:/Project/moment-campus/miniprogram/project.config.json#L32-L40) 原本已有 `"urlCheck": false`，但没有注释，新人 / 换电脑的人不知道它对应微信开发者工具 UI 哪个勾选框（不同版本的工具会有默认值差异，旧工程可能被 UI 覆盖）。

在其上方加 2 行中文注释，明确 UI 路径：「详情 → 本地设置 → ✅ 不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」；
微信官方 project.config 支持 `//` 注释，JSONC 解析不会报错，也不会上送小程序后台，不影响体验版/正式版域名白名单审核。

## 4. 实现思路

### 4.1 为什么只选 WLAN 网卡地址，而不是选第一个命中 192.168

PowerShell 返回的顺序是：`vEthernet (WSL Hyper-V firewall, 172.24.x)` → `WLAN (192.168.3.10)` → `Fxy (198.18.x)`。如果"取第一个 192.168"会拿不到，所以按 InterfaceMetric 排序后再挑 InterfaceAlias==`WLAN` 的那个，语义最稳。对于公司网络/实验室网络，如果网卡名是 `以太网 vEthernet (默认交换机)`，注释里留了手动改 3 处的清单。

### 4.2 为什么 AI Skills 的两个文件也必须改（不能只改业务 config/env.ts）

微信小程序的「Skills 分包」和「业务包」是两套独立的代码隔离域：
- 业务代码：`app.ts` import `config/env.ts` 的 `BASE_URL` → 注入 services/request 拦截器。
- Skills 代码：`skills/moment-campus/utils/*.js` 通过 `require('./request.js')` 方式加载**自己的 BASE_URL**，根本不会 import 业务包的 env.ts（否则会形成跨包模块引用，编译期失败）。

所以如果只改 1 处、忽略 Skills 里 2 处，真机调试时就会出现"登录、发帖、列表等业务流程全通（走 env.ts 地址），但帖子图片全是 404（util.js 补了 localhost:8000）、AI 技能弹窗一点全是 request:fail（request.js 连手机自己）"这种非常折磨人的半残状态——经验 329062 里就踩过类似"只改一处配置，其他地方残留硬编码"的坑，所以这次刻意一次补全 3 处 + 注释 checklist。

### 4.3 不把 DEV_LAN_HOST 做到自动探测的原因

真机调试配置是开发期**非常稳定**的变量（一天最多换一两次 Wi-Fi），自动探测会引入：
- 小程序运行时需要 `wx.getSystemInfoSync()` 拿不到电脑 IP；
- 如果把电脑 IP 写进编译期 env，又需要 vite/uniapp 的 define 插件；
- Skills 是纯 JS 分包，没有 define 插件注入能力，还是得用静态常量。

所以采用「统一常量 + 注释 checklist」成本最低、可读性最好。而且换 Wi-Fi 的 PowerShell 一行式命令也直接写在注释里，改起来 10 秒内搞定。

### 4.4 为什么不把 urlCheck 改成 false 就算完了（还要加注释）

`"urlCheck": false` 在微信开发者工具里不会 100% 同步到 UI——有时候开发者工具新建项目会把这个字段还原，需要你手动去勾。注释精准对应 UI 复选框路径，避免用户排查半天"我代码里已经 false 了为啥真机还报不在合法域名"。

### 4.5 防火墙规则 Profile 只选 Private+Domain，不选 Public

`-Profile Private,Domain`：在家/学校 Wi-Fi 分类为"专用网络"或加域环境才放行；Public 网络（咖啡店、公共 Wi-Fi）默认关闭，避免把数据库+后端暴露在公网咖啡厅里，属于安全保守默认。

## 8. 后续建议

1. **🔥 立即手动执行（30 秒）**：打开 Windows 开始菜单搜索 `PowerShell` → 右键「以管理员身份运行」→ 复制粘贴并回车：
   ```powershell
   New-NetFirewallRule -DisplayName 'MomentCampus Backend :8000' -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow -Profile Private,Domain | Out-Null
   ```
   然后启动后端时用 AGENTS.md 的新命令（**0.0.0.0**），别用老的默认回环。

2. **如果换了 Wi-Fi / 换了网线 / 路由器重新拨号导致局域网 IP 变了**：
   - 先跑 `Get-NetIPAddress -AddressFamily IPv4 | ? IPAddress -notlike '127.*' | ? IPAddress -notlike '169.254.*' | select InterfaceAlias,IPAddress` 拿到新 IP（一般还是 192.168 开头那一条）
   - 统一修改 3 处（env.ts 顶部注释有 checklist），**保存后微信开发者工具→项目→重新编译**。

3. **生产上线前记得补 2 件事**（和本轮无关，但避免将来遗漏）：
   - 小程序管理后台「开发 → 开发管理 → 开发设置 → 服务器域名」里把 `https://campus.chaina1.com`（HTTPS）填到 request合法域名 / uploadFile合法域名 / downloadFile合法域名。
   - 用 `npm run build` 打正式包时，务必走 experience/prod 环境（自动用 HTTPS 域名，不走 DEV_LAN_HOST 逻辑），不要把 192.168 的 HTTP 配置带到体验版/正式版。

4. **如果真机还是白屏 request:fail url not in domain list**：一般是微信开发者工具 UI 的复选框被升级重置了，手动去「详情→本地设置」再看一眼「不校验合法域名」是不是还勾着；重启一下开发者工具就行（project.config.json 的 urlCheck:false 和 UI 是两个存储位置，有时候 UI 会优先）。
