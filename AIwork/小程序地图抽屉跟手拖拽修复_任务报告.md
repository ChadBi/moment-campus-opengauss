# 任务报告：小程序地图抽屉跟手拖拽修复

## 1. 任务概述

修复地图地点详情抽屉“松手后直接全屏、拖动过程中不跟手”的问题。根因是触摸事件绑定在 `scroll-view` 外层，连续 `touchmove` 被内部滚动容器拦截，页面只能收到最后的方向判断。

## 2. 已完成内容

- 将地点抽屉的 `touchstart`、`touchmove`、`touchend` 绑定到实际承载内容的 `scroll-view`。
- 半屏状态将 `scroll-y` 关闭，拖动过程中实时更新整块抽屉的 `translate3d` 位移。
- 全屏状态仍使用同一个 `scroll-view` 阅读标题、摘要、帖子和详情按钮，不拆成两个滚动区域。
- 保留上滑展开、轻微拖动回弹、下滑关闭的阈值逻辑。

## 3. 未完成内容

- 尚未在真实手机上确认不同机型的触摸采样频率和拖拽阻尼；开发者工具自动化已验证连续触摸事件和布局位移。

## 4. 实现思路

问题不在位移计算，而在事件接收层级。原实现把事件放在固定抽屉父节点，`scroll-view` 会优先处理触摸并导致父节点只在结束时得到方向结果。将事件下移到 `scroll-view`，并根据 `sheetExpanded` 动态控制 `scroll-y`，即可在半屏时把触摸距离用于移动外层抽屉，在全屏时恢复原生内容滚动。

## 6. 影响范围

仅影响小程序地图地点详情抽屉的触摸事件绑定和半屏/全屏滚动切换，不改变地点数据、相关帖子、学校切换或地图坐标。

## 7. 测试与验证

- `miniprogram npm run typecheck`：通过。
- `miniprogram npm run test:format`：通过。
- 微信开发者工具 `compile_wxml pages/map/map.wxml`：通过。
- 微信开发者工具 `compile_wxss pages/map/map.wxss`：通过。
- 自动化触摸事件验证：`touchstart` 后 `touchmove` 120px，页面数据 `sheetDragOffset=-120`；元素布局 top 同步变为约 `240px`，证明整块抽屉在移动过程中已跟手更新；`touchend` 后按阈值切换全屏。

## 8. 后续建议

- 真机上分别从标题、摘要和帖子区域上滑，确认任意位置都能拖动整块半屏抽屉。
- 如果真机上仍有轻微延迟，可再把 `setData` 更新频率限制到每帧一次，但当前开发者工具布局已能实时跟随。
