# 任务报告：批准计划文档同步与残留扫描

## 1. 任务概述

检查当前工作区，并将批准计划已经形成的现行实现口径同步到 README、Demo 作品帖及指定 docs 文档。统一两类协同验证、单数写端点、独立 systemd timer、动态分类、DataVec 混合检索与关键词降级、独立测试库安全门禁，同时扫描容易造成误解的历史残留。

## 2. 已完成内容

- 将协同验证统一为 `confirmation/refutation` 两类互斥投票，明确创建、切换、取消语义与作者不可自验规则。
- 将写接口统一为 `POST /api/v1/posts/{post_id}/validate`，将登录态统计接口统一为 `GET /api/v1/posts/{post_id}/validation-stats`，并说明帖子详情 `governance` 字段承担公开聚合。
- 将自动过期统一描述为独立 `moment-expire-posts.timer` 每 5 分钟触发 oneshot worker，明确不在多 Uvicorn Web worker 内启动重复调度器。
- 将分类统一为当前学校 API 动态加载、按 `category.code` 稳定计算视觉，并明确切校时清理旧校分类、筛选和地图标记。
- 将 AI 搜索统一为 openGauss DataVec 384 维语义召回与语义 35%、新鲜度 25%、验证数 20%、关键词 20% 混合排序；Embedding 或向量查询不可用时降级为关键词检索。
- 将测试安全统一为只读取独立 `TEST_DATABASE_URL`，要求数据库名包含 `_test` 且不得与开发库相同，并在 schema 重建或数据清理前失败停止。
- 清理项目概览中的固定五分类描述、技术架构中的旧 `validity.py` 目录与旧复数有效性统计示例，以及测试文档中绕过统一夹具和旧有效性服务的示例。
- 扫描指定文档中的五类验证、复数端点、进程内调度、固定分类、pgvector、SQLite 与测试库安全残留；保留项均为明确的历史说明或禁止事项。
