# 任务报告：修复注册后误报无该学校访问权限

## 1. 任务概述

用户反馈：注册完账号后进入系统会显示"您没有该学校的访问权限，已切换回 xxx"的提示，需要修复。

## 2. 已完成内容

- 定位两处根因并修复：
  1. `frontend/src/pages/RegisterPage.tsx`：注册成功后仅同步了 store 的当前学校，未同步 URL 中的 `school` 参数（如游客态残留的 `?school=fudan`），`useSchoolSync` 的 URL 监听器读到残留旧值会反向覆盖刚设置的当前学校，最终由 `ensureValidSchool` 回退并弹出提示。修复：注册成功后立即同步改写 URL 的 `school` 参数（与 `setCurrentSchool` 同一批次，`replace: true`），再延迟跳转
  2. `frontend/src/hooks/useSchoolSync.ts`：登录态 effect 用 effect 闭包捕获的 `currentSchoolCode` 作为回退前后对比基准（`prevCode`），注册瞬间与 `setCurrentSchool` 存在渲染竞态，闭包旧值导致"未真正回退"也误判为需要回退并弹提示。修复：`prevCode` 改为读取实时 store 值 `useCampusStore.getState().currentSchoolCode`
- 更新 CHANGELOG.md（v2.1.3）与 TODO.md

## 3. 未完成内容

暂无。

## 4. 实现思路

问题本质是"学校状态同步时序"缺陷：

- 第一处：store 与 URL 两个状态源未在同一批次更新，导致 URL 监听器反向覆盖。修复为 store + URL 原子同步。
- 第二处：effect 闭包捕获旧值引发的竞态误判。修复为用实时 store 值做前后对比，只有真正发生回退（ensureValidSchool 改变了学校）才提示。

两处都保持最小改动，未改变产品语义：用户主动通过 URL 深链接进入无权限学校时，仍会回退到默认学校并提示。

## 5. 修改文件

- `frontend/src/hooks/useSchoolSync.ts`（回退对比基准改用实时 store 值）
- `CHANGELOG.md`（新增 v2.1.3 章节）

## 6. 影响范围

- 注册流程：注册成功后进入系统的学校上下文初始化
- 登录态学校同步（useSchoolSync）：回退提示触发条件更精确（仅真正回退时提示）
- 后端无改动

## 8. 后续建议

- 登录场景存在同类时序风险（登录后 URL/store 残留无权限学校），如后续遇到可参照本修复：登录成功后同步 URL school 参数至默认/可访问学校
- `useSchoolSync` 第 6 步 effect 的提示逻辑可进一步抽象：区分"用户主动深链接进入无权限学校"（提示）与"系统初始化自动回退"（静默），提升可维护性
