# 任务报告：自动过期锁租约权限与定时部署

## 1. 任务概述

按已批准计划完善自动过期任务：采用 TDD 修复数据库锁失败语义，增加 60 分钟脏任务租约，收紧手动触发与运行记录查询权限至 super_admin，并新增 systemd service/timer 及部署集成。按用户要求不更新 TODO.md、不提交 Git，仅运行定向测试。

## 2. 已完成内容

- 数据库 advisory lock 调用异常或未获锁时采用 fail-closed，不再无锁继续扫描帖子，并持久化 failed 运行记录。
- 超过 60 分钟的 running 记录自动标记为 failed，填写结束时间与租约回收原因，随后允许新任务运行；租约内 running 记录仍阻止重复执行。
- POST `/api/v1/admin/jobs/expire-posts` 与 GET `/api/v1/admin/jobs/expire-posts/records` 调整为仅 super_admin 可访问。
- 新增 `moment-expire-posts.service` oneshot 单位和每 5 分钟触发、支持 Persistent 补跑的 `moment-expire-posts.timer`。
- 传统初始化、传统更新和华为云混合部署脚本均安装并启用自动过期 timer。
- 新增锁失败、未获锁不处理帖子、脏任务租约回收、admin 拒绝和 super_admin 放行测试。

## 3. 未完成内容

- 未在真实 Linux 生产服务器执行 `systemctl daemon-reload`、启动 timer 或观察一次真实调度；当前工作环境为 Windows/WSL，生产路径不存在。
- 未执行前后端 E2E 自动化测试。本任务限定运行定向测试，且改动不涉及前端交互。
- 未更新 TODO.md、未提交 Git，遵循用户明确要求。

## 4. 实现思路

先补充行为测试并确认 4 类预期失败，再进行最小生产代码修改。任务入口必须先成功获取 advisory lock；任何锁调用异常或返回 false 均立即停止业务扫描。获得锁后查询最近 running 记录，以当前时间减 60 分钟作为租约边界，回收超期记录后继续执行。平台级跨校任务 API 使用统一 `require_role(Role.SUPER_ADMIN)`。调度层使用独立 oneshot worker 和 systemd timer，避免在 4 个 Web worker 中重复启动调度器。

## 8. 后续建议

部署后执行 `systemctl status moment-expire-posts.timer`、`systemctl list-timers moment-expire-posts.timer` 和 `journalctl -u moment-expire-posts`，确认至少一次真实触发成功。可进一步为任务运行记录增加数据库级并发约束，减少未来绕过 advisory lock 的错误调用造成并发记录的风险。
