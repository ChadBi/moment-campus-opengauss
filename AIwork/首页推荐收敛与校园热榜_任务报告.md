# 任务报告：首页推荐收敛与校园热榜

## 1. 任务概述

根据 Web/小程序一致性重构要求，缩短首页推荐内容，移除快捷入口，并把校园热榜改为近 7 天浏览量 Top10 的横向预览与独立榜单页面。热榜条目需要可以进入帖子详情，Web 与微信小程序保持相同的排序口径和交互结构。

## 2. 已完成内容

- 首页推荐区只展示一条精选推荐，普通校园动态仍单独分页加载。
- 首页区块顺序统一为“校园热榜 → 为你推荐 → 普通校园动态”。
- 热榜入口补充“查看榜单”直接点击绑定、页面栈满时重定向兜底和失败提示；各端标题统一两行高度并省略超长文本。
- 针对子包导航超时，将小程序热榜详情页调整到主包 `pages/hot-ranking`，并通过主包路由完成入口导航。
- 首页不新增或保留四个快捷入口，校园地点入口和普通信息流继续保留。
- 后端帖子列表新增 `sort=views`，在当前学校、已发布、时间窗口条件下按浏览量降序。
- 小程序首页增加横向滚动热榜卡片，标题可进入独立热榜页，卡片可进入帖子详情。
- 小程序新增 coral/米白视觉的“校园热榜”榜单页，展示排名、作者、分类、摘要、地点与统计数据。
- Web 首页同步热榜预览，并新增 `/hot-ranking` 页面。
- 兼容带时区的 ISO 时间筛选，避免无时区时间列被 asyncpg 直接比较而返回 500。

## 3. 未完成内容

- 首次放在 subpackage 时，微信开发者工具自动化导航出现 `automator timeout`；调整到主包后，已通过自动化点击“查看榜单”进入 `pages/hot-ranking/hot-ranking`，并通过点击榜单卡片进入帖子详情。尚未在真机上验证。
- 热榜目前以帖子创建时间作为“最近 7 天”窗口，再按累计 `view_count` 排序；现有浏览历史是每个用户/帖子一条 upsert 记录，尚不具备逐次浏览事件统计能力。

## 4. 实现思路

在已有 `GET /posts` 上增加 `views` 排序，避免引入重复热榜接口。小程序和 Web service 都传入本地墙上时间格式的 `date_from`，后端同时兼容带时区的 ISO 输入。首页只消费第一页 Top10，其中小程序使用 `scroll-view`，Web 使用横向溢出容器；完整榜单页复用同一查询和帖子详情路由，确保数据不产生第二套口径。

## 8. 后续建议

补充真机验证点击“查看榜单”、热榜条目进入帖子详情和返回首页；如果产品需要“过去 7 天真实浏览事件”而不是“过去 7 天发布帖子累计浏览量”，应新增按浏览事件聚合的统计表或日志模型，再替换 `sort=views` 的排序来源。
