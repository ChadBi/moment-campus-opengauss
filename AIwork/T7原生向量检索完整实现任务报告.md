# 任务报告：T7 原生向量检索完整实现

## 1. 任务概述

按批准计划实现独立 OpenAI 兼容 Embedding 配置与服务、openGauss DataVec 384 维帖子向量、可逆 Alembic 迁移、帖子创建与更新向量生成、历史回填脚本，以及按语义 35% / 新鲜度 25% / 验证数 20% / 关键词 20% 打分的租户安全混合检索。

## 2. 已完成内容

- 增加独立 `EMBEDDING_*` 配置，不复用聊天模型的密钥、地址或模型。
- 实现 OpenAI 兼容 Embedding 客户端，显式请求 384 维向量，校验响应维度并在失败时安全降级；日志不记录密钥、地址、正文或异常详情。
- 实现 openGauss 原生 `vector(384)` SQLAlchemy 类型映射及 asyncpg 文本 codec。
- 为 `posts.embedding` 增加 384 维 ORM 字段，并提供创建/删除向量列与 HNSW 索引的可逆 Alembic 迁移。
- 帖子创建时生成向量；标题或正文变化时刷新向量；创建生成失败不阻断主流程，更新生成失败保留旧向量。
- 实现仅扫描缺失向量、按主键游标分批提交的历史回填脚本及统计结果。
- AI 搜索在候选截断前执行 DataVec 原生距离排序，并按 35/25/20/20 融合打分；向量不可用或查询失败时回退关键词检索。
- 所有向量候选查询继续强制使用 `TenantContext.school_id`，新增跨校向量相同也不可召回的集成测试。

## 3. 未完成内容

- 当前环境没有配置独立 Embedding Provider/API Key/Base/Model，无法执行真实 API 同义联调，也无法为生产库 90 条历史帖子生成真实向量。
- 历史回填脚本已真实运行，结果为 `scanned=90, updated=0, failed=90, skipped=0`；失败原因是 Embedding 服务处于未配置/禁用状态，不是数据库写入错误。
- 未执行浏览器端到端测试：本任务仅改后端，且当前工具集中没有规则指定的 `integrated_code_mode/run_mcp`；未将未执行项写成已完成。

## 4. 实现思路

采用可降级的同步业务集成：外部 Embedding 调用发生在帖子事务写入前，但任何外部失败均返回 `None`，不阻断创建；更新时仅用成功结果覆盖旧向量。检索先在当前租户、公开且未过期的集合内用 HNSW 距离召回最多 200 条候选，再批量读取距离并归一化为语义相似度，最后与新鲜度、验证数和关键词相关度融合。无向量时恢复原关键词过滤，确保 AI 服务缺失时核心搜索仍可用。
