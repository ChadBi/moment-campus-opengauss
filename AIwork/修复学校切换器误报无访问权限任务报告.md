# 任务报告：修复学校切换器加入新学校后误报无访问权限

## 1. 任务概述

用户反馈：注册账号只有单一学校时，通过页头学校切换器进入其他学校失败，提示"您没有该学校的访问权限"，且"申请不了"。

## 2. 已完成内容

- 定位根因并修复 `frontend/src/components/layout/SchoolSwitcher.tsx`：
  - 原流程：选择未加入学校 → `joinSchool(code)`（后端已创建 membership）→ `switchSchool(code)`，但 join 成功后未刷新前端 store 的 memberships
  - `useSwitchSchool` 用过期 memberships 校验权限 → 误判"无该学校访问权限"并 return，导致切换被拦截
  - 修复：join 成功后重新拉取 `me/memberships` 并 `setMemberships(list)`，再执行切换
- 端到端验证通过；前端 `npm run build` 通过
- 更新 CHANGELOG.md（v2.1.2）与 TODO.md

## 3. 未完成内容

暂无。

## 4. 实现思路

问题本质是前端状态同步时序错误：后端 membership 已创建，但前端 store 仍持有旧数据，权限校验基于过期状态误拦截。

修复采用最小改动：在 join 成功路径中补一次 memberships 刷新，使 `useSwitchSchool` 校验时数据为最新。未改动后端 join 接口（后端逻辑本身正确）与权限安全设计（TEN-03.2：未加入学校不可访问）。

## 5. 修改文件

- `frontend/src/components/layout/SchoolSwitcher.tsx`（join 成功后刷新 memberships）
- `CHANGELOG.md`（新增 v2.1.2 章节）
- `TODO.md`（新增已完成条目）

## 6. 影响范围

- 页头学校切换器（SchoolSwitcher）：加入新学校 → 切换的完整链路
- 个人中心（ProfilePage）切换学校不受影响（仅切换已加入学校）
- 后端无改动

## 7. 测试与验证

- 前端构建：`npm run build` → 通过
- 端到端（浏览器实测）：注册单校账号 → 页头切换器选择另一所学校 → join 成功并切换，页面显示新学校上下文，帖子流正常加载，无"无访问权限"报错
- 未运行后端测试：本次无后端代码改动，后端行为未变化

## 8. 后续建议

- `useSwitchSchool` 的权限校验依赖调用方保证 memberships 最新；后续可考虑将"未加入学校 → join → 刷新 → 切换"收敛为 hook 内统一封装，避免调用方遗漏刷新
- 可考虑在切换失败时给出更明确的提示（如区分"未加入"与"加入失败"），提升可诊断性
