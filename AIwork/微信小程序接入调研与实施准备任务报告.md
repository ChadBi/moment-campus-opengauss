# 任务报告：微信小程序接入调研与实施准备

## 1. 任务概述

评估当前“此刻校园”项目增加微信小程序的可行性，说明需要准备的账号、资料、软件、模块、测试与发布方式，并在 `docs/` 形成可执行报告。

## 2. 已完成内容

- 阅读项目架构、用户流程、API、安全、测试、运行环境、全量审计、认证评估和复赛要求等相关文档。
- 检查当前 FastAPI 路由、认证、上传、地图、多租户、User 模型和 Web 请求层实现。
- 使用当前 `backend/.venv` 生成静态 OpenAPI，确认当前工作区有 105 个 path、123 个 operation。
- 查阅微信官方注册、开发工具、合法域名、登录、地图、定位、隐私、自动化和发布资料。
- 检查线上首页、健康检查和学校接口，三者在 2026-07-29 均返回 HTTP 200。
- 明确推荐架构：新增独立 `miniprogram/` 原生 TypeScript 用户端，复用现有后端与 openGauss，管理后台保留 Web。
- 明确位置接口、合法域名/ICP、坐标系、微信身份模型、图片相对 URL 等关键风险。
- 新增 `docs/34_微信小程序接入评估与实施准备报告.md`。

## 4. 实现思路

先从源码确定可复用与不可复用边界，再以微信官方资料核对平台规则。方案优先降低体验版风险：首期复用邮箱密码 JWT，不修改用户核心模型；地图默认校园中心并支持地图点击选点，不把受类目限制的实时定位作为前置；管理后台继续使用 Web。

## 8. 后续建议

优先完成平台硬门槛验证：注册主体和类目、取得 AppID、在小程序后台实际添加合法域名、绑定体验成员。通过后再创建 `miniprogram/` 骨架，按“登录/请求层 → 信息流 → 地图 → 发布互动 → 自动化与真机”的顺序实施。
