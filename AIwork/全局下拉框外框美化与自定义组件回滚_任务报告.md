# 任务报告：全局下拉框外框美化与自定义组件回滚

## 1. 任务概述

解决用户反馈的「所有页面的下拉选框都是浏览器默认的丑框框」问题。目标：统一美化全站 `<select>` 的视觉外观，使外框、圆角、箭头、焦点环与 Input/Button 的水墨风设计语言保持一致。

## 2. 已完成内容

1. **`index.css` 新增 `.select-nice` / `.select-nice-sm` 两档通用工具类**
   - `.select-nice`（默认 40px / 圆角 10px）：纸面白底、1px 线框边框、内嵌 SVG `ChevronDown` 图标替换浏览器默认三角箭头、湖蓝 `lake` 色 focus ring（带 3px 光晕）、hover 边框加深、disabled 灰显半透明、选中 `<option>` 保持深色（避免占位灰字污染）
   - `.select-nice-sm`（紧凑 36px / 圆角 8px）：参数按比例压缩，专供 admin 后台列表筛选区紧凑排版

2. **全站 14+ 原生 `<select>` 统一套用新类名**
   - `PostForm.tsx` 2 处：发布页地点下拉框、失物类型下拉框
   - `LocationPage.tsx` 1 处：地点页筛选排序下拉
   - `SearchPage.tsx` 3 处：搜索页分类/排序/范围筛选区 3 枚 select
   - admin 后台 8 处：`ActivationFunnelPage` / `AdminLogsPage`（2 处）/ `AdminTopicsPage` / `AnalyticsPage` / `PlatformOverviewPage` / `PlatformPlansPage`（3 处）/ `PlatformSchoolsPage` / `SchoolImportPage`
   - 特判豁免：`SearchPage` 的 AI 分类/排序（用 Chip 胶囊样式，`rounded-full bg-lake/10`）、`RegisterPage` 的学校选择下拉（带学校图标的自定义 wrapper，已独立美化）保持现状不改

3. **评估并回滚自定义下拉展开组件方案**
   - 曾尝试新建 `frontend/src/components/ui/Select.tsx` 自定义组件（含分组/禁用/图标/动画），希望覆盖 OS 原生 `<option>` 弹窗的外观
   - 根因确认：原生 `<select>` 展开后的 `<option>` 弹窗由操作系统直接渲染（Windows 下为系统级 ComboBox 弹出层），**浏览器 CSS 无法触及**；即使替换为自定义 DOM 组件，也需同步处理无障碍键盘操作（↑↓/Esc/Enter）、移动端选择器、触摸滚动、表单原生 submit 等问题，改造成本与收益不匹配
   - 经用户明确表示「那算了不改了」，已完整回滚：删除 `Select.tsx`、移除 `index.css` 新增的 `selectFadeIn` keyframes、撤销所有页面的 `import` 替换，回到原生 `<select>` + `.select-nice` 外框美化的方案

4. **构建验证**：前端 `npm run build` 0 error 0 warning（仅 chunk 大小提示，与本次改动无关）

## 3. 未完成内容

- 下拉展开弹窗（OS 原生控件）的美化：**无法实现**（CSS/浏览器限制，非工程问题），已与用户确认放弃，不在范围内。

## 4. 实现思路

**方案选型**：
- 方案 A（采用）：原生 `<select>` + `appearance:none` 去掉默认外观 + SVG 背景图自绘箭头 + 统一圆角/边框/焦点环。**优点**：零运行时、零无障碍风险、完全兼容移动端原生选择器、改动面小仅需加 className；**缺点**：无法改变展开弹窗的 OS 原生样式。
- 方案 B（评估后放弃）：自定义 DOM 下拉组件（button 触发 + 绝对定位面板）。**优点**：展开面板外观完全可控；**缺点**：需重写 ↑↓/Esc/Enter/Tab 键盘导航、触摸滚动、`form.submit()` 原生取值等大量边界，且移动端会丢失系统级滚轮选择器的交互质感。

**实施策略**：先走方案 A 快速落地；同步做方案 B 原型展示效果让用户判断；用户确认放弃方案 B 后立即完整回滚，避免留下半死不活的组件代码。

## 6. 影响范围

- **视觉层**：全站 14+ 原生下拉框的**外框视觉**统一为水墨风宣纸质感（圆角 8/10px、纸面底、湖蓝焦点环、自绘下箭头），与 Input/Button 组件风格一致，消除「默认浏览器丑框框」感
- **交互层**：无变化——展开/收起、键盘操作、移动端原生选择器均保持 OS 原生行为，无障碍零退化
- **构建层**：`npm run build` 通过，tsc 类型零错误
- **豁免模块**：SearchPage Chip 胶囊型 select、RegisterPage 学校选择框（带自定义 icon wrapper）两处保持原有独立样式，避免与特化设计冲突

## 8. 后续建议

1. **若后续仍希望美化展开弹窗**，建议在特定高价值页面（如发布页地点选择）引入「虚拟化搜索选择器」（类 `react-select` / Headless UI `Listbox`），与全站原生 select 并存——不要为了 14 个低频下拉框引入一整套自定义组件，避免「为了漂亮的弹窗牺牲全局无障碍一致性」。
2. **统一 vs.select 设计令牌**：目前各页面通过字符串字面量直接写 `select-nice` / `select-nice-sm`，后续可抽出 `const vs = { select: 'select-nice', selectSm: 'select-nice-sm' }` 集中管理，便于未来再迭代时一处改动全站生效。
3. **演示视频/截图补拍**：下拉外框美化属于可见但不可感的视觉微调整，建议在演示视频中给 1-2 个下拉聚焦态的特写镜头，让评委感知到设计语言的统一性。
