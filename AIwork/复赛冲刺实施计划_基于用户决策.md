## 3. T2：自动过期定时任务

### 实现方案

在 FastAPI `lifespan` 中启动一个 `asyncio` 后台循环，每 30 分钟扫描一次 `expired_at < now()` 的已发布帖子，将其状态转为 `expired`。

### 涉及文件

| 文件 | 操作 |
|------|------|
| `backend/app/main.py` | 修改（在 lifespan 中启动后台任务） |
| `backend/app/services/post_service.py` | 添加 `expire_expired_posts()` 函数 |
| 新增 `backend/app/tasks/__init__.py` | 后台任务目录 |
| 新增 `backend/app/tasks/expire_posts.py` | 过期扫描任务 |
| `backend/app/core/post_status.py` | 检查是否已有 expired 状态的流转入口 |

### 实现步骤

1. 在 `post_service.py` 中添加 `async def expire_expired_posts(db: AsyncSession)`：
   ```python
   async def expire_expired_posts(db: AsyncSession):
       now = datetime.utcnow()
       result = await db.execute(
           select(Post)
           .where(Post.status == "published", Post.expire_at < now, Post.is_deleted == False)
       )
       posts = result.scalars().all()
       for post in posts:
           post.status = "expired"
       await db.commit()
       logger.info(f"Expired {len(posts)} posts")
   ```

2. 在 `main.py` 的 `lifespan` 中启动后台循环：
   ```python
   async def expire_loop():
       while True:
           try:
               await expire_expired_posts(db)
           except Exception as e:
               logger.error(f"Expire loop error: {e}")
           await asyncio.sleep(1800)  # 30 分钟
   ```

3. 补充 pytest 测试用例

### 验收标准
- [ ] 系统运行 30 分钟后，过期帖子自动转为 expired 状态
- [ ] 日志中可看到过期扫描记录
- [ ] 对应 pytest 测试通过

## 8. T7：原生向量检索实现（增强项）

### 重要发现（2026-07-31 验证通过）

经实测，**openGauss 7.0.0-RC3 轻量版原生支持 DataVec 向量引擎**，无需安装 pgvector 扩展：

| 测试项 | 结果 |
|--------|------|
| `vector(384)` 数据类型 | ✅ 原生支持 |
| `<=>` 向量距离操作符 | ✅ 原生支持 |
| HNSW 向量索引 | ✅ 原生支持 |
| IVF 向量索引 | ✅ 原生支持 |

`CREATE EXTENSION vector` 会失败（扩展文件不存在），但这不影响——向量能力是内核级的，直接可用。

### 实现方案

**采用 AI Embedding + openGauss 原生向量检索** 方案：

1. **数据层**：在 `posts` 表添加 `embedding vector(384)` 列，存储 AI 生成的帖子内容向量
2. **索引层**：为 `embedding` 列创建 HNSW 索引，加速向量相似度查询
3. **生成层**：帖子发布/更新时，调用 AI 生成 embedding 并存入数据库
4. **检索层**：AI 搜索时，将用户查询转为 embedding，与帖子 embedding 计算向量距离
5. **融合层**：向量相似度 + 结构化条件（分类/时间/地点）+ 新鲜度 + 验证数，综合打分排序

### 实现步骤

#### Step 1：数据库迁移
```sql
ALTER TABLE posts ADD COLUMN embedding vector(384);
CREATE INDEX idx_posts_embedding_hnsw ON posts USING hnsw (embedding vector_l2_ops);
```

#### Step 2：模型更新
- `backend/app/models/post.py`：添加 `embedding` 字段
- `backend/alembic/`：新增迁移脚本

#### Step 3：Embedding 生成服务
- 新增 `backend/app/services/embedding_service.py`
- 调用 AI API 生成文本的 384 维 embedding
- 在帖子创建/更新时自动触发

#### Step 4：批量生成历史数据 embedding
- 编写一次性脚本为现有帖子生成 embedding
- `backend/scripts/generate_embeddings.py`

#### Step 5：改写 AI 搜索
- `backend/app/services/ai_search.py`：
  - `_compute_score` 调整为 4 维加权：
    - 向量语义相似度 35%（`embedding <=> query_embedding`）
    - 新鲜度 25%
    - 验证数 20%
    - 关键词相关度 20%
  - 新增 `_generate_query_embedding()` 函数
  - 新增向量检索降级逻辑（AI 不可用时退化为关键词搜索）

### 涉及文件

| 文件 | 操作 |
|------|------|
| `backend/app/models/post.py` | 添加 `embedding` 字段 |
| `backend/alembic/versions/` | 新增迁移脚本 |
