## 3. T2：自动过期定时任务

### 实现方案

在 FastAPI `lifespan` 中启动一个 `asyncio` 后台循环，每 30 分钟扫描一次 `expired_at < now()` 的已发布帖子，将其状态转为 `expired`。

### 涉及文件

| 文件 | 操作 |
|------|------|
| `backend/app/main.py` | 修改（在 lifespan 中启动后台任务） |
| `backend/app/services/post_service.py` | 添加 `expire_expired_posts()` 函数 |
| 新增 `backend/app/tasks/__init__.py` | 后台任务目录 |
| 新增 `backend/app/tasks/expire_posts.py` | 过期扫描任务 |
| `backend/app/core/post_status.py` | 检查是否已有 expired 状态的流转入口 |

### 实现步骤

1. 在 `post_service.py` 中添加 `async def expire_expired_posts(db: AsyncSession)`：
   ```python
   async def expire_expired_posts(db: AsyncSession):
       now = datetime.utcnow()
       result = await db.execute(
           select(Post)
           .where(Post.status == "published", Post.expire_at < now, Post.is_deleted == False)
       )
       posts = result.scalars().all()
       for post in posts:
           post.status = "expired"
       await db.commit()
       logger.info(f"Expired {len(posts)} posts")
   ```

2. 在 `main.py` 的 `lifespan` 中启动后台循环：
   ```python
   async def expire_loop():
       while True:
           try:
               await expire_expired_posts(db)
           except Exception as e:
               logger.error(f"Expire loop error: {e}")
           await asyncio.sleep(1800)  # 30 分钟
   ```

3. 补充 pytest 测试用例

### 验收标准
- [ ] 系统运行 30 分钟后，过期帖子自动转为 expired 状态
- [ ] 日志中可看到过期扫描记录
- [ ] 对应 pytest 测试通过

## 8. T7：向量检索实现（增强项）

### 方案分析

openGauss 7.0.0-RC3 轻量版**不支持 pgvector 扩展**，因此需要采用轻量方案。可选方案：

**方案 A：关键词权重向量化**
- 将帖子标题/内容按字分词，构建倒排索引
- 搜索时将查询分词后与帖子的关键词集合做交集/并集计算
- 用 Jaccard 相似度或 TF-IDF 计算相关度
- 优点：纯 SQL 实现，不依赖扩展
- 缺点：语义理解有限

**方案 B：AI Embedding + 数组存储**
- 调用 AI 生成帖子内容的 embedding（如 384 维）
- 存入 openGauss 的 `NUMERIC[]` 数组字段
- 搜索时调用 AI 生成查询 embedding，用 SQL 计算余弦相似度
- 优点：真正的语义搜索
- 缺点：每条帖子需要一次性 embedding 计算

**方案 C（推荐）：混合方案**
- 保持现有关键词+结构化条件检索为基础
- 在确定性打分阶段，增加一个"向量相似度"维度
- 用轻量级方法（如 jieba 分词 + 关键词频率）构建帖子的"语义指纹"
- 搜索时用相同方法构建查询的"语义指纹"，计算 Jaccard 相似度
- 优点：不依赖 AI 调用，零成本，可立即计算
- 缺点：不是真正的向量空间模型，但对校园场景足够

### 推荐实现（方案 C）

在 `ai_search.py` 的 `_compute_score` 函数中增加 4 个维度：

```python
# 当前权重：新鲜度 40% + 验证数 30% + 相关度 30%
# 调整为：新鲜度 30% + 验证数 20% + 关键词相关度 20% + 语义相似度 30%
```

语义相似度计算：
1. 预处理：jieba 分词 + 停用词过滤 → 帖子关键词集合
2. 构建帖子"关键词指纹"（每个关键词的 TF-IDF 权重）
3. 查询同理构建"查询指纹"
4. 计算加权 Jaccard 相似度

### 涉及文件
- `backend/app/services/ai_search.py`（修改 `_compute_score` 函数，添加 `_compute_semantic_similarity` 函数）
- 可能需要在 `requirements.txt` 中添加 `jieba` 依赖
- 测试文件补充向量/语义相似度测试

### 验收标准
- [ ] AI 搜索对同义表述（"哪里能打印" vs "打印店在哪"）能返回相似结果
- [ ] 打分仍为确定性（同输入同输出）
- [ ] 不增加 AI 调用次数（零额外成本）
