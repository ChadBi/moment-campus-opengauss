# 任务报告：小程序注册表单与地图抽屉交互修复

## 1. 任务概述

修复微信小程序注册页输入框超出卡片边界、表单被拆成多个卡片的问题，并按地图软件的交互方式调整地点详情抽屉：地点首次点击显示半屏，半屏状态下整张抽屉随手势移动，上滑后展开为全屏，展开后的内容使用同一个滚动区域。

## 2. 已完成内容

- 注册/绑定页的昵称、学校、邮箱、密码和确认密码统一放入一个连续的表单卡片。
- 表单容器和输入控件统一使用 `box-sizing: border-box`、`width: 100%`、`max-width: 100%` 与 `min-width: 0`，并由父容器裁剪异常溢出。
- 地图抽屉的触摸事件从顶部拖拽条移到整个抽屉容器，半屏时记录起点、实时计算并渲染 `translate3d` 位移。
- 半屏上滑达到阈值后切换全屏并清零位移；轻微拖动回弹，向下拖动达到阈值时关闭地点面板。
- 全屏状态才启用内部 `scroll-view`，标题、评分、摘要、相关帖子和详情按钮仍处于同一内容流，不再出现固定外壳包裹局部帖子滚动的结构。
- 切换学校、切换地点和关闭地点面板时清除拖拽状态与偏移，避免旧手势残留。

## 3. 未完成内容

- 尚未在真实微信手机上验证不同屏幕尺寸下的拖拽阻尼和手势阈值。
- 微信开发者工具 CLI 的元素触摸参数在当前 PowerShell 调用中存在 JSON 转义问题，本轮使用运行时页面方法合成触摸事件验证状态转换；需要在自动化连接恢复后补一次真实坐标滑动 E2E。

## 4. 实现思路

注册页只保留一个表单分组，避免通过多个圆角卡片模拟分组而导致视觉断裂。地图抽屉采用“状态高度 + 手指位移”的组合：半屏时外层容器的位移由触摸距离直接驱动，松手后按阈值决定展开、回弹或关闭；全屏后交给唯一的 `scroll-view` 负责内容阅读，外层手势处理器不再抢占滚动事件。

## 6. 影响范围

仅影响小程序注册/绑定页的表单布局和地图地点详情抽屉的手势、滚动与状态样式；不改变地点接口、相关帖子查询、学校租户、地图坐标、AI 摘要或 Web 端逻辑。

## 7. 测试与验证

- `miniprogram npm run typecheck`：通过。
- `miniprogram npm run test:format`：通过。
- 微信开发者工具 `compile_wxml` / `compile_wxss`：注册页和地图页均通过。
- 模拟器注册页截图确认所有输入框位于同一个连续白色卡片内，右侧没有越界。
- 模拟器地图体育馆面板截图确认半屏状态和全屏状态均为一个连续抽屉；地点真实相关帖子仍显示 1 条。
- 运行时调用半屏抽屉触摸处理器：上滑过程中 `sheetDragOffset=-316`，结束后 `sheetExpanded=true` 且偏移归零。
- 全屏地点 `scroll-view` 的运行时内容高度为 632，可视宽度为 372，具备继续阅读内容的滚动空间。
