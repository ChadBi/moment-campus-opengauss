# 任务报告：游客学校切换与发帖入口

## 1. 任务概述

根据产品规则调整小程序游客行为：未登录用户切换学校只影响本地浏览租户，不应触发账号学校绑定；未登录用户打开发布页时弹窗提醒登录并返回首页。

## 2. 已完成内容

- 学校选择页区分游客与登录用户：游客直接将所选学校写入 `campusStore` 和本地 `school_code`；登录用户仍调用 `joinSchool` 并同步账号学校。
- 发布页在 `onShow` 立即检查登录态；游客会看到登录提醒，确认后通过 TabBar 导航返回首页，不停留在发布表单。
- 保存草稿和提交审核入口继续使用 `requireLogin` 作为防御性兜底，未登录时不会创建帖子。

## 3. 未完成内容

- 微信开发者工具的局部 WXML/WXSS 编译请求遇到微信侧 `-80408`（60 次/分钟）频率限制，本轮未取得局部编译结果。
- 未执行需要当前开发者工具会话的 automator 输入操作；代码静态链路已检查。

## 4. 实现思路

1. 在学校确认逻辑中读取 `authStore` 登录态。
2. 游客分支从已加载学校目录取出选中学校，清理旧学校缓存后调用 `campusStore.setSchool`，不访问 `/schools/{code}/join`。
3. 登录分支保留原有加入学校、获取当前学校和更新用户 `school_id` 的流程。
4. 发布页在打开时对游客进行一次登录提示并返回首页；提交动作仍保留 `requireLogin` 防止绕过页面入口直接调用写操作。

## 6. 影响范围

- 游客切换学校后，首页、地图、搜索和发布页使用新的本地浏览学校；不会产生会员关系或修改用户绑定学校。
- 登录用户的学校切换和跨校只读权限不变。
- 游客进入发布页会被友好提示并返回首页；未登录用户仍不能保存草稿、提交审核或绕过后端权限。
