# 任务报告：微信小程序全功能对等与跨端统一登录方案补充

## 1. 任务概述

根据用户确认，将微信小程序目标从“精简用户闭环、邮箱登录、定位后置”调整为“与 Web 用户端功能完全对等，微信一键登录和实时定位均为必要功能”，并补充 Web 与小程序统一账号、独立会话和冲突处理方案。

## 2. 已完成内容

- 重新核对当前 Web 用户端路由、services、User 模型、JWT refresh 和 logout 实现。
- 确认跨端一致性应以相同 `users.id` 为核心，而非共享同一 Token。
- 设计邮箱密码、微信小程序和未来网站微信 OAuth 多身份绑定模型。
- 设计 `auth_sessions` 设备会话、refresh token 哈希轮换、单端退出和全部撤销方案。
- 补充已有 Web 用户绑定、新微信用户创建、设置 Web 登录方式及网站微信登录三类流程。
- 将实时定位改为 P0，明确 GCJ-02、类目/接口申请、隐私授权和拒绝授权降级。
- 将小程序范围调整为所有 Web 用户端能力，并增加共享契约、能力矩阵和双端 E2E 门禁。
- 更新 `docs/34_微信小程序接入评估与实施准备报告.md` 和 `TODO.md`。

## 4. 实现思路

将 User 从“邮箱密码账号”提升为唯一业务主体。邮箱密码、微信 OpenID/UnionID 都只是可绑定的登录身份，登录成功后统一签发 `sub=users.id` 的项目 JWT。Web 和小程序各自创建可撤销的 `auth_sessions`，因此既能共享业务账号和数据，又能独立刷新、退出和管理设备。

已有 Web 用户首次进入小程序时必须显式验证原账号并绑定，禁止按昵称、手机号或邮箱文本自动合并。微信新用户可创建纯微信账号，之后通过已验证邮箱或网站微信 OAuth 获得 Web 登录方式。

## 7. 测试与验证

已执行静态核对：

- 当前 Web 用户端路由与 service 模块清单。
- 当前 User 的 `email/password_hash` 非空约束。
- 当前 refresh JWT 无 `sid/jti`、无服务端 session 表。
- 当前 logout 只返回成功，不能撤销服务端 refresh token。
- 微信官方小程序登录、code2Session、UnionID 和网站应用 OAuth 规则链接可访问。
