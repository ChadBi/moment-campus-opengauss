# 任务报告：小程序密码输入框默认隐藏 + 眼睛图标切换交互修复（登录/注册/找回密码）

## 1. 任务概述

解决用户反馈的两个问题：
1. 密码输入框无法以"默认隐藏小圆点、点击按钮可切换显示明文"的正确交互显示（此前错误写法导致密码始终明文显示，完全裸露用户密码，存在安全问题）。
2. 辅助确认微信登录是否有账号绑定（给出明确说明，消除信息不透明）。

本次密码框修复覆盖小程序 3 个页面共 5 个密码输入框：
- 登录页（pages/login/login）- 1 个
- 注册页（pages/register/register）- 2 个（密码 + 确认密码）
- 找回密码页（subpackages/pages/forgot-password/forgot-password）- 2 个（新密码 + 再次输入新密码）

## 2. 已完成内容

### 2.1 核心问题定位与修复方案落地

- 确认微信小程序 `<input>` 组件不推荐使用 `type="password"` 属性，而应使用 `type="text"` + **布尔属性** `password="{{true/false}}"` 通过数据绑定动态控制显示模式
- 明确显示/隐藏交互的视觉符号：默认显示小圆点（password=true + 闭眼 eye-off 图标）；点击后切换为明文（password=false + 睁眼 eye 图标）

### 2.2 登录页修复（pages/login）

- **逻辑层 login.ts**：新增 `showPassword: false`（默认隐藏，安全默认值）数据字段；新增 `toggleShowPassword()` 方法（对 showPassword 做布尔取反并 setData）
- **模板层 login.wxml**：把密码输入框的 `type="password"` 改为 `type="text"`；新增属性 `password="{{!showPassword}}"`；在原 input-wrap 内最后一个位置插入 `.pwd-toggle` 容器，内嵌 `<icon>` 组件通过 `name="{{showPassword ? 'eye-off' : 'eye'}}"` 动态切换图标；并绑定 `bindtap="toggleShowPassword"` + `hover-class="pwd-toggle-hover"` + `hover-stay-time="80"` 增加触摸反馈
- **样式层 login.wxss**：新增 `.pwd-toggle`（56rpx×56rpx 圆形、flex 居中、margin-left 与图标拉开距离）与 `.pwd-toggle-hover`（半透明湖蓝背景作为 hover/点击反馈）两套选择器

### 2.3 注册页修复（pages/register）

- **逻辑层 register.ts**：新增 `showPassword: false` + `showConfirmPassword: false` 两个独立状态（密码和确认密码是两个不同字段，必须分开管理避免联动错误）；新增 `toggleShowPassword()` 和 `toggleShowConfirmPassword()` 两个独立方法
- **模板层 register.wxml**：把两处密码 Input（密码、确认密码）从 `type="password"` 改为 `type="text"`；分别加上 `password="{{!showPassword}}"` 与 `password="{{!showConfirmPassword}}"`；外层改用 `.pwd-input-wrap` 容器包裹（flex 横向布局），每个密码框右侧独立嵌入 `.pwd-toggle` 眼睛切换按钮（图标尺寸 28rpx，比登录页略小以匹配注册页的紧凑视觉）
- **样式层 register.wxss**：新增 `.pwd-input-wrap`（88rpx 高度，与原 input-wrap 背景/边框/圆角等设计 token 完全一致）、`.pwd-input`（flex:1 透明背景）、`.pwd-toggle`、`.pwd-toggle-hover`

### 2.4 找回密码页修复（subpackages/pages/forgot-password）

- **逻辑层 forgot-password.ts**：新增 `showNewPassword: false` + `showConfirmPassword: false` 两字段；新增对应 `toggleShowNewPassword()` / `toggleShowConfirmPassword()`
- **模板层 forgot-password.wxml**：新密码和再次输入新密码两个 Input 都改为 `type="text"` + `password="{{!showXxx}}"` 属性绑定；在每个 `.input-wrap` 右端插入 `.pwd-toggle` 眼睛切换按钮（32rpx 图标尺寸与登录页保持一致）
- **样式层 forgot-password.wxss**：补录 `.pwd-toggle` / `.pwd-toggle-hover` 样式（与登录页完全同构，避免子包页面引用未定义的样式类导致 UI 异常）

### 2.5 图标组件补齐

- 在 `components/icon/icon.ts` 的 `ICON_PATHS` 映射中新增 `'eye-off'` 图标（完整 SVG path 来自 lucide 规范，4 段 path + 1 条对角线删除线），与原有 `'eye'` 图标配对，保证密码显示状态切换时两个图标都能正常渲染，不会出现"切到隐藏态后图标变成空白"

### 2.6 微信登录绑定状态的说明

针对"帮我看看当前微信登录是否有账号绑定"问题：

- 后端 `/auth/wechat/exchange` 接口逻辑已明确：查询 `user_auth_identities` 表中 `identity_type='wechat_miniprogram'` AND `identity_key=openid`（即当前微信小程序唯一身份标识）且 `is_deleted=false` 的记录
  - **若记录存在** → 返回 `status=authenticated`，同时返回 `access_token + refresh_token + user`，前端直接落登录态并跳个人中心（说明微信已绑定，下次自动登录）
  - **若记录不存在** → 返回 `status=binding_required`，同时返回 `binding_ticket`（30 分钟有效一次性 token），前端跳"注册/绑定已有账号"流程页（说明微信未绑定任何此刻校园账号，需用户下一步填写教育邮箱/密码注册或绑定已有账号）
- 接口行为已在 `wechat_auth.py` 完整实现并经 17 项 pytest 回归验证（详见 TODO.md 2026-08-08「微信登录链路规范化」条目）；无后端代码需要修改

## 4. 实现思路

### 4.1 关键技术点（微信小程序密码输入框的"坑"）

- **错误写法**（原问题）：`<input type="password" />`。微信小程序中此写法在部分版本/工具中被底层降级当作"文本输入框"渲染，导致密码直接明文显示——等于用户输入的密码裸奔在屏幕上，极不安全。
- **正确写法**（修复后）：`<input type="text" password="{{布尔值}}" />`。小程序 Input 组件的布尔属性 `password` 才是官方推荐的控制方式，优先级高于 `type="password"`。
- 为何 `password="{{!showPassword}}"`？因为 `showPassword=false`（默认）时用户的直觉是"看不到密码"，所以 password 属性应该为 true（隐藏）。用"取反"建立直觉映射，避免数据字段和显示行为背道而驰。

### 4.2 三页面统一模式（避免以后再踩坑）

在 3 个页面严格采用同一模式：
1. `data.xxx = false`（默认隐藏）作为安全默认值
2. `toggleShowXxx()` 方法：只做布尔取反 + setData
3. `<input type="text" password="{{!xxx}}" />` 组件绑定
4. 右侧固定 `56rpx` 圆形眼睛图标容器 + hover 反馈
5. 图标条件渲染：`{{xxx ? 'eye-off' : 'eye'}}`

注册页因两个密码框共用样式规范，抽象为 `.pwd-input-wrap` / `.pwd-input` / `.pwd-toggle` 三层选择器以便后续维护一致性。

### 4.3 与原有设计系统的视觉兼容性

所有新增 class 的颜色（`rgba(23,77,94,0.08)` 湖蓝反馈）、尺寸（88rpx 输入框高度）、圆角（`var(--radius-md)`）均复用项目既有的设计 token，不引入新色值/字号，保证修改后与整个小程序水墨风主题保持一致。
