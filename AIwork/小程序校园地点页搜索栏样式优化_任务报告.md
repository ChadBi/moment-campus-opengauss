# 任务报告：小程序校园地点页搜索栏样式优化

## 1. 任务概述

用户反馈：小程序「校园地点」页面（`subpackages/pages/locations/locations`）的搜索栏"有点看不清吧"，希望优化。

从用户提供的截图可以看到：搜索图标和 placeholder 文字几乎与页面背景色混为一体，没有明显的输入框外框和背景，视觉上没有"这是一个可点击/可输入的搜索框"的形态认知。

目标：让搜索栏与页面背景形成足够对比度，一眼能识别为搜索输入框。

## 2. 已完成内容

### 2.1 根因定位

`subpackages/pages/locations/locations.wxml` 第 12-15 行：
```xml
<view class="location-search-wrap">
  <icon name="search" size="28rpx" color="#6a7d81" />
  <input placeholder="搜索地点名称、描述、楼栋或楼层" placeholder-class="ph" />
</view>
```
搜索容器引用了 `location-search-wrap` class，但对应的 `locations.wxss` 中**从未定义过该选择器**（通过 `grep location-search-wrap miniprogram` 只匹配到 WXML 引用、零条样式）。

这导致：
1. `wrap` 没有 `background / border / border-radius / padding / height`，完全是"裸露"的一行元素，和页面背景糊在一起；
2. 图标颜色 `#6a7d81`（muted）与 mist 背景对比弱；
3. 输入框也没有高度、字号约束，看起来像一行默认文字而不是输入框。

### 2.2 WXSS：补齐搜索框样式

在 `locations.wxss` 中新增一个独立的搜索框样式区块（按"最小 diff"策略，只补缺失样式，不触动现有任何选择器）：

| 选择器 | 说明 | 关键值 |
|---|---|---|
| `.location-search-wrap` | 搜索容器主体，形成清晰的胶囊输入框形态 | `height: 88rpx; padding: 18rpx 22rpx; background: var(--paper); border: 1rpx solid rgba(23,77,94,0.18); border-radius: 999rpx; box-shadow: 0 8rpx 22rpx rgba(21,38,41,0.06); gap: 12rpx; margin: 16rpx 0 22rpx` |
| `.location-search-wrap:focus-within, :active` | 聚焦/按压态：描边变湖蓝 + 阴影加深 | `border-color: var(--lake); box-shadow: 0 10rpx 26rpx rgba(47,127,143,0.14)` |
| `.location-search-input` | 输入框字体 | `flex:1; font-size:28rpx; color:var(--ink); font-weight:500; height:100%; line-height:1` |
| `.location-search-ph` | 占位文字（比 ink-disabled 清晰但仍保留占位语义） | `color:#8a9a9e; font-size:26rpx; font-weight:400` |
| `.location-select-hint` | 顺带微调 select 模式提示间距 | `margin-bottom:10rpx` |

### 2.3 WXML：同步加强对比度

同时对 `locations.wxml` 搜索栏节点做最小量增强：

| 属性 | 原值 | 新值 | 说明 |
|---|---|---|---|
| `<icon>` size | `28rpx` | `30rpx` | 放大 2rpx，提高可见性 |
| `<icon>` color | `#6a7d81`（muted） | `#174d5e`（湖蓝主色） | 与主色系统一，对比度显著提高 |
| `<input>` class | 无 | `location-search-input` | 绑定上面的字号/字重/颜色样式 |
| `<input>` placeholder-class | `ph`（全局 `--ink-disabled` 过淡） | `location-search-ph`（#8a9a9e） | 占位符更清晰 |
| `<input>` confirm-type | 无 | `search` | 键盘回车按钮显示"搜索"而非"换行"，语义更准确 |

## 4. 实现思路

**遵循"最小 diff"经验教训**：经验库 `Experience ID 134550` 明确指出——像素级 UI 对齐/优化场景必须避免"用 Write 全量覆盖 WXML/WXSS"，否则容易破坏已有交互并回退。所以本次严格遵守：

1. 不做结构改动，保持搜索栏仍在 `.page-header` 之后、`.list-area` 之前的原位；
2. 只用 `Edit` 增量新增样式和改少量 icon/input 属性，不触动列表/详情/表单/资料等其他区块；
3. WXSS 中只加新选择器，不修改任何已有选择器属性（甚至不删除未被使用的 `.ph` 复用）。

**颜色选择策略**：保持品牌湖蓝 `#174d5e / var(--lake)` 为主视觉锚点——搜索图标用湖蓝、focus/active 边框用湖蓝，与页面顶部"校园地点"标题的 `var(--lake)` 呼应；背景 `var(--paper)` 纯白 + 淡湖蓝描边 + 淡阴影，形成"浮在 mist 之上"的清晰输入盒。

## 6. 影响范围

- **唯一受影响的页面**：`subpackages/pages/locations/locations`（校园地点页）搜索栏可见性；其他页面和逻辑完全不受影响。
- **不影响**：搜索功能逻辑（`onKeywordInput` handler 未改，仍走原有关键词过滤）；地点卡片/详情/评分/资料表单等；地图页；首页；Web 端；后端；数据库。
- **样式变量兼容**：WXSS 用了 `var(--paper)` / `var(--lake)` 等已存在的 CSS 变量，即使主题切换也能保持一致性（不写死硬编码白/蓝除了颜色语义必要的描边值）。

## 8. 后续建议

1. **加右侧清空按钮**（建议立即跟进，工作量极小）：当 `searchKeyword` 非空时，在搜索框右侧显示一个小 `x` 图标，点击后清空关键词并恢复完整列表；当前输入后只能手动删除，效率偏低；
2. **扩展到所有搜索框统一风格**：检查小程序其他页面（如 SearchTab、发布页筛选、选择器弹层内部的搜索）是否也存在遗漏样式的搜索框，统一套用 `.search-wrap` 通用胶囊样式，形成 UI 一致性；
3. **聚焦态 placeholder 变浅**：可选增强——用户 focus 后 placeholder 从 `#8a9a9e` 变为 `--ink-disabled`，进一步传达"已进入输入状态"；当前版本 focus 只改变边框和阴影，视觉已足够；
4. **关键字高亮**：列表卡片中命中搜索关键词的部分加粗/湖蓝高亮（如搜索"图书馆"后，卡片中"图书馆"三个字变湖蓝），能进一步提升可搜索感；
5. **Android 真机字体微调**：在鸿蒙/Android 真机型上验证 placeholder 字重 400 是否与微信默认风格一致，避免两端视觉差异（目前模拟器 iOS 外观正常）。
