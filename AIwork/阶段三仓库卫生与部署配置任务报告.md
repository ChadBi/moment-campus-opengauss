## 4. 实现思路

### 仓库卫生策略
- **git mv 而非删除**：verify_*.py 脚本对 E2E 回归验证仍有价值，移到 `backend/tests/manual/` 保留 git 历史 + 保留可执行性 + 不被 pytest 自动收集
- **.gitignore 防御**：新增 `/verify_*.py` 规则，从源头杜绝根目录再次堆积同类脚本
- **本地删除而非 git rm**：102 个调试文件均已被 .gitignore 覆盖（未 tracked），删除本地文件即可，无需走 git 流程

### Docker 构建上下文过滤策略
- 双 Dockerfile 均使用 `COPY . .`，存在三类风险：
  1. 镜像体积膨胀（node_modules / .venv / .git 动辄数百 MB）
  2. 密钥泄露（.env / .env.local 进入镜像层）
  3. 测试与生产混淆（tests / e2e / playwright-report 进入镜像）
- 通过 .dockerignore 在构建上下文阶段过滤，比在 Dockerfile 内逐条 `RUN rm` 更高效（不进入构建上下文 = 不进入镜像层）

### AI_* 模板补齐策略
- 与 `backend/app/config.py` 中的 Settings 类逐字段对齐（9 项 AI_* 全部覆盖）
- 默认值与 config.py 一致（AI_PROVIDER=mock / AI_MODEL=gpt-4o-mini 等），确保无 .env 时也能正常启动
- 注释说明各项含义、推荐值、安全注意事项（密钥不进前端/日志/git）

### authApi.logout 接入策略
- **先调后端，再清本地**：让后端有机会失效 refresh token / 写黑名单
- **失败不阻塞**：网络异常/后端宕机时仍能本地登出（用户不至于卡死在登录态）
- **保持 api.ts 拦截器行为不变**：401 拦截器中 `useAuthStore.getState().logout()` 直接清本地是合理的（后端已拒绝 token，无需再调 /auth/logout）
