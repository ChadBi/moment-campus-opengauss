# 任务报告：微信小程序本地环境路由切换

## 1. 任务概述

解决小程序地点详情接口与本地 Web 后端不一致的问题：开发者工具先使用本地后端验证完整详情链路，体验版和正式版继续保留线上地址。

## 2. 已完成内容

- `miniprogram/config/env.ts` 增加微信运行版本到 API 环境的自动映射。
- 开发者工具 `develop` 使用 `http://localhost:8000`。
- 微信体验版 `trial` 使用 `https://campus.chaina1.com`。
- 微信正式版 `release` 使用线上生产地址。
- 保留 `__ENV__` 显式覆盖能力，便于特殊测试或发布前固定环境。

## 3. 未完成内容

- 线上体验环境仍未部署地点详情、评价和摘要路由；上传体验版前需要完成后端部署。

## 4. 实现思路

优先读取构建标记 `__ENV__`；没有显式标记时读取 `wx.getAccountInfoSync().miniProgram.envVersion`，按照开发、体验、正式三种微信运行版本选择 API 和图片域名。读取账号信息失败时默认本地，避免开发者工具误连旧线上服务。

## 5. 修改文件

- `miniprogram/config/env.ts`
- `docs/小程序契约矩阵与重构执行记录.md`
- `TODO.md`

## 6. 影响范围

影响小程序请求层、图片地址解析、学校/地点/帖子等所有 API 调用的环境地址选择；不改变接口路径、租户头或业务数据结构。

## 7. 测试与验证

- `npm run typecheck` 通过。
- `npm run test:format` 通过。
- 微信开发者工具刷新后，网络请求已切换为 `http://localhost:8000/api/v1`。
- 本地 `GET /locations/6` 和 `GET /locations/6/reviews?page=1&page_size=20` 均返回 200，地点详情页面可读取评分和评价列表。
- 线上 OpenAPI 仍仅提供地点列表路由，详情路由缺失的事实已保留记录。

## 8. 后续建议

后端部署到体验环境并重启服务后，用上传的体验版再次验证 `trial` 自动切换；上线正式版前确认 `release` 指向生产域名，并补跑地点详情、评价、摘要和资料提议 E2E。
