## 4. 实现思路

### 4.1 链路检查三步法（参考过往图文流经验，避免路径拼接问题）

按上传→入库→读回→渲染 4 段分段走查，每段明确「输入→输出→契约」：

| 阶段 | 输入 | 输出 | 契约 |
|---|---|---|---|
| 上传 | 用户选择的 File 对象 | `{ url, thumbnail_url, filename, file_size }` | url 形态固定为 `/uploads/<uuid>.<ext>`，thumbnail_url 为 `/uploads/thumb_<uuid>.<ext>` |
| 写入 DB | `PostCreate.image_urls: str[]` | `PostImage` 多行按 idx 顺序写入 | sort_order = idx，与前端选择顺序一致 |
| 列表回读 | Post.post_images | `PostListResponse.cover_image: str?` | 取按 sort_order 排好序的第 0 张 |
| 详情回读 | Post.post_images | `PostResponse.images: PostImageBrief[]` | 按 sort_order 升序返回 |
| 前端渲染 | PostResponse.images | 主图轮播 + 缩略图带 | 缩略图缩略优先 thumbnail_url，错误时 ImageIcon 占位 |

### 4.2 Bug 修复策略（小而稳，不引入新依赖）

- **Bug 1：列表 cover_image 顺序错位** → 只需在 posts.py 列表循环内，先 `sorted(post.post_images, key=lambda i: i.sort_order)`，再取 `[0].image_url`，与详情页 L303 同口径；无需改 Schema，无外部影响
- **Bug 2：缩略图带宽浪费** → `img.thumbnail_url || img.image_url`，缩略缩略不存在时自动回退原图，不改变老数据/老行为
- **Bug 3：加载失败破图显示** → 用 `brokenImgUrls: Set<string>`（Map 不可序列化，React 里 Set 用 React state setter `new Set(prev).add(src)` 保证引用更新）触发 re-render，渲染分支切到 ImageIcon，比原生 JS 改 DOM 安全

## 8. 后续建议

1. **卡片缩略图布局扩展**：HomePage / 搜索页 / 推荐页的信息流卡片目前纯文字，`cover_image` 字段已在后端填充，建议后续产品迭代时，给卡片加左侧 64×64 或顶部 4:3 封面缩略图缩略，提升图文内容 CTR 和视觉吸引力（与详情页缩略图口径一致：`post.cover_image || <ImageIcon>`）
2. **上传组件预先生成缩略图**：PostForm 现在图片预览用的是原图 image_url，建议编辑态和图片预览条里也用 `img.thumbnail_url || img.image_url`（与详情页缩略图同口径），减少编辑页的大图片加载开销；目前只在详情页做了这一步
3. **PostImage 补充 thumbnail_url 写库**：当前 upload 接口返回了 thumbnail_url，但 `PostCreate → PostImage` 创建时**没有把 thumbnail_url 写入 PostImage.thumbnail_url 列**（只写了 image_url）！这导致详情页 `img.thumbnail_url` 目前永远是 `null`，只能回退原图。建议：`PostForm` 上传时把 `{ url, thumbnail_url }` 两个字段一起存（需要把 formData.image_urls 从 `string[]` 改成 `{image_url: string, thumbnail_url: string}[]` 新类型，同步升级 `PostCreate.image_urls` Schema）；这个建议优先级高——目前修复后的缩略图虽然逻辑正确，但因 DB 里 thumbnail_url 全是空，实际缩略带宽优化未生效。
4. **评论 / 评价图片链路扩展**：本次只检查了 Post 的图片，评论（Comment）和地点评价（LocationReview）目前没有图片上传功能，但如果未来产品要加「评论配图」「评价配图」，直接复用本任务的 PostImage + upload + 脱敏三段式结构即可：① 新增 CommentImage / ReviewImage 模型；② 上传还是走 `/upload/image`；③ 渲染时 thumbnail_url 优先 + onerror fallback 的 pattern 直接复用 PostDetail 的代码
5. **部署环境的 uploads 持久化**：如把后端部署到容器或 systemd，**务必保证 `backend/uploads/` 目录挂载到独立数据卷（Docker Volume）或固定路径**，不能被发布覆盖（参考 370815 失败经验）。本项目 main.py 里使用的是相对路径 `./uploads`，等价于 `backend/uploads/`，部署时建议覆盖到项目外的固定绝对路径并设环境变量 `UPLOAD_DIR=/srv/moment/uploads`。
