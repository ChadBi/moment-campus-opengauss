# 任务报告：自动过期定时器三十分钟周期统一

## 1. 任务概述

按冻结实施计划将 `moment-expire-posts.timer` 从每 5 分钟触发统一为系统启动后 5 分钟首次触发、此后每 30 分钟触发；同步 README、现行 docs、作品帖与部署说明口径，并以先 RED 后 GREEN 的静态测试证明 systemd unit 周期配置。

## 2. 已完成内容

- 将 timer 的 `OnCalendar=*:0/5` 改为 `OnBootSec=5min` 与 `OnUnitActiveSec=30min`，保留 `Persistent=true` 和 service 绑定。
- 更新 timer 描述，明确 worker 每 30 分钟运行。
- 新增 systemd timer 静态测试，断言首次启动延迟、后续周期、移除旧 `OnCalendar`、持久化和 service 绑定。
- 同步 README 两处、作品帖、社区治理文档、技术架构文档、运行与开发环境说明、项目演示流程指南中的现行调度口径。
- 扫描 README、作品帖、docs 与 timer，确认不存在自动过期任务“每 5 分钟”及 `OnCalendar=*:0/5` 的现行残留。

## 3. 未完成内容

- 未在目标 Linux 生产服务器安装 unit、执行 `systemctl daemon-reload` 或观察真实 timer 调度；本次仅完成本地静态配置验证。
- 按用户明确要求，未修改小程序、`TODO.md`，未执行 Git 提交。

## 4. 实现思路

先从冻结计划确认精确配置为 `OnBootSec=5min`、`OnUnitActiveSec=30min`、`Persistent=true`。随后先添加读取 unit 文件的 pytest 静态契约测试，在旧配置上运行并取得预期失败；再修改 timer 及现行文档，使同一测试转为通过。最后运行自动过期相关 pytest，并在 WSL 中使用 `systemd-analyze verify` 验证 unit 语法。由于生产 `ExecStart` 路径在本机不存在，验证时仅在 `/tmp` 临时副本中将 `ExecStart` 替换为 `/bin/true`，未改动仓库 service 文件。

## 6. 影响范围

- 生产环境自动过期 worker 的调度频率由每 5 分钟降低为启动后 5 分钟首次运行、此后每 30 分钟运行。
- 到期帖子最迟可能在下一次 30 分钟周期中被处理；帖子过期业务逻辑、锁、租约、幂等通知和权限均未修改。
- README、作品展示与现行架构/运行/治理/演示文档统一采用同一调度口径。
- 不影响 Web、小程序、API 契约、数据库 Schema 和部署脚本安装流程。

## 7. 测试与验证

- RED：使用 `backend/.venv/Scripts/python.exe -m pytest tests/test_systemd_units.py -q`，结果 `1 failed`；失败点为旧 unit 缺少 `OnBootSec=5min`，符合预期。
- GREEN：修改 unit 后重复同一命令，结果 `1 passed in 2.93s`。
- 相关 pytest：运行 `backend/.venv/Scripts/python.exe -m pytest tests/test_systemd_units.py tests/test_gov_02_expire.py -q`，结果 `17 passed in 19.27s`。
- systemd 直接验证：WSL 中对仓库 unit 执行 `systemd-analyze verify`，可解析 unit，但因目标部署路径 `/opt/moment-campus/backend/.venv/bin/python` 在本机不存在而返回失败；同时 WSL 挂载盘权限映射产生 executable/world-writable 提示。
- systemd 可行静态验证：复制两个 unit 到 WSL `/tmp`、设为 `0644`，仅将临时 service 副本的 `ExecStart` 替换为 `/bin/true` 后运行 `systemd-analyze verify`，退出码为 0；输出中的 netplan 权限与旧版 systemd 不识别 snapd `RestartMode` 均来自 WSL 系统 unit，不是本项目 unit。
- 残留扫描：README、作品帖、docs 中未发现自动过期 timer 每 5 分钟口径；timer 中未发现 `OnCalendar=*:0/5` 或 `Every 5 Minutes`。
- VS Code 诊断：`backend/tests/test_systemd_units.py` 无诊断问题。
- 未运行前端构建或端到端浏览器测试：本次只修改 systemd unit、静态测试和文档，不涉及前端/小程序或用户交互链路。

## 8. 后续建议

部署到目标 Linux 后执行 `systemctl daemon-reload`、重启 `moment-expire-posts.timer`，通过 `systemctl list-timers moment-expire-posts.timer` 确认首次与后续触发时间，并使用 `journalctl -u moment-expire-posts.service` 保留至少一次真实调度成功证据。
