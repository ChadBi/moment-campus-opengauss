# 任务报告：登录与校园认证统一教育邮箱

## 1. 任务概述

消除"登录邮箱 ≠ 认证邮箱"的割裂体验，将小程序与 Web 端的登录、注册、校园认证统一到**同一条教育邮箱**。统一心智：登录邮箱 = 教育邮箱 = 认证邮箱（同一字段 `email`）。认证 = 向当前登录邮箱发验证码，验证"邮箱确实属于你"。

依据：用户决策（统一教育邮箱）；演示账号改教育邮箱但加 example 避免真实发邮；只留一个邮箱字段；不需要学号。当前处于开发阶段、无老用户，可做彻底收敛、无需向后兼容。

## 2. 已完成内容

- **后端字段收敛**：删除 `users.campus_email`、`users.student_id` 两列，保留 `campus_verified`/`campus_verified_at`；新增 Alembic 迁移。
- **认证接口收敛**：`send_campus_verify` 去掉 `student_id`/`campus_email` 入参，直接用登录邮箱校验允许域名并发码；`confirm` 同理仅需 `token`/`code`。
- **Web 端收窄教育邮箱**：注册页邮箱域名命中目标学校允许域名校验；`CampusVerifyCard` 移除学号输入框，认证邮箱只读展示登录邮箱。
- **小程序端收敛**：我的页认证 UI 移除学号/校园邮箱输入，改为只读展示登录邮箱 + 发码；auth 服务与类型定义移除冗余字段。
- **seed 演示数据适配**：演示账号改教育邮箱并加 example 域名，各校 `addl_domains` 追加 example 域。
- **测试与门禁**：认证测试 8 项通过；前端 build 通过；小程序 typecheck 通过。

## 3. 未完成内容

- 未做后端全量回归测试（用户明确要求跳过）。

## 4. 实现思路

- **字段收敛**：`campus_email` 与 `email` 语义相同、`student_id` 不再需要，直接删列，避免冗余数据。
- **认证用登录邮箱**：因为登录邮箱即教育邮箱，发码与校验都围绕 `current_user.email`，无需再收集额外信息。
- **产品收窄在前端**：后端 `register` 不强硬限制域名（保留微信临时邮箱/测试建号能力），教育邮箱约束下沉到 Web/mp 注册页前端校验。
- **演示安全**：演示账号用 `example.学校域名` 并加入允许域名，能过校验但 example 域不真实发邮，避免测试误发邮件。
