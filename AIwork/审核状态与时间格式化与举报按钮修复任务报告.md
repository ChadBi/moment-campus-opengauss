# 任务报告：审核状态与时间格式化与举报按钮修复

## 1. 任务概述

修复用户反馈的三个问题：
1. 后台审核通过的帖子前端看不到
2. 帖子发布时间显示为 "-471 分钟前"（时区错乱 + 时间规则不符合预期）
3. 举报按钮点不到（无 onClick 处理）

## 2. 已完成内容

### 修复 1：审核状态不一致（后端）
- **根因**：[admin.py:177](file:///d:/Project/database-class/moment-campus/backend/app/api/admin.py#L177) 审核通过时把 status 设为 `"approved"`，但状态机（[post_status.py](file:///d:/Project/database-class/moment-campus/backend/app/core/post_status.py)）中只有 `published`，前端列表查询 `status == "published"` 自然查不到
- **修复**：
  - `approve_post`: `"approved"` → `"published"`
  - `reject_post`: `"rejected"` → `"archived"`（归档终态）
- **数据修复**：执行 SQL 把已存在的 1 条 `approved` 帖子更新为 `published`

### 修复 2：时间格式化（前端 4 个页面）
- **根因**：
  1. 数据库时区与前端解析时区不一致（约 8 小时差），导致 `date > now`，diff 为负数
  2. PostDetailPage 用 `toLocaleString` 显示绝对时间，其他页面用相对时间但规则不符合用户预期
- **修复**：统一 4 个页面的 formatDate 函数：
  - 不到 1 分钟：刚刚
  - 不到 30 分钟：X 分钟前
  - 不到 24 小时：X 小时前
  - 超过 24 小时：X 天前
  - 兼容时区错乱：diff < 60000ms（含负数）时显示"刚刚"
- **涉及文件**：
  - PostDetailPage.tsx（改为相对时间）
  - HomePage.tsx
  - SearchPage.tsx
  - NotificationsPage.tsx

### 修复 3：举报按钮（前端）
- **根因**：[PostDetailPage.tsx:361](file:///d:/Project/database-class/moment-campus/frontend/src/pages/PostDetailPage.tsx) 举报按钮没有 onClick 处理，点击无反应

  - 已举报过的会显示后端返回的"您已举报过该帖子"错误

## 4. 实现思路

### 审核状态修复
直接对齐状态机定义：`published` 是审核通过的正式状态，`archived` 是归档终态。拒绝的帖子归档后不会出现在前端列表（查询 `status == "published"`）和待审核列表（查询 `status == "pending"`）中。

### 时间格式化修复
- **根本原因是时区错乱**，但修后端时区涉及面广（所有模型 default=datetime.now），先用前端兜底处理
- 前端 formatDate 在 diff < 60000ms 时直接返回"刚刚"，规避负 diff 显示问题
- 应用用户要求的规则：< 30 分钟显示分钟前，< 24 小时显示小时前，>= 24 小时显示天前

### 举报按钮修复
用内联展开表单而非 Modal，避免引入新的 UI 组件依赖。表单包含类型选择 + 描述输入 + 提交/取消按钮，提交后调用已有的 `interactionsApi.reportPost` API。

1. **根本性修复时区问题**：后端所有 `datetime.now()` 改为 `datetime.utcnow()`，或让 schema 序列化时带时区后缀（如 `+08:00`），让前端正确解析
2. **举报表单增强**：可加字符计数器、举报类型说明 tooltip
3. **审核拒绝后通知作者**：当前 reject 仅改状态，未通知用户，可补充 notification
4. **时区统一**：建议在 `app/database.py` 中设置连接时区，或在 openGauss 服务器配置 `TIME_ZONE = 'Asia/Shanghai'`
