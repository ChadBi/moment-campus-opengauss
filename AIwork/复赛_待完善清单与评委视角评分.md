## 2. 高优先级实现规划（P0 项）

- `backend/app/main.py` — 添加 lifespan 启动 asyncio 后台任务

## 3. 评委视角重打分

> 以下分数基于**评委实际能看到的东西**评估，分为两种场景。

### 场景 A：评委仅看作品帖 + 演示视频（不手动测试）

这是初赛/复赛的常见评审方式。评委根据帖子内容和视频演示打分。

| 维度       | 原分       | 场景 A 分   | 说明                                            |
| -------- | -------- | -------- | --------------------------------------------- |
| 产品完成度    | 72       | **80**   | 帖子展示的功能完整，视频展示的链路通畅；未实现的功能在帖子中有清晰的"规划中"说明，不扣分 |
| 技术实现     | 80       | **82**   | 架构图、AI 网关设计、openGauss 选型等技术亮点在帖子中充分展示，评委给予认可  |
| 实用性      | 75       | **82**   | 视频中 AI 搜索解决真实痛点的案例极具说服力，场景代入感强                |
| 创新性      | 70       | **78**   | "AI 解析+真实数据检索"的设计哲学在帖子中清晰传达，区别于"AI 编造答案"的方案   |
| 社会价值     | 68       | **75**   | 跨校复制路径、多租户独立运营、公共基础设施定位在帖子中有清晰阐述              |
| **加权总分** | **73.0** | **79.4** | <br />                                        |

**场景 A 评语**：

> 整体完成度高，产品定位清晰，AI 与校园场景结合自然。AI 不直接生成答案而是解析条件+检索真实数据的设计理念值得肯定。建议在视频中增加"AI 降级演示"片段以增强可信度。

### 场景 B：评委拿到体验入口，实际动手测试线上系统

这是复赛/答辩环节的评审方式。评委会按照帖子描述的路径逐一测试。

| 维度       | 原分       | 场景 B 分   | 说明                                                                                                |
| -------- | -------- | -------- | ------------------------------------------------------------------------------------------------- |
| 产品完成度    | 72       | **65**   | 实操中会发现：①协同验证只有 2 类可操作（若帖子仍宣称 5 类）；②部分页面空/错/ Loading 状态不完善；③过期帖子仍为 published 状态（若自动过期未部署）。这三项会直接扣分 |
| 技术实现     | 80       | **76**   | 代码质量在实操中不可见，但功能不一致会让评委质疑工程质量；AI 搜索若偶尔失败且无降级提示会进一步扣分                                               |
| 实用性      | 75       | **70**   | 如果演示数据丰富、AI 搜索稳定，实用性分不降反升；但如果遇到空状态、接口报错等问题，体验割裂                                                   |
| 创新性      | 70       | **68**   | 创新性扣分点与产品完成度一致：描述与实现的落差影响创新可信度                                                                    |
| 社会价值     | 68       | **65**   | 多校切换如果数据隔离完好，社会价值分不受影响；如果隔离有漏洞（如残留其他校数据），大幅扣分                                                     |
| **加权总分** | **73.0** | **68.8** | <br />                                                                                            |

**场景 B 评语**：

> 核心 AI 搜索链路体验流畅，地图集成良好。但协同验证口径不一致、异常态缺失等问题在实操中会被发现，影响整体完成度感知。需在提交前完成口径对齐和状态组件补全。

### 两种场景的核心差异

| 差异项    | 场景 A（看帖/视频）    | 场景 B（实操）               |
| ------ | -------------- | ---------------------- |
| 协同验证口径 | 帖子写 5 类则按 5 类算 | 点进去只有 2 类 → 扣分         |
| 异常态/空态 | 视频剪接跳过         | 点到无数据页面 → 扣分           |
| 自动过期   | 帖子描述为规划中       | 看到过期帖子仍 published → 扣分 |
| AI 降级  | 视频展示成功案例       | 关闭 AI 后功能是否仍可用 → 加分项   |
| 多校隔离   | 帖子描述清晰         | 切换学校后数据是否干净 → 验证点      |

## 4. 结论与行动建议

**场景 A 得分（79.4）明显高于场景 B 得分（68.8）**，差距近 11 分。这说明：

1. **如果作品帖口径对齐、演示视频精心制作**，评委仅通过"看"就能给予较高评价
2. **如果评委实际动手测试**，任何口径不一致、异常态缺失都会直接暴露，导致分数大幅下降

| **P0-3** | 关键页面添加空/错/加载状态组件       | 提升异常态体验    | 场景 B |
| **P0-4** | 部署后执行版本核验              | 确保线上版本一致   | 场景 B |
