# 任务报告：彻底修复跨校管理员登录需要两次点击问题

## 1. 任务概述

彻底解决跨校管理员登录时出现的"需要两次点击才能登录"问题，并消除登录后误导性的"您没有该学校的访问权限"提示。同时修复退出登录后redirect循环导致登录后跳回登录页的问题。

## 2. 已完成内容

1. **登出清除学校上下文**：在 `useSchoolSync.ts` 中监听 `isAuthenticated` 从 true→false 变化，调用 `useCampusStore.getState().clearSchool()` 彻底清除学校上下文
2. **登录初始化静默切换学校**：新增 `isFirstAuthBootstrapRef` 标记，登录后首次学校初始化时（包括正常登录和换号登录两种场景）静默切换学校，不弹出"无权限"toast
3. **换号登录场景支持**：新增 `prevUserIdRef` 检测 `user.id` 变化，覆盖"已登录状态下直接访问/login换号登录"的边缘场景
4. **修复redirect循环**：`buildLoginRedirect()` 排除公开页面路径（`/login`、`/register`），避免 `redirect=/login` 死循环；`LoginPage` 做双重校验
5. **移除不可靠的setCurrentSchool逻辑**：从 `LoginPage.tsx` 移除之前尝试手动设置学校的代码（依赖未加载的schools列表不可靠），统一由 `useSchoolSync` 负责登录后的学校初始化
6. **端到端浏览器测试**：在集成浏览器中完成三校管理员跨校登录验证，均一次点击成功，无误导性提示

## 4. 实现思路

**根本原因**：
- 登出时 zustand persist 持久化的 `campus-storage` 中 `currentSchoolCode` 未被清除，新用户登录后store中残留旧学校code
- `useSchoolSync` 的学校权限校验 effect 在登录后首次加载 memberships 时执行，发现旧学校code不属于新用户，自动切换到正确学校并弹出"无权限"toast
- 由于学校切换发生在 `navigate('/admin')` 之后，首次API请求携带错误的 X-School-Code 头发送导致403，造成需要再次点击登录的错觉
- 退出登录时 `buildLoginRedirect()` 用 `window.location.pathname` 生成 redirect 参数，若已在/login页面会生成 `redirect=/login`，导致登录成功后navigate('/login')

**修复方案**：
1. 登出时主动调用 `clearSchool()` 清除学校上下文，同时重置bootstrap标记
2. 通过双重检测（`isAuthenticated` false→true 和 `user.id` 变化）标记"新登录初始化"场景，bootstrap期间切换学校不弹toast
3. bootstrap标记在首次处理完学校切换后重置为false，确保用户登录后手动切换到无权限学校时仍会正常提示
4. 过滤掉指向公开页面的redirect参数，避免登录后跳回登录页的死循环
