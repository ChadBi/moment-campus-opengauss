# 任务报告：侧边栏「首页」菜单项重命名为「帖子」

## 1. 任务概述

地图升级为主页（路径 `/` → `/map` 重定向，HomePage 挂 `/home`）后，侧边栏与移动端底栏的原「首页」菜单项仍沿用旧名，存在语义歧义：用户点击「首页」预期进入主页（地图），但实际打开的是帖子信息流与话题聚合页。需将该菜单项改为比「首页」更贴切的称呼（如「帖子/广场/动态」），并继续指向原 HomePage 内容页（路径 `/home`），不改变页面内容与跳转目标。

## 2. 已完成内容

1. 命名决策：原 HomePage 内容为「帖子信息流 + 话题聚合 + 最近发布/热门推荐」，与产品名称「此刻校园」的核心产物「帖子」直接对应，故选择最直白准确的 `帖子` 作为新菜单项名称。
2. `Sidebar.tsx`：导航项 `{path:'/', label:'首页'}` 改为 `{path:'/home', label:'帖子'}`，与 `routes.tsx` 路由定义保持一致，点击后直接命中 HomePage 路由，不再经过 `/` → `/map` 的重定向链路；保留 Home 图标（小房子）作为视觉占位。
3. `MobileNav.tsx`：与 Sidebar 同步，移动端底部第二枚导航项从 `首页 /` 改为 `帖子 /home`，两处导航彻底一致。
4. 前端构建验证：`npm run build`（tsc -b + vite build）0 error 通过，1973 modules transformed。

## 4. 实现思路

属于纯文案/导航链接层面的轻量调整，不涉及组件状态、数据流与 API：

1. **命名选择**：在「帖子 / 广场 / 动态 / 发现」四个候选中选「帖子」，原因——① 页面主体即帖子列表；② 顶部导航已有「地图/地点/搜索/通知/我的」，「帖子」与它们同为名词且语义独立；③ 「广场/动态/发现」对应用心智不够直接，容易与 Admin 页面、Feed 推荐混淆；④ 两字宽度与「地图」「地点」「搜索」「通知」「我的」一致，视觉排版整齐。
2. **path 同步从 `/` 改为 `/home`**：若保持为 `/`，则点击「帖子」会先命中根路由 → `<Navigate to="/map" replace />` 重定向 → 进入地图页；用户要再点一次「帖子」才能真正打开帖子流。改为 `/home` 后一步直达，避免「点帖子反而进地图」的交互陷阱。
3. **与 routes.tsx 定义对齐**：上一次调整已配置 `<Route path="/home" element={<HomePage />}/>`，因此本任务无需再改路由配置表。
4. **图标保留 Home**：继续用小房子图标，与原菜单项视觉记忆一致（避免用户找不到入口）；如后续需要视觉彻底去耦，可再换为 `BookOpen`/`FileText`/`MessageSquare` 等与帖子更贴合的图标——本轮未改。

## 6. 影响范围

- 前端 UI：桌面端左侧 Sidebar 第 2 项与移动端底栏第 2 项；仅此两处，无后台逻辑影响。
- 路由命中：点击「帖子」由原来的 `/` → `/map`（重定向失败/必须再次点击）改为直接命中 `/home` → 渲染 HomePage，交互链路缩短 1 步。
- 高亮（isActive）：`useLocation().pathname === item.path` 判定保持一致——进入 `/home` 会正确高亮「帖子」；进入 `/map` 正确高亮「地图」；不再出现「URL 在 /home 但高亮根路径首页」的情况。

## 8. 后续建议

1. **图标替换**：若产品希望「帖子」入口视觉上更准确（避免小房子与「地图/我的」图形联想冲突），可换为 `FileText` / `BookOpen` / `MessageSquare` 等更贴合内容的图标；需同步更新 Sidebar + MobileNav 两处。
2. **HomePage 功能定位校验**：若后续 HomePage 强化「话题卡片 + 推荐」而非纯帖子流，届时菜单项可再升级为「广场」或「发现」；当前 MVP 阶段「帖子」最直观。
3. **全局文案审查**：其他页面的面包屑、空状态 CTA（如「返回首页」）需检查是否应改为「返回地图」或「查看帖子」——上一轮仅调整了导航入口，可能还存在散落文案引用旧「首页」语义，建议下一轮系统性扫描一次。
