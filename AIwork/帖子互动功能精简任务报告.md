# 任务报告：帖子互动功能精简（点赞/验证/收藏/分享）

## 1. 任务概述

按用户需求对帖子互动功能进行精简和重构：

1. **点赞**：保持 toggle 模式（每用户对每帖只能点赞一次，再点取消），前端补上 is_liked 状态显示
2. **验证**：删除"补充更新/过期上报/冲突上报"3 类，只保留"证实/证伪"2 类；每用户对每帖只能有 1 条验证记录，可切换可取消
3. **收藏**：后端模型+API+schema+Post.favorite_count 字段全删，前端按钮+收藏列表+API 全删
4. **分享**：前端按钮删除（无后端 API）

## 4. 实现思路

### 互斥可切换的验证逻辑

每用户对每帖只能有一条 `ValidationRecord`，通过 `(post_id, user_id) unique` 约束保证。前端调用 `POST /posts/{id}/validate` 时，后端按以下规则处理：

| 当前状态 | 提交类型 | 结果 |
|---|---|---|
| 无记录 | confirmation | 新建 confirmation |
| 无记录 | refutation | 新建 refutation |
| confirmation | confirmation | 删除记录（取消） |
| confirmation | refutation | 切换为 refutation |
| refutation | refutation | 删除记录（取消） |
| refutation | confirmation | 切换为 confirmation |

前端通过 `GET /posts/{id}/validation-stats` 返回的 `user_validation_type` 字段判断当前用户的验证状态，高亮对应按钮。

### 数据库迁移策略

迁移脚本 `04_drop_favorites_and_simplify_validation.sql` 幂等可重复执行：

1. `DROP TABLE IF EXISTS favorites CASCADE` — 删收藏表
2. `ALTER TABLE posts DROP COLUMN IF EXISTS favorite_count` — 删字段
3. `DELETE FROM validation_records WHERE validation_type IN (...)` — 删 3 类废弃记录
4. 去重保留每个 (post_id, user_id) 最旧的记录
5. 通过 `DO $$` 块判断索引是否存在再创建（openGauss 不支持 `CREATE UNIQUE INDEX IF NOT EXISTS`）
6. 重算 posts.valid_count/invalid_count 保证统计准确
