# 任务报告：修复新增地点无需审核直接上线问题

## 1. 任务概述

修复用户反馈：普通用户新增地点后直接出现在公开列表，没有经过管理员审核环节，不符合内容审核要求。需要完善地点审核机制，确保用户提交的地点需管理员核验通过后才公开可见。

## 2. 已完成内容

1. **后端公开地点列表接口过滤**：修改 `get_locations` 接口，查询条件新增 `Location.is_verified == True`，仅返回管理员审核通过的地点
2. **后端创建地点权限区分**：`create_location` 接口根据用户角色设置核验状态：
   - 管理员/超管（admin/super_admin）创建的地点 `is_verified=True`，直接通过核验，`needs_review=False`
   - 普通用户创建的地点 `is_verified=False`，进入审核队列，`needs_review=True`
3. **新增响应结构**：`LocationCreateResponse` 新增 `message`（提示文案）和 `needs_review`（是否需要审核）字段
4. **发帖自动创建地点确认**：确认 `posts.py` 中创建/编辑帖子时通过 `location_name` 自动创建的地点已正确设置 `is_verified=False`，符合审核规则
5. **小程序端适配**：
   - `services/locations.ts` 更新 `createLocation` 返回类型为 `CreateLocationResult`（包含 location/message/needs_review）
   - `subpackages/pages/locations/locations.ts` 提交成功后，待审核状态显示 Modal 提示"等待管理员审核通过后将在列表中显示"，清空表单并关闭弹窗，不尝试打开地点详情；管理员创建成功则正常刷新列表并打开详情
6. **Web端H5适配**：
   - `services/categories.ts` 更新 `createLocation` 返回类型为 `CreateLocationResponse`
   - `components/CreateLocationModal.tsx` 适配新响应结构，待审核显示 Toast 提示，管理员创建成功才调用 onCreated 回调打开详情

## 4. 实现思路

问题根因是公开地点列表接口（`GET /api/v1/locations`）的查询条件没有过滤 `is_verified` 字段，无论是否审核通过都返回给前端显示。

修复方案：
1. 所有**公开只读**地点查询接口统一加上 `Location.is_verified == True` 条件，确保用户端只能看到审核通过的地点
2. 保留**管理员后台**的地点管理接口可以看到所有（包括未核验）地点，用于审核
3. 创建地点时按角色区分：管理员操作直接通过，普通用户提交进队列
4. 前端根据返回的 `needs_review` 字段展示不同的成功提示，待审核时不跳转详情页（因为未核验地点不在公开列表，直接跳详情会造成困惑）
5. 发帖时用户通过输入新地点名称自动创建的地点同样 `is_verified=False`，随帖子一起审核
