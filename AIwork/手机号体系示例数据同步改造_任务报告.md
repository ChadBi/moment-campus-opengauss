# 手机号体系示例数据同步改造——任务报告

- 为三校生成固定手机号演示账号：平台超管 `13900000001`，江南大学 `13900000002~13900000011`，复旦大学 `13900000101~13900000106`，浙江大学 `13900000201~13900000206`。

- seed 创建的历史 `users.email` 全部为空；已认证用户写入唯一教育邮箱，未认证用户不写教育邮箱。
- 清库时显式处理 `user_auth_identities`、`auth_sessions`、`sms_verifications` 和 `binding_tickets`，并重置相关序列。
- 增加 seed 配置和运行期校验，覆盖手机号唯一、邮箱字段为空、认证状态一致、微信身份和内容引用有效性。
- 更新当前演示指南、项目协作说明、前端 README、Playwright 登录辅助函数、状态 fixture 和手工验证脚本。

## 3. 未完成内容

本次计划内无功能性未完成项。后端全量测试按用户要求未执行；微信真实生产接口和真机授权仍需在真实 AppID 环境验证。

## 4. 实现说明

`users.id` 继续作为数据库物理主键，seed 使用 `users.phone` 作为所有业务数据的查找键。教育邮箱只写入 `education_email`，且只对 `campus_verified=True` 的预置用户写入。微信示例账号通过固定 openid 与手机号预置账号同时命中，重复 Mock 登录不会创建第二个用户。

seed 的清理顺序在用户表之前加入认证身份、会话、短信验证和绑定票据表，避免旧认证数据影响重建。所有敏感配置仍只由环境变量读取，本任务未读取、复制或提交密钥文件。

## 6. 影响范围

重建后的演示账号不再支持邮箱登录；普通密码账号使用手机号和 `pass123`，教育邮箱只用于校园认证。无密码微信账号可通过 Mock 微信手机号登录，并继续使用个人中心设置密码。帖子、评论、验证、专题、通知、举报和学校成员关系的业务语义保持不变。
