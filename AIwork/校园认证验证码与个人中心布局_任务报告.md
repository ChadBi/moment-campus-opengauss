# 任务报告：校园认证验证码与个人中心布局

## 1. 任务概述

将校园身份认证统一为“当前登录教育邮箱接收 6 位数字验证码”，移除验证链接流程；同时修复小程序个人中心当前学校卡片的文字布局问题。

## 2. 已完成内容

- 后端生成 6 位数字验证码并以哈希形式保存，确认接口只接受 6 位数字验证码。
- SMTP 邮件改为只发送验证码，不再包含验证链接或复制链接入口。
- Web 与微信小程序认证页面统一显示验证码输入和 6 位格式校验。
- 移除 Web 验证链接落地页与对应路由。
- 当前学校卡片改为学校名称、说明文字分行显示，切换按钮保持独立对齐。
- 更新认证说明文档与 TODO。

## 3. 未完成内容

- 真正的 SMTP 生产投递尚未连接真实邮箱验证；当前已验证邮件 HTML 只包含验证码。
- 真实教育邮箱收件箱尚未验证；本地开发接口会返回演示验证码，已完成模拟器输入与确认链路。

## 4. 实现思路

使用 `secrets.randbelow` 生成固定 6 位数字，数据库继续只保存 SHA-256 哈希。发送接口在本地无 SMTP 时返回验证码方便演示，生产配置 SMTP 时仅通过邮件投递验证码。前端删除 token/link 状态和链接落地页，统一使用数字输入框与正则校验。学校卡片通过固定的块级布局避免学校名和说明文本挤在同一行。
