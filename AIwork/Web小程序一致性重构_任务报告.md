# 任务报告：Web/小程序一致性重构

## 1. 任务概述

以 Web 当前实现和后端接口为唯一契约，重构微信小程序首页、发帖/编辑、地图、地点详情、学校切换及外围互动能力。重点解决首页误把推荐当作整页信息流、地图地点没有相关帖子、学校接口/坐标字段错位、冷启动草稿被误报为不存在等问题，同时保持本地开发使用 `http://localhost:8000/api/v1`，不恢复附近、GPS、距离、最近排序和专题订阅入口。

## 2. 已完成内容

- 首页拆分为固定 5 条“为你推荐”和独立分页普通信息流；分类筛选只作用于普通信息流，推荐失败不阻塞信息流。
- 统一帖子、分类、学校、地点、通知和订阅的 service 归一化；发布/编辑补齐标题正文限制、图片对象、有效期、地点、匿名、联系方式、失物类型、草稿和提交审核。
- 地图只读取 `/locations` 和 `/schools/current`，使用学校中心坐标；增加湖蓝/琥珀水滴标记、选中态、圆角控件及位于自定义 TabBar 上方的地点面板。
- 地图点选并行读取地点详情、评价和 `GET /posts?location_id=...`，面板展示真实相关帖子、AI 摘要、评分和空/失败状态，并用学校代码与请求版本防止旧响应覆盖。
- 地点详情已在本地路由正常加载，展示稳定资料、AI 摘要、可信层级、结论和评价；不再出现远端路由 404。
- 学校选择页改为卡片式两字校徽、清晰选中态和底部确认栏；学校切换按加入→临时租户请求→当前学校读取→原子更新缓存执行。
- 彻底移除小程序专题详情的订阅按钮；订阅管理只保留分类/地点，历史 `target_type=topic` 数据在 service 层过滤。
- 修复 access token 仅存在内存时的冷启动：非认证请求会先用 refresh token 恢复会话，私有草稿详情不会再被无认证 404 误判。

## 3. 未完成内容

- 暂无本轮代码链路未完成项。线上域名、真机发布和正式环境性能尚未验证，当前证据来自本地后端与微信开发者工具模拟器。
- 后端仍保留历史专题订阅数据和相关测试以兼容历史事实；小程序产品入口已删除，本轮没有重写历史数据。

## 4. 实现思路

先在 service 层建立单一响应归一化边界，页面只消费标准类型；首页、地图和发布页不再兼容旧字段或旧路径。地图地点选择采用静态地点列表/静态地图，不申请设备定位。学校切换把租户请求和 store 更新放在一个事务式流程中，并通过版本号取消旧请求。AI 摘要只读取已批准结果，不在访问时生成；地点面板和首页卡片只消费后端已返回的数据。

- 小程序 `npm run typecheck`：通过。
- 小程序 `npm run test:format`：通过。
- Web `npm run build`：通过；仅有既有大 chunk 提示。
- 后端独立测试库执行 9 个相关测试文件：107 passed，15 warnings，0 failed。
- 微信开发者工具 `check_wechatide_status`：登录有效、版本匹配；`simulator_refresh`、关键 WXML/WXSS 编译和 console 错误筛查通过。
- 模拟器验证：首页同时请求 `/recommendations?page_size=5` 与普通 `/posts`；地图点选图书馆同时请求 `/locations/5`、`/locations/5/reviews` 和 `/posts?location_id=5...`，均返回 200；地点详情截图显示 AI 摘要弹层位于当前页面底部而非系统窗口底端。
- 登录态 E2E：草稿创建→冷启动恢复→编辑→`pending`；点赞、协同验证、评论、举报；通知 `PUT /notifications/read-all`；分类订阅创建 201/取消 200；江南→复旦→江南切换并恢复中心坐标，均通过。

重复使用 `simulator_open_page` 直接压入已有页面栈时，开发者工具会记录 `appLaunch with non-empty page stack` 的导航提示；正常刷新和页面运行接口无对应业务错误。

## 8. 后续建议

- 在体验版/正式环境切换线上 API 基地址后，重复学校切换、地点详情和发布审核 E2E，并增加真机网络弱网测试。
- 为地点摘要来源卡片补充真实来源快照展示验收，持续监控摘要审核队列和旧版本回退。
- 后续若删除后端专题订阅能力，应单独设计数据迁移和历史报告处理，不与本次小程序入口清理混做。
