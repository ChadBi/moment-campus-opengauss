# 任务报告：小程序局域网真机调试配置

## 1. 任务概述

将微信小程序开发环境从只能在电脑模拟器访问的 `localhost` 模式切换为局域网模式，使同一 Wi-Fi 下的手机可以访问本机后端进行真机调试。

## 2. 已完成内容

- 开发环境 API 和图片主机改为 `http://192.168.3.10:8000`。
- 体验版和正式版地址保持 `https://campus.chaina1.com`，不影响线上环境。
- 本机微信开发者工具私有配置开启 `setting.useLanDebug=true`。
- 保持开发配置 `urlCheck=false`，允许真机调试使用本地 HTTP 地址。
- 后端当前监听 `0.0.0.0:8000`，具备被局域网设备访问的监听条件。

## 3. 未完成内容

- 当前局域网地址取决于电脑所在 Wi-Fi；更换网络后需要更新 `miniprogram/config/env.ts` 的 `DEV_LAN_HOST`。
- 尚未拿真实手机扫码执行完整登录、地图、发帖和互动流程；需要手机与电脑连接同一 Wi-Fi，并确认 Windows 防火墙放行 TCP 8000。

## 4. 实现思路

开发者工具模拟器和手机都使用同一个开发环境配置，但手机无法解析电脑的 `localhost`。因此只替换 `dev` 环境的主机为当前电脑局域网 IPv4，保留 `experience` 与 `prod` 的线上域名。`useLanDebug` 放在被 Git 忽略的个人配置中，避免把某台电脑的局域网地址误作为团队通用设置。

## 6. 影响范围

影响小程序开发者工具和真机调试时的开发环境请求地址；不影响后端接口、学校租户、线上体验版/正式版地址或 Web 端。

## 7. 测试与验证

- `http://192.168.3.10:8000/api/v1/schools/current` 携带 `X-School-Code: jiangnan` 请求返回 HTTP 200。
- 后端端口检查确认监听地址为 `0.0.0.0:8000`，不是仅绑定 `127.0.0.1`。
- 小程序环境配置仍按开发者工具/体验版/正式版区分，线上地址未被替换。
- 修改后应重新编译小程序；本次只改请求配置，未改页面类型和业务代码。

## 8. 使用说明与后续建议

1. 让手机和电脑连接同一个 Wi-Fi。
2. 在微信开发者工具中重新编译，并确认项目设置的“不校验合法域名、web-view 业务域名、TLS 版本”已关闭（本项目 `urlCheck=false`）。
3. 手机真机调试时访问开发环境；若换 Wi-Fi，查询新的 IPv4 并更新 `DEV_LAN_HOST`。
4. 若手机请求超时，优先检查 Windows 防火墙入站规则和 8000 端口，而不是改回 `localhost`。
