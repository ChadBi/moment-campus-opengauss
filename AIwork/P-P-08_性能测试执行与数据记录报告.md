### 7.2 索引/物化视图命中情况

| 查询 | 优化对象 | 实际执行计划 | 命中情况 |
| ---- | ------- | ----------- | ------- |
| Q1 | idx_post_recommend 部分索引 | 初次：idx_post_school_category + 3 表 Seq Scan；ANALYZE 后：分区 Seq Scan + Hash Join | 未命中预期索引（小表优化器选 Seq Scan） |
| Q2 | MV01 mv_post_validation_stats | idx_mv_post_validation_pk（物化视图索引）+ Partition Seq Scan posts | ✓ 命中物化视图 |
| Q3 | MV02 mv_user_reputation_ranking | Seq Scan on MV（11 行） | ✓ 命中物化视图（小表直接扫） |
| Q4 | MV03 mv_admin_dashboard | idx_mv_admin_dashboard_pk | ✓ 命中物化视图 |
| Q5 | idx_posts_title_trgm GIN | Seq Scan + Filter `~~ '%食堂%'`（GIN 索引不存在） | ✗ 未命中（pg_trgm 未安装） |
| Q5b | （同上） | Seq Scan + Filter | ✗ 未命中 |
| Q6 | idx_post_expire_active 部分索引 | 初次：idx_post_status_recommend；ANALYZE 后：Partition Seq Scan | 未命中预期索引（小表） |
| Q7 | idx_notification_unread 部分索引 | 初次：idx_notification_unread；ANALYZE 后：Partition Seq Scan | 初次命中，ANALYZE 后改走分区扫描 |
| Q8 | idx_comment_post_created 复合索引 | Partition Iterator + Partitioned Seq Scan + Hash Join | 未命中预期索引（小表） |
| 附加 | 分区剪枝 | Selected Partitions: 6（仅 2026-06 分区） | ✓ 分区剪枝生效 |

### 7.3 关键观察

1. **数据规模影响**：演示数据仅 30 条 posts，优化器在 ANALYZE 后认为 Seq Scan + Hash Join 比 Index Scan 更便宜，这是正确的代价模型决策。预期在生产数据规模（doc 27 第 10.1 节估算 18 万条/年）下，优化器会自动选择索引扫描。
2. **物化视图有效**：Q2/Q3/Q4 均命中物化视图，避免了原始的 5 次 GROUP BY / 全表 JOIN / 15+ 子查询。
3. **分区剪枝有效**：附加测试中查询 2026-06 月数据，仅扫描分区 6（13 个分区中只扫 1 个）。
4. **GIN trigram 索引缺失**：Q5 标题模糊搜索预期使用 `idx_posts_title_trgm` GIN 索引，但 pg_trgm 扩展未安装，索引也不存在。当前因数据量小（30 行）仍达标，但生产规模下无法满足 30ms 预期。该问题应纳入 P-P-10（zhparser 中文分词扩展）一并解决。
