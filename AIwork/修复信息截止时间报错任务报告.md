# 任务报告：修复信息截止时间报错

## 1. 任务概述

修复新建帖子时选择"信息截止时间"导致服务器内部错误（500）的 Bug。

## 2. 已完成内容

- [x] 排查根因：前端 `toISOString()` 生成 UTC 时区 ISO 字符串，被 Pydantic 解析为带时区 datetime，asyncpg 无法插入 `TIMESTAMP WITHOUT TIME ZONE` 列
- [x] 在 `PostCreate` schema 的 `expire_at` 字段添加 `field_validator`，统一转为北京时间（UTC+8）后去掉时区信息
- [x] 在 `PostUpdate` schema 的 `expire_at` 字段添加相同的 `field_validator`
- [x] 更新 `TODO.md` 和 `CHANGELOG.md`
- [x] Git 提交

## 3. 未完成内容

暂无

## 4. 实现思路

- 根因：前端使用 `new Date(datetimeLocal).toISOString()` 生成 ISO 字符串（如 `"2026-08-10T14:30:00.000Z"`），`Z` 后缀表示 UTC 时区。Pydantic v2 将其解析为 `datetime.datetime(2026, 8, 10, 14, 30, tzinfo=TzInfo(0))`（带时区）。但数据库列定义为 `TIMESTAMP WITHOUT TIME ZONE`，asyncpg 在插入时会报 `DataError: can't subtract offset-naive and offset-aware datetimes`。
- 修复方案：在 `PostCreate` 和 `PostUpdate` 的 `expire_at` 字段上添加 `@field_validator("expire_at")`（默认 mode="after"），当值为带时区 datetime 时，先转为北京时间（UTC+8），再调用 `.replace(tzinfo=None)` 去掉时区信息。
- 不传 `expire_at` 或传入无时区字符串时，validator 直接返回原值，不受影响。

- 前端不受影响，正常发送 ISO 字符串即可

  - 无时区时间：`"expire_at": "2026-08-10T14:30:00"` → 返回 `2026-08-10T14:30:00`

## 8. 后续建议

- 考虑统一后端所有 datetime 字段的处理方式，避免类似问题在其他字段上重现
- 长期可考虑数据库迁移至 `TIMESTAMP WITH TIME ZONE`，统一存储 UTC 时间
