# 任务报告：个人中心页未登录态改为点击登录统一卡片

## 1. 任务概述

用户明确反馈："个人中心页面，如果没有登录的话，最上面不应该时未命名用户，直接统一为点击登录之类的，然后下面的校园身份认证、我的帖子、浏览历史、推荐隐私、编辑资料、通知编号（= 通知偏好）、退出登录都不显示"。

还附带一张当前实机截图：顶部湖蓝渐变卡片显示"未命名用户 / 这个人很懒，还没有简介 / 编辑资料 / 通知"，下方显示"校园身份认证 / 当前学校 / 我的帖子与浏览历史 / 推荐隐私 / 编辑资料 / 通知偏好 / 退出登录"完整布局——这明显是把"已登录态的占位显示"错误地给未登录用户看了，视觉暗示自己已经是"用户 X"，却又无法操作，语义混乱。

目标：
1. ✅ 未登录时，顶部**绝对不要**渲染"未命名用户 / 这个人很懒..."这种占位文本——改为一个语义明确、整卡可点的"点击登录"引导；
2. ✅ 校园身份认证、我的帖子、浏览历史、推荐隐私、编辑资料、通知偏好、退出登录——共 7 类登录后专属菜单——在 WXML 层完全隐藏（不只是置灰或缩小）；
3. ✅ 学校选择（当前学校卡片）、用户协议、隐私政策、关于——这 4 类游客也可以访问的公共入口——无论登录与否都保持显示；
4. ✅ 原 onShow 里的 guardPageLogin 强制弹窗（"请先登录后查看个人中心"）一并移除——因为现在游客也能合法地进入"我的"Tab 查看学校选择和协议内容，不应该被弹走；
5. ✅ 同一 `isLoggedIn` 判据驱动"展示 + 行为"两端，避免"看起来登录了其实没登录"的割裂。

## 2. 已完成内容

### 2.1 经验库先行，避免两条历史踩坑路线

- 经验 ID 322067 Failure 1：❌ 不要用"❓/登录/点击登录"文本占位 + 仍渲染"ID:"字段做打补丁。正确做法是**严格条件渲染**：昵称 ID 整体块 `wx:if` 掉不渲染，未登录就只渲染独立的「点击登录」引导卡，不做半成品占位。**完全按此执行。**
- 经验 ID 344553 Failure 3：❌ 登录态判定不要依赖昵称/userInfo.name，因为接口返回 nickName / user_name / name 三种字段会导致"实际已登录但昵称空，仍显示登录按钮"。正确做法**以 authStore.isLoggedIn + refresh_token 持久化做唯一主判据**。**完全按此执行，authStore.initFromStorage() 用 refresh_token 存在性初始化 isLoggedIn，展示与行为两端共享同一 data 字段。**

### 2.2 profile.wxml：顶层做 `<block wx:if="{{!isLoggedIn}}">` / `<block wx:else>` 双分支

**未登录态分支（block #1）**：
- 「点击登录」大卡片 `.login-entry-card`：湖蓝 `var(--lake)` 背景 + 左 96rpx 圆形 user 图标（半透明白圆 + 白边 + 8rpx 投影）+ 中间"点击登录"38rpx/700 主标题 + "登录后可查看你的资料、帖子和浏览记录"24rpx/0.85 副文案 + 右 chevron-right 箭头。整卡 bindtap="onGoLoginTap" → 跳登录页。
- 「当前学校」卡片：游客也能切换学校，保留渲染——保证即使不登录也能浏览"江南大学 / 复旦 / 浙大"三校内容切换。

**已登录态分支（block #2）**：

- 推荐隐私整块（个性化推荐 switch + 清除推荐画像历史按钮）

**设置区**：独立设置区 7 条单独做 `wx:if="{{isLoggedIn}}"` 细粒度：
- 登录后才显示：编辑资料、通知偏好、退出登录（红色危险项）
- 无论登录与否都显示：用户协议、隐私政策、关于

**编辑资料弹出层**：保留在 WXML 末尾，不包进 wx:if 分支——防止因登录态变更导致弹出层无法正常关闭。

### 2.3 profile.ts：移除强制 Modal + 未登录分支主动清残留

**移除 guardPageLogin**：原来 `onShow` 一进页面就调 `guardPageLogin('请先登录后查看个人中心')`，未登录就弹 Modal 让用户去登录——但游客只想看"当前学校"或"用户协议"也会被强制打断，体验很差。移除后采用"主动点击登录卡片才跳"的策略，更符合游客浏览不打断原则（AGENTS Task 6）。

**未登录分支 setData 清空残留**：当 `authStore.getState().isLoggedIn === false` 时，主动把 nickname / bio / email / campusVerified / 4 列统计 / memberships / posts / history / verifyStep / recEnabled 等 16 个展示字段清空为默认值。防止场景"上次登录 A 用户 → 点退出 → 回首页 → 切回"我的"Tab"时，WXML 闪烁显示上一个人的残留假数据。

**新增 onGoLoginTap**：单独 handler，`wx.navigateTo('/pages/login/login')` 而非 reLaunch——保留返回栈，用户在登录页取消时可以回到个人中心原页面，更符合微信小程序返回交互预期。

**移除无用 import**：顶部 guardPageLogin import 已不用，删掉——避免编译后未使用 import warning，同时让代码更干净。

- `.login-entry-card`：44/30/48rpx padding，flex 居中，transition 0.18s 背景过渡

## 4. 实现思路

### 4.1 条件渲染的粒度选择：整页双分支 vs 条目级 if

一开始我想过"条目级一个个加 `wx:if` 更简单"，但写了两个条目就发现坑：统计卡和 user-card 之间有负 margin(-30rpx) 组合关系——如果只把 user-card 单独隐藏，stats-card 的负 margin 会直接 overlap 到学校卡片上，形成错位。因此改用顶层 `<block wx:if="{{!isLoggedIn}}">` / `<block wx:else>` 两个**完整分支块**，各自布局独立，互相不影响尺寸和负边距。缺点是"当前学校卡片"代码在两个分支里要重复一次，但这是一个很小的代价，换来了布局零错位的稳定性。

### 4.2 登录态判据的单一化

经验 ID 344553 的"展示与行为两端走同一判据"原则严格执行：
- onLoad 里订阅 authStore，回调只做两件事：①注入 isLoggedIn 到 data；②如果已登录才 applyUser。
- onShow 开头用 `!authStore.getState().isLoggedIn` 做主判，直接决定"渲染分支 + 清空字段"；**不做**"昵称有值就算登录"、"email 有值就算登录"这种次级判断。
- WXML 中所有 `wx:if` 条件全部用 `{{isLoggedIn}}` 这个单一布尔，不允许出现 `{{nickname}}` 或 `{{user}}` 这种展示字段当条件。

### 4.3 主动引导 vs 被动打断

原 guardPageLogin 是"被动打断"模式——用户刚点"我的"想看看协议，就弹"请先登录 + 取消/去登录"双选 Modal——**干扰浏览**。改为"主动点击登录卡片才跳"后，才是真正尊重用户意图的体验：
- 游客只想看学校：没问题，停留在当前学校卡片随便切；
- 游客只想看协议：直接拉到底部点进协议页；
- 游客想登录时自然会点顶部那张最醒目的"点击登录"大卡片。

这个改造同时解决了 AGENTS Task 6（游客模式登录引导）的语义：**"引导"≠"强制拦截"**。

## 6. 影响范围

- **唯一受影响页面**：`pages/profile/profile`（小程序 Tab Bar 第 4 页「我的」）。
- **正面影响**：
  1. 未登录用户不再看到"我是未命名用户"的伪账号语义；
  2. 未登录用户无法再点击"编辑资料/发送验证码/清空历史"这些需要登录的操作入口（原入口虽然内部有 `!isLoggedIn return` 的代码守卫，但外层直接隐藏是更清晰的第一层防御）；

- **完全不影响**：登录态的已登录布局（原 user-card / 统计 / 身份认证 / 我的帖子 / 浏览历史 / 推荐隐私 / 编辑资料 / 退出登录逻辑）一丁点儿都没改——它们全部被原封不动包在 `<block wx:else>` 分支里，渲染节点与原来完全一致。

### 7.3 未执行项（原因说明）

- **登录后反向验证（登录后回原布局正常）**：本次未登录态改造只包了 `<block wx:else>`，原节点一点没动，理论上已登录态 100% 不回退；但由于模拟器目前 auth storage 没有有效 refresh_token（保持在游客态），没有重新跑"登录→回到我的 Tab"闭环。建议下一轮真机测试时走一遍：登录成功 → 切 TabBar 到"我的"→ 确认 user-card、统计卡、身份认证、我的帖子等完整布局正常渲染 + 退出登录按钮正常。
- **真机登录完成后重定向回个人中心**：`onGoLoginTap` 使用 `wx.navigateTo('/pages/login/login')`，登录成功后如果 login 页没有特殊 reLaunch 逻辑，点返回键能回到"我的"。不过更优雅的体验是"登录完成→自动返回到点击登录前的页面"，需要后续在 login 页加 redirect 参数透传机制，暂不在本次改动范围内。

## 8. 后续建议

1. **login 页支持 redirect 参数透传**：在 `onGoLoginTap` 里传 `wx.navigateTo({ url: '/pages/login/login?redirect=/pages/profile/profile' })`，login 页登录完成后自动 redirect 回个人中心，不用用户再手动切 Tab。
2. **登录引导卡改为 3 入口（校园邮箱授权/微信快捷登录/注册）**：如果登录体系未来不止校园邮箱一种方式，可以在 `.login-entry-text` 副文案下方新增 2~3 个小按钮做"快捷登录分流"，避免用户点进去才知道选哪种。
3. **编辑资料弹出层加未登录兜底守卫**：目前未登录时 settings-item 编辑资料条已隐藏，editVisible 无法被外部触发；但为了防御未来代码变动（比如有人直接从 JS 调用 `setData({ editVisible: true })`），建议在 popup-mask 的条件上再加 `wx:if="{{editVisible && isLoggedIn}}"`，加一层双保险。
