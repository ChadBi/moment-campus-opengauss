# 任务报告：小程序微信短信绑定手机号登录

## 1. 任务概述

由于当前小程序主体无法稳定使用微信手机号授权组件，将小程序登录调整为“微信登录 → 输入手机号 → 阿里云短信验证码 → 绑定 OpenID 和手机号 → 登录”，同时继续以手机号作为业务唯一身份。

## 2. 已完成内容

- 新增 `POST /auth/wechat/sms-login`，完成微信 `code2Session`、登录短信核验、手机号账号复用或创建、OpenID 身份绑定和登录令牌签发。
- 复用现有阿里云短信发送与核验服务，使用 `login` 用途验证码及既定 60 秒发送间隔、5 分钟有效期。
- 增加微信已绑定其他真实手机号时的冲突保护；仅允许历史无手机号微信壳账号合并到已有手机号账号。
- 小程序登录页改为微信会话初始化和手机号短信绑定两个阶段，移除 `getPhoneNumber` 组件依赖。
- 新账号保持未认证、无密码状态，可在个人中心完成教育邮箱认证和首次设置密码。
- 同步 README、用户流程、API、路线图、小程序契约矩阵和上线指引。

## 3. 未完成内容

- 未代替用户向真实手机号发送收费短信，也未取得用户收到的真实验证码，因此“真机收到短信并最终进入个人中心”需要用户使用本人手机号完成最后一次验收。
- 微信开发者工具自动点击接口在当前真机调试会话中等待 automator 超时；已完成静态编译、控制台和代码门禁验证，但未把该自动点击写成通过。

## 4. 实现思路

小程序先通过 `wx.login` 获取一次性 code，再调用现有短信发送接口获取 `login` 用途验证码。提交时后端先交换 OpenID、核验短信，再以手机号查找业务账号：已有账号直接复用，新手机号创建未认证且无密码的账号，最后创建或更新 `wechat_miniprogram` 身份并签发登录会话。保留原 `/auth/wechat/phone-login` 接口，供主体资质具备后恢复微信手机号授权能力，但当前页面不调用。

## 6. 影响范围

影响小程序登录入口、微信 OpenID 与手机号账号绑定、手机号短信登录验证码消费和首次账号创建。Web 手机号登录、教育邮箱认证、既有会话与权限体系不变；原微信手机号授权接口仍保留兼容。

## 7. 测试与验证

- 后端使用 `backend/.venv` 执行 `pytest tests/test_phone_auth.py -v`：7/7 通过；按用户要求未执行后端全量测试。
- 小程序执行 `npm run typecheck`：通过。
- 小程序执行 `npm run test:format`：通过。
- 微信开发者工具执行登录页 WXML/WXSS 编译：均成功；刷新并打开 `pages/login/login` 后控制台无 error。
- 运行中后端 `/health` 返回 `ok`；向 `/api/v1/auth/wechat/sms-login` 发送空请求返回 422，确认真实进程已加载新路由。
- 代码扫描确认当前登录页不存在 `getPhoneNumber`、`bindgetphonenumber` 或 `onGetPhoneNumber`。
- 开发者工具 automator 在真机调试占用状态下超时；未发送真实短信，也未声称真实收码链路已经自动化通过。

## 8. 后续建议

在真机重新编译后，使用本人手机号点击“获取验证码”，输入收到的 6 位验证码并提交。登录成功后检查个人中心手机号脱敏、未认证状态和设置密码入口；若已有同手机号 Web 账号，应确认复用同一 `users.id`，而不是创建重复账号。
