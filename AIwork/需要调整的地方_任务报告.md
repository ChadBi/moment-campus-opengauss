## 4. 实现思路

### 整体编排

采用「阶段顺序执行 + 阶段内 Task 并行」的策略：

1. **阶段 1 先行**：数据模型重构是后续所有改动的基础，必须最先完成。ChangeReport / PostType / Tag / 活动时间字段在模型层彻底删除，避免后续阶段误用。
2. **阶段 2 + 阶段 5 并行**：都修改后端但无冲突（阶段 2 改 API 行为，阶段 5 改 AI 服务）。
3. **阶段 3 + 阶段 4 并行**：都修改前端但无冲突（阶段 3 改核心组件，阶段 4 改 Bug）。
4. **阶段 6 依赖阶段 3**：`MapLocationPicker` 组件在 PostForm 中集成后才能在 AdminLocationsPage 复用。
5. **阶段 7 最后**：所有改动落地后统一回归测试与 E2E 验证。

### 关键技术决策

1. **数据模型清理策略**：自顶向下（model → schema → API → service → test → script）逐层清理引用，确保无残留。Alembic 迁移严格新建版本，绝不修改历史迁移文件。
2. **MapLibre GL 而非 Leaflet**：项目已使用 MapLibre GL，保持技术栈一致性；地图聚合通过自实现 `Map` 数据结构 + 自定义 DOM marker 完成，避免引入额外依赖。
3. **AI 关键词提取双保险**：AI 解析优先，失败时 fallback 到基于停用词表与正则切分的本地提取函数，避免直接降级到原始 query（精准度差）。
4. **前端 Bug 修复根因导向**：
   - `useSchoolQueryKey` 用 `useMemo` 稳定数组引用
   - `AdminJobsPage` 让 `loadRecords` 自管理 loading，避免 `updateFilter` 与 useEffect 重复触发
   - `AdminReviewPage` 修正接口类型与渲染逻辑
   - `PlatformPlansPage` 后端 JOIN schools 表返回 school_name，前端优先显示
5. **Vite API 代理**：新增 `/api` 与 `/uploads` 代理配置到 `http://127.0.0.1:8000`，解决 MCP 浏览器测试的 CORS 与 502 问题。
