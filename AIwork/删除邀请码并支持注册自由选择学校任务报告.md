## 4. 实现思路

按"分层删除"推进：
1. 先删数据层（模型 + 迁移），保证库表契约先行收敛；
2. 再改 API 层（register 以 body 选择学校为准、join 直接加入、平台创建学校不再生成邀请）；
3. 同步清理测试与 seed 脚本；
4. 最后前端/小程序收敛 UI 与请求参数。

注册学校解析优先级设计：用户显式选择（body.school_id）> 学校上下文头（X-School-Code，兼容既有调用方）> 400，防止创建无学校用户。注册成功时始终创建所选学校的 active membership 并设为首校默认。
