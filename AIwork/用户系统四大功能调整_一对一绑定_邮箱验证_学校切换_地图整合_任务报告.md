# 任务报告：用户系统四大功能调整（一对一绑定 + 教育邮箱验证 + 学校切换 + 地图地点整合 + 未认证只读门禁）

## 1. 任务概述

依据用户 `/plan` 指令，对校园用户系统进行四项重要功能调整与优化，并补充未认证只读门禁保证数据安全与用户体验：

1. **UC-01 用户-学校严格一对一绑定**：禁止同一用户同时拥有多个 active membership，切换学校必须先"离校"再"入校"。
2. **UC-02 教育邮箱验证系统**：学生以学号 + 校园邮箱验证身份；支持 SMTP 真实发邮件；管理员可在后台配置学校默认邮箱后缀。
3. **UC-03 学校切换功能**：个人中心新增"切换学校"入口；切换后原校认证失效、原校内容匿名化，需重新完成新校邮箱认证才能发布内容。
4. **D-04 地点页面与地图整合**：地图标记点点击弹出地点信息卡（评分/相关帖子/详情入口）；保留独立 `/locations` 页面并支持深链。
5. **D4 未认证只读门禁**：未完成校园身份认证的用户（无论是否登录）一律只读，所有写入操作（发帖/评论/点赞/证实/证伪/举报/评分）均被拦截。

## 4. 实现思路

### 4.1 UC-01 一对一绑定

采用 PostgreSQL 部分唯一索引（Partial Unique Index）实现"一个用户最多一个 active membership"：

```sql
CREATE UNIQUE INDEX idx_membership_user_active
ON school_memberships(user_id)
WHERE is_active = true;
```

这比在应用层加锁更安全（DB 层强约束，防止并发竞态）。super_admin 因平台管理需要可保留跨校能力——实现上 super_admin 切校不触发 leave 原校逻辑。

### 4.2 UC-02 教育邮箱验证

- **域名后缀匹配**：学校→域名由 `school_domains` 表维护（支持一校多域名，如 pku.edu.cn / stu.pku.edu.cn），管理员后台可 CRUD。
- **双通道凭据**：
  - 6 位数字 code：便于人工输入（dev 模式直出）
  - 24 位 URL-safe token：用于邮件验证链接（`/verify-campus?token=xxx`），SHA-256 哈希后存库（避免明文 token 泄露风险）
- **SMTP 可配置**：`smtp_configured()` 检查必要字段是否齐全；未配置时 send 接口返回 `verify_link` 字段给前端展示（dev 模式），配置后真实发邮件。
- **前端落地页**：VerifyLinkPage 读取 URL token → 存 sessionStorage → 跳转个人中心；CampusVerifyCard 挂载时检查 sessionStorage，自动填充 token 并调用 confirm（用户零操作完成认证）。

### 4.3 UC-03 学校切换

- **原子切换**：整个切校流程在单个 DB 事务中完成（membership 状态变更 + 认证重置 + 内容匿名化），任何一步失败全部回滚。
- **内容匿名化**：原校 posts/comments/location_reviews 的 `is_anonymous` 置 true，author 关系保留但序列化时不返回作者信息，前端显示"已离校用户"。既保留内容价值（对其他同学仍有参考意义），又保护离校用户隐私。
- **UX 强提示**：SwitchSchoolModal 在确认按钮前展示红色警告条，明确说明"原校认证将失效、原校内容将匿名化、需重新完成新校邮箱认证后才能发布内容"，避免误触。

### 4.4 D-04 地图地点整合

- **地点图层与帖子图层分离**：MapPage 原有 MAP_MARKER_LAYER_ID（帖子 marker）之外新增 MAP_LOCATION_LAYER_ID（地点 marker），两层独立渲染，互不干扰。
- **点击侧面板复用**：地点面板与帖子面板共享右侧抽屉容器风格，点击地点 marker 时拉取地点详情 + 并行拉取该地点相关帖子（GET /posts?location_id={id}&page=1&page_size=5），在面板中展示评分、评价数、距离，以及最近 5 条相关帖子标题（可跳详情）。
- **深链**：LocationPage 挂载时读取 `?location=` 参数，通过 useCallback 定义的 openDetail 打开对应地点详情（effect 移至 openDetail 定义之后解决 lint 警告）。

### 4.5 D4 未认证只读门禁

- **后端统一拦截**：`require_campus_verified()` 作为 FastAPI 依赖，挂在所有写入端点的 `dependencies` 上。返回 403 统一响应，前端拦截器可识别后引导认证。
- **前端双层防护**：
  1. **UI 层**：VerifyGate 组件（大卡/紧凑两种模式）在渲染层面拦截，未认证用户看不到输入框/按钮
  2. **按钮级**：PostDetailPage 等页面的点赞/协同验证/举报/回复按钮通过 `canInteract` 判断直接不渲染
  3. **即使前端被绕过**：后端 403 兜底保证数据安全
- **fixture 策略**：测试默认用户标记 `campus_verified=True` 以保持现有测试正常运行，未认证场景由 `test_campus_gate.py` 专项覆盖，避免对 800+ 已有测试造成大面积破坏。

## 6. 影响范围

- **权限模型**：所有写入端点强制 campus_verified，权限门槛由"登录即可写"收紧为"登录+校园认证才可写"，这是对现有产品权限模型的重要收紧
- **多租户语义**：用户-学校从"多对多（可同时在多校）"改为"多对一（同一时刻仅一所）"，切校成为显式操作而非静默加入
- **匿名化逻辑**：新增离校匿名化路径，触发时机是"切校"而非"删除账号"，影响帖子/评论/地点评价三个实体的 author 可见性
- **邮件基础设施**：新增 SMTP 配置项，为后续通知类邮件（审核结果、账号安全）打下基础
- **前端渲染**：所有交互按钮在未认证时隐藏或替换为门禁提示，对未登录和已登录未认证用户一致只读
- **测试基线**：测试 fixture 默认用户改为已认证，新增专项测试覆盖未认证拦截

## 8. 后续建议

1. **配置 SMTP 启用真实邮件发送**：在 `backend/.env.opengauss` 中填入 QQ 邮箱（或其他服务商）授权码，重启后端即可启用真实邮件发送。QQ 邮箱授权码可在"邮箱设置→账户→POP3/IMAP/SMTP"中生成。
2. **小程序端门禁与切校适配**：本次 Web 端的 VerifyGate 组件、SwitchSchoolModal、地图地点面板需要同步到 miniprogram/ 端；小程序端可复用后端 API，UI 按小程序设计规范实现。
3. **管理后台可视化域名配置 UI**：后端 API 已就绪，可在 Admin 学校管理页面增加"邮箱域名后缀"的可视化配置界面（当前可通过 API 直接配置）。
4. **认证过期/续期策略**：当前认证一旦通过永久有效。后续可考虑增加"每学年重新认证""毕业自动失效"等策略，进一步保证社区纯度。
5. **切校匿名化视觉样式**：可在前端为"已离校用户"的评论/帖子添加微妙的视觉提示（如灰色昵称 + "已离校"标签），但不影响内容可读性。
6. **SMTP 发送失败重试与退信处理**：当前为单次同步发送，生产环境可引入 Celery/RQ 异步队列处理邮件发送，增加重试与退信处理。
7. **邮件模板美化**：当前验证邮件为纯文本，后续可使用 HTML 模板提升品牌感。
