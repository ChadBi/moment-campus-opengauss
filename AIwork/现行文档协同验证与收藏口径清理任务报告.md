# 任务报告：现行文档协同验证与收藏口径清理

## 1. 任务概述

将 `AGENTS.md` 的协同验证约束从历史五类更新为现行两类，并清理项目总览、产品需求和 API 规范中把收藏描述为现行能力的内容；同时扫描 `docs/` 的相关口径，对仍需保留的历史设计增加明确标注。

## 2. 已完成内容

- 将 `AGENTS.md` 的协同验证统一为 confirmation/refutation 两类互斥验证，并说明支持切换或取消。
- 从项目总览的现行价值、用户闭环和地图交互中移除收藏，将收藏及“我的收藏”明确列入当前版本不包含范围。
- 从产品需求的详情字段、删除规则、互动需求、个人中心、推荐行为、排序规则和核心 API 列表中移除收藏，并增加现行能力说明。
- 在 API 规范中增加收藏能力边界，明确不存在收藏路由、收藏列表、`favorites` 表和 `favorite_count` 字段。
- 清理技术架构中的 `/profile/favorites` 路由示例，以及社区治理中的“收藏后可查看”和收藏关联数据口径。
- 扫描 `docs/` 中的收藏与历史五类验证引用，对课设模型、阶段计划、历史现状、旧一致性报告等保留材料增加历史或过时标注。

## 3. 未完成内容

暂无。

## 4. 实现思路

先以当前后端模型、迁移、测试和前端类型为事实基线，确认协同验证只接受 confirmation/refutation，且收藏表、收藏计数和前端调用均已移除。随后优先清理现行产品与接口文档；对于课程设计、旧规划、旧审计等具有留档价值的内容，不删除原始方案，而是在文档顶部明确其历史属性和现行差异，避免读者误将其作为当前契约。
